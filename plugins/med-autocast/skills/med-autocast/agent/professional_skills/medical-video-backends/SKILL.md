# 医学视频后端运行

以显式 `workspace_root` 定位制作数据，按目标系列解析作者覆盖和后端档案。OPL 持有阶段运行；本 Skill 保留原工作台专业职责。下文 `scripts/`、`backends/`、`content/`、`productions/`、`work/`、`publish/` 均相对制作工作区，方法链接相对本 Skill。工具通过 [工作台工具接入](../../../docs/workspace-adapter.md) 定位：优先使用现有工作区入口，缺少通用工具时使用随包工具；不得默默替换工作区的专用修订入口。案例中的疾病、尺寸和作者选择只适用于对应案例。


这个 Skill 负责从工作台已经登记的本地、局域网和云端后端中选择合适路径，提交生成任务，并把结果验收到可交给剪辑和视觉 QA 的程度。生产前先读取作者/医生基线，确认参考音频和表达方向。新视频默认走本地 JavaScript/SVG/Canvas 动画与手绘拼贴：先查已审关键帧与插图库，缺口再用 ImageGen 或授权网上素材补齐；有授权参考声线时按作者档案调用本机 IndexTTS 或等效后端，未设定声线或用户明确跳过时才使用 Edge TTS `zh-CN-XiaoyiNeural`。按[十阶段SOP](../../../runtime/workbench/docs/04_医学科普视频系列SOP.md#0-十阶段流程与交接)，S06仅按需确认能力和具体替代，S07接收已审故事包/生成计划并产出实际媒体与回执；选题、故事设计或文档更新不触发模型调用。MiniMax H3 等视频模型保留为显式备选。

始终先读 `workbench.yaml` 的 `active_profiles.media_backends`、`backends/config/media_backends.yaml` 和 `docs/05_多后端本地与远程运行.md`。能力目录定义可移植协议，部署档案定义当前机器可用的实例与默认选择，两者不可互相取代。实际生产再读 `docs/06_媒体后端运行SOP.md`；使用云供应商时读 `docs/08_云视频API接入.md`；只有诊断当前机器或复核性能时才读 `docs/local/`。

## 首次环境准备

使用[安装说明](../../../docs/installation.md)中的随包 setup_workbench 与 environment_check 帮助新用户准备环境。新建空目录自动生成有效档案和安装独立依赖；已有工作区先只读检查，再按授权增量修复。先确认 Python/Node/FFmpeg/中文字体与真实浏览器启动，使用 smoke_local_animation 验证短编码链路；这些证据不批准素材、医生基线或医学内容。IndexTTS/Whisper/视频模型单独准备，缺少可选项不把核心安装判失败。Edge 合成必须联网，不能称为离线 TTS。

## 选择方法

用户明确跳过专用声线时，用 `configure_voice --mode edge` 保留参考音频并记录选择；服务故障不构成静默换声线授权。

新 JS 动画先按[素材准入与配音基线](../../../runtime/workbench/docs/13_素材准入与配音基线.md)完成作者/医生基线、准备和查看素材，再执行 `check_animation_assets` 与 `render_javascript_animation`。ImageGen 由当前会话对应 Skill 内置工具生成并登记。IndexTTS 使用同一参考音频、模型和情绪参数贯穿全篇，禁止逐场切换情绪指令；Edge 可在无声线或用户明确跳过时作为整篇旁白。`audio_baseline` 只检测响度，语气和完整听感须另审。

1. 先解析用户显式指定的后端；没有指定时使用登记表当前默认值。不要在 Skill 中硬编码默认后端、端口或路径，也不要因某个服务暂时不可达而静默切换。
2. 根据任务所需的文生、图生、首尾帧、参考图/视频/音频、分辨率、时长、音轨、隐私、成本和时延选择后端。后端不支持的字段必须显式拒绝或降级说明，不能悄悄忽略。
3. 本地与局域网后端适合可控、离线或已有算力的场景；云 API 不要求工作台机器具备模型所需硬件。二者是并列能力，不互相取代。
4. 保持旁白和画面解耦：先由导演共同设计内容与可见事件，再用统一声线完成旁白时间轴，生成对应镜头。H3原生音轨默认不进入成片；不把后期丢弃音轨声称为已关闭内部音频采样或节省推理算力。
5. 新后端的 `contract_documented`、`candidate` 或服务可达都不等于可生产。只有真实产出、媒体回读和质量验收完成后才能标记 ready。

## 实际运行

先确认有需要生成的缺口。已有同类合格区间、原 WAV/SRT 与未变工作流可复用时，交给导演和视觉 QA 确认，无须为了恢复重跑 smoke 或启动推理服务。完整执行与中断续接见 [后端 SOP](../../../runtime/workbench/docs/06_媒体后端运行SOP.md)。

1. 用 `python3 scripts/media_backend.py resolve --media <video|audio> --pretty` 读取实际配置，再运行 `python3 scripts/media_backend.py doctor --pretty`。需要当前机器的启动、隧道或安装命令时，转到登记表指向的部署文档。
   参考资产先从目标系列作者档案读取，再上传到所选后端；镜头记录该后端实际可用的引用位置。不能假设另一台服务器已有同名人物图，也不能把本地路径直接当作供应商已上传资产。
2. 新任务先确认具体基础替代，再按[后端SOP第4.2节](../../../runtime/workbench/docs/06_媒体后端运行SOP.md#42-提交快照与串行批次)核对实际提交快照，确保已审首帧、上传引用、完整提示及参数一致；编辑设计不代表runner已读取新版。停止批次前核对当前应处理清单与精确回执/产物，沿用唯一写入者；按连续性SOP第0.4节累计预算，默认一次生成，明确输入/调用缺陷最多一次定向修正。未知能力试验独立于整季交付，已有匹配证据不重复smoke。异步后端保存任务ID并查询精确输出；断流先查原队列/history，不重复提交。
3. 回执至少保存后端、供应商、模型、去密后的请求参数、任务 ID 或本地运行 ID、状态、耗时、精确输出路径、文件大小及对应任务引用；既有接口幂等校验标识按原合同保留，不新增日常剪辑哈希。不得按文件名前缀或目录时间猜测最新结果。
4. 用 `ffprobe` 或等价工具验证文件可解码、时长、分辨率和音视频流；随后按目标旁白时码交给 `medical-video-visual-qa`。本机遵守后台复核要求，不自动打开播放器或发声。
5. 记录加载、推理和端到端耗时；一次 smoke 只能证明该参数组合，不得外推整季吞吐量。

## 云视频 API

1. 每个云后端都按 `docs/08_云视频API接入.md` 中登记的供应商原生合同调用。Bearer 鉴权或 `/models` 可见不能证明它兼容 OpenAI 视频协议。
2. endpoint 与 API Key 由用户或部署环境提供。Key 只从登记的环境变量或受控密钥存储读取，不写入项目、命令、回执或日志。
3. 工作台负责公共参数到供应商字段的转换、异步轮询、下载、错误归一化和技术验收。模型特有的输入组合和限制留在供应商合同，不复制到 Skill。
4. OPL Gateway 只有在真实支持该视频协议并完成出片验收后才作为可选入口；切换 Gateway 只改变 endpoint 和凭据来源，不删除直连、本地或局域网能力。

## 生成视频经验

按[连续性SOP第0节](../../../runtime/workbench/docs/11_解释对应与叙事连续性SOP.md#0-视觉视频的首要原则)保持观看任务：首帧只提供起点依据，不能保证设备、姿势或读数在后续帧正确。精确区域使用已审素材；未知生成只作有具体替代的增强。不能把失败自动转成文字图卡，单个成功也不能标记整类能力稳定。

新H3路线按[调研策略第4-6节](../../../runtime/workbench/docs/12_H3调研与制作策略.md#4-稳定调用与画风)执行：参考职责、节点与权重一致；完整官方提示使用 `official_prompt` 直通，不能再次被旧包装器追加冲突锁定。Turbo/LoRA/步数配套；只有当前任务需要提升清晰度才继续画布比较。当前高血压按用户要求保持608×352、Turbo8，已主动中止的高清试验不重提、不计作模型失败。读取实际帧数与输出尺寸，回执保留完整图、发送提示、后端实际参考资产引用与接口已有校验标识、模型/代码标识及耗时，断流先查原任务。官方支持与社区自述不是本机能力通过；尚未实测的Ref2VA、引导和高质量档不得写ready。

生成分工按 [解释对应与叙事连续性 SOP](../../../runtime/workbench/docs/11_解释对应与叙事连续性SOP.md)：H3负责已验证的自然动作，精确关系由审定图示与后期负责。开工前确认整篇故事板已审；同场景派生关键帧仍须实际查看。单clip的continuous提示不保证跨镜连续，后端不能靠延长提示或随机换seed替代导演承接设计。

图片关键帧失败先按 [后端 SOP 4.1](../../../runtime/workbench/docs/06_媒体后端运行SOP.md#41-场景关键帧与图片-api-故障) 定位实际路由；Responses 可用不代表 Images 可用。已有授权的上游图片 API 可以恢复生产，不能静默跳过参考图。图片编辑先判断非空 base64 或精确结果 URL，客户端解码失败不等于未生成，避免重复计费。工具文本只返回必要状态与精确路径，不打印base64、image_url或完整生成响应，图像按需通过图片工具查看。机器端口与凭据字段只查本机记录，不写入本 Skill。

对当前生成模型，用“开场构图 -> 一次变化 -> 可用落点”描述动作。实测边界见调研策略第3.1节，失败预算以连续性SOP第0.4节为准；换图片、提示、seed或模式不重置同一观看任务的预算。目标区间过长交回导演接相关对象，不循环或大段尾帧填充。代码支持、服务接受任务和推理日志均不能替代输出验证。

## 交接

输出候选视频、生成回执和运行记录，交给 `medical-video-visual-qa`。后端不自行批准替换；导演可选择已审旧候选或少量稳定插图，由 QA 核对语义与真实类别。复用不伪造本次生成回执，失败候选计入实际尝试，不用筛选后的合格素材推算一次成功率。

配音默认使用 paper_project narrate；--beat 精确返修，固定参考声音与表达方向，独立环境自动解析。align 通过显式模型环境输出 ASR 差异及时间提案，不替换审定正文。不得因模型异常静默换声线。 具体命令见[单集工具与局部返修](../../../runtime/workbench/docs/20_纸剧场单集工具与局部返修.md)。


中文发音先按完整语境确定，IndexTTS 2.5 的 `tts_text` 可用 `<还|HAI2>` 控制配音，`text` 保持审定正文；不跨后端直接发送该标签。改发音控制即重新合成目标段，明确拒用的旧音不得作为缓存复用。先审听首句/高风险术语所在整段，再听最终混音，未听保持 pending。 方法见[中文配音发音控制与听辨](../../../runtime/workbench/docs/27_中文配音发音控制与听辨SOP.md)。


全季可运行 `scripts/audit_pronunciation.py` 生成高风险语境索引；它是 Review 定位材料，不是自动错读判定或阻断门。
