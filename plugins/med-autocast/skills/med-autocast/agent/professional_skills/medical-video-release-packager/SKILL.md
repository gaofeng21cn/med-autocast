# 医学视频成片与发布包

以显式 `workspace_root` 定位制作数据，按目标系列解析作者覆盖和后端档案。OPL 持有阶段运行；本 Skill 保留原工作台专业职责。下文 `scripts/`、`backends/`、`content/`、`productions/`、`work/`、`publish/` 均相对制作工作区，方法链接相对本 Skill。工具通过 [工作台工具接入](../../../docs/workspace-adapter.md) 定位：优先使用现有工作区入口，缺少通用工具时使用随包工具；不得默默替换工作区的专用修订入口。案例中的疾病、尺寸和作者选择只适用于对应案例。


目标是把已选镜头、审定旁白和文案合成为可转存的真实文件，分别标注技术交付、完整听感和医学终审。承担[十阶段SOP](../../../runtime/workbench/docs/04_医学科普视频系列SOP.md#0-十阶段流程与交接)的S08合成、S09技术检查及S10交付。文案语义交给内容策划维护，不在打包时新增医学事实。完整顺序与单集示例见 [系列 SOP 第 6-7 节](../../../runtime/workbench/docs/04_医学科普视频系列SOP.md#6-质量检查)；交付包不等于公开发布许可。

本工作台当前用户要求后台检查，禁止为质检自动打开、操控桌面播放器或播放音视频。采用离线帧序列、时码和音轨分析；具体范围与未覆盖项按解释连续性SOP第7节记录，不伪报完整听感。

## 开始前

1. 从 `workbench.yaml.series` 读取目标系列的作者与目录，未覆盖的作者继承当前档案；再读取该系列发布目录、目标集 `production_plan.yaml` 和 `visual_delivery_manifest.json`。
2. 确认视觉 manifest 逐镜记录了旁白区间、视觉意图、动作审核和图文一致性审核，且制作输入与已审定旁白、字幕一致。
3. 核对最新源片准入结论和允许区间与当前制作单、构建时间轴一致；停用状态优先于历史可用范围。未审镜头交回导演和视觉QA，不能直接合成后宣称已审。

## 成片合成

执行[连续性SOP第0节](../../../runtime/workbench/docs/11_解释对应与叙事连续性SOP.md#0-视觉视频的首要原则)：合成器不替导演生成文字课件。第0.4节的基础素材必须真实存在、区间可用；只在已审对象上叠必要标签。生成前用当前画布预排文字，不能等昂贵素材齐备才发现字幕放不下。替代镜头按真实来源、时长和现行合同核对，不降低比例或伪造运动。技术QA前回读形式复核，来源、动作、听感与医学审核分别记录。

质量档按[H3调研策略第4.3节](../../../runtime/workbench/docs/12_H3调研与制作策略.md#43-区分质量档位)回读实际源片与成片尺寸；共享合成器已支持制作单画布及按基准坐标缩放，608×352和1344×768的实际合成测试通过。当前高血压按用户要求继续608×352，不把画质升级设为内容迭代前置条件。新尺寸仍须检查字幕、品牌、裁切和比例；放大旧源不算高分辨率生成，高质量候选也重新接受视觉审核。

- 最终旁白是主时间轴；只改画面就复用原 WAV/SRT，按制作单显式路径取用，不猜字幕文件名。
- 字幕、Logo 和品牌元素按作者档案在后期确定性叠加；只使用档案指向且已审定的独立资产。
- BGM、相对音量和淡入淡出参数从作者档案的 `audio_mix` 读取；旁白始终是主声道，风险和行动段不抢戏。
- 单集构建与 QA 分别使用 `build_series_videos.py`、`qa_series_videos.py` 的 `--series <series_id> --episode <episode_id>`。唯一合成器为 `scripts/build_episode_video.py`；先做候选时可直接调用它，审核后不重复渲染同一成片。显式覆盖写入构建记录。
- `visual_annotations` 只放必要短标签；字幕仍由 SRT 排版。`brand_character_segments` 非空会关闭全部额外头像，不仅对应区间；无品牌镜头而需关头像时用 `--no-avatar`，不伪造人物段。BGM 与品牌实际参数从档案、CLI 及 `build-manifest.json` 核对，详见配置文档第 7 节。

## 快速检查

交付前按 [解释对应与叙事连续性 SOP](../../../runtime/workbench/docs/11_解释对应与叙事连续性SOP.md) 回读当前母版的整篇理解路线与切点。解码和动画比例通过不替代解释连续性；确定性图形变化如实登记类别，不冒充生成动画。保留完整听感、医学终审和解释复核各自的状态及方法。

在当前制作单、审核和publish manifest一致指向的母版上执行并回读；先区分正式final与review审看包，不能硬编码旧final路径。

完成后后台核对全时长帧序列与旁白时码：切镜是否承接意义变化，当前画面是否与当前句子同向，字幕是否完整，形式与品牌是否符合作者档案，结尾是否保留行动边界。音轨检查电平、异常静音与ASR差异；必要的编码、画幅、时长和完整解码一起回读。发现问题定位到镜头或时间段，修完核对受影响段及整篇衔接；未做的连续动态/完整听感保留pending，不为质检打开播放器。

明确记录检查方法与范围。逐秒联系表、ASR、音轨电平/差分和播放器结束状态均不能替代完整听感。QA 单集入口保留其他集 JSON 报告，但系列联系表只展示本次选择，不能把它作为全季观看证明。

## 发布包

打包前必须存在绑定当前成片、制作单和实际检查范围的人物构图复核记录；逐镜检查人物完整头部或明确的纯对象构图。发现半头、无头躯干或推近截头时阻止该版本作为已修复交付。共享合成器默认等比缩小并补边，避免隐式居中裁切；补边不能修复源片已经缺失的头部。显式裁切先在源素材完成并审定，所有被引用集同步更换、重新检查和打包，不能只修首次发现的一集。

交付位置与审核状态分开：用户要求的整篇或整季可审看成片统一进入登记的`publish_root`，在说明和manifest中如实标注待确认项，不另建平行的`deliveries`交付入口。放入publish不授予动画门、医学终审或公开发布通过；旧交付先归档，复制实际已审视频并逐字节回查，不为迁移目录重渲染。

去重复修复必须落到母版与发布包：确认生产单和 manifest 引用的是已审新候选，不能把同源裁切或仅下载新素材当完成。新场景可通过单条 `visual_annotations.offset` 避让主体，具体值以成片复看为准。双平台文案按医学信息是否变化决定修改；纯画面替换不强行改稿，但仍核对文案没有依赖旧画面表达。

发布文字只在系列登记的 `release_catalog` 维护。先按[系列SOP第7.1节](../../../runtime/workbench/docs/04_医学科普视频系列SOP.md#71-单集更新与回读)核对打包器与当前source/Schema匹配；审看包沿登记的已验证更新入口，不能用旧脚本回退新版。下列命令仅用于匹配的正式final合同：

```bash
python3 scripts/build_release_packages.py --series <series_id>
python3 scripts/build_release_packages.py --series <series_id> --check
```

上述命令处理整季，没有 `--episode`。只改一集时按SOP第7.1节选匹配入口；符合上述正式合同才复用示例公开函数，限定目标集及系列索引；未完成篇目导致整季 check 失败，不代表本集失败。正式final的SHA256字段按既有接口合同保留；日常审看包不新增哈希。复制字节、元数据、文案全文、字幕和下游记录按SOP第7.1节回读；只改画面时以新旧成片整段解码音轨比较证明声轨未变，不能只看WAV路径。文案语义按 [内容文档第 7.1 节](../../../runtime/workbench/docs/01_医学科普内容生产.md#71-小红书与微信视频号文案同步)；只改文案不渲染视频。

已通过动画门的每篇必须在登记的 `<publish_root>/<episode_id>/` 包含真实文件：

```text
video.mp4
小红书文案.txt
微信视频号文案.txt
发布交付包.md
```

没有合格动画的篇目先交付文案和状态说明，等成片准备好再补视频；不从 animatic 冒充正式成片。每篇目录保留一个真实 `video.mp4`、两个独立 UTF-8 TXT 和一份交付说明，方便用户直接压缩转存。
