# 医学科普内容生产模块

## 新制作交接要求

本模块承担[十阶段SOP](04_医学科普视频系列SOP.md#0-十阶段流程与交接)的S02—S05，以及S06内容冻结、S09医学问题溯源与S10文案/事实更新。专用入口为`medical-video-content-planner`。先明确医学含义和患者任务，再按[解释对应与叙事连续性SOP](11_解释对应与叙事连续性SOP.md)在配音前共同设计旁白草稿和视觉事件链，故事包交接具体医学关系、整篇理解路线和主要行动；不能把多机制原句压缩成宽泛话题交给通用对谈，也不能把每段旁白改成文字图卡。诊断阈值、治疗目标及急症条件明确区别，旁白节拍不决定镜头数量。医学文字与画面都需对应核对。

外部动画教育与多媒体学习证据见[调研文档第2节](12_H3调研与制作策略.md#2-证据与采用边界)：关注理解和行动，保持图词邻近与解释同步，保留字幕。模型画风、运动量、观看量或单镜成功不能成为患者理解或临床效果的证据。

状态：内容方法及模板已建立；资料判断、叙事和医学审核由AI与人工执行，不是自动医学审批流水线  
适用范围：从给定材料或联网检索开始，生成可直接交给视频制作的医学科普故事包

## 1. 模块目标

本模块负责把零散医学资料转化为准确、患者愿意听、能够形成记忆和行动的科普故事。最终产物不是论文摘要，也不是小红书正文，而是经过内容审查的 `video_story_package`。

高质量内容同时满足六件事：

1. 事实可靠：关键结论能追溯到适用于当前人群和场景的来源。
2. 患者相关：从患者正在困惑、害怕或需要决定的事情出发。
3. 故事成立：有问题、张力、推进、转折和收束，不是知识点堆砌。
4. 行动安全：告诉受众下一步如何理解、准备或就医，不替代个体诊疗。
5. 适合视频：旁白自然可朗读，每个节拍都能转化为清楚的视觉动作。
6. 视觉可落地：研究阶段同步找到可追溯、可判断授权状态的医学视觉和情境参考，不把找画面的压力全部留到制作阶段。

AI 小红书笔记和 RedCube AI 的成熟经验已被提炼到本文。它们可以提供历史内容或兼容输入，但本项目不依赖其目录结构或运行状态。

已落地的完整案例：`content/pituitary_tumor/README.md`。该目录按编号保存从系列简报、来源、事实库、患者问题地图、系列拆分、视觉素材库到第一篇故事包的实际产物，可作为后续疾病主题的流程参考。

## 2. 输入与输出

### 2.1 可接受输入

- 用户提供的 PDF、Word、PPT、网页、笔记、指南、论文或讲课材料。
- 一个疾病、症状、检查、治疗决策或患者管理问题。
- 指定受众、平台、作者身份、风格和时长偏好。
- 允许联网时，通过权威公开来源补齐证据。

输入材料不是天然真相。即使来自讲课稿或历史科普，也必须区分原始观点、可核验事实、过时信息和缺失证据。

### 2.2 必须输出

- `brief`：任务、受众、传播目标、平台、品牌和限制。
- `source_list`：材料与公开来源、发布日期/更新日期、适用人群和用途。
- `fact_library`：事实、来源、适用条件、不确定性、可视化边界和禁止表述。
- `visual_library`：可用于医学核对、场景设计或合法复用的视觉素材，连同来源、许可、医学含义和可重绘边界。
- `storyline`：核心问题、受众张力、记忆点、推进与收束；系列还要有不重复边界。
- `video_story_package`：单条视频的最终内容交接物。
- `content_review`：内容审查结论、遗留风险和人工医学复核人/状态。

## 3. 工作流程

### 3.1 定义受众任务

先回答以下问题，再开始检索或写稿：

- 这条内容具体给谁看？患者、家属、普通公众还是某类高风险人群？
- 他们在什么情境下看到它？刚拿到检查结果、症状出现、准备治疗还是长期随访？
- 他们现在最容易误解什么？
- 看完后应多一个什么判断、问题或安全行动？
- 哪些事情绝不能让观众自行决定？

“给大众科普某疾病”过于宽泛，不能直接进入脚本。应收敛成一个读者任务，例如“刚发现垂体占位的人，如何理解大多良性与仍需评估之间的关系”。

### 3.2 摄取给定材料

完整阅读可接受材料，不能只看标题、摘要或检索命中片段。为每份材料记录：

- 文件或 URL、标题、机构/作者、发布日期和访问日期。
- 材料类型：指南、共识、系统综述、原始研究、机构患者教育、专家讲稿等。
- 适用人群、医疗场景和地区。
- 可支持哪些结论，不能支持哪些结论。
- 是否存在版本过时、样本局限、利益冲突或与其他来源冲突。

扫描件、Office 文件和网页应先转换为可检索文本，同时保留原文件和页码/章节锚点。转换结果只是阅读副本，不取代原始材料。

### 3.3 联网检索与补证

联网检索的目标是补齐关键结论，不是堆积链接。优先级通常为：

1. 最新适用的临床指南、政府或专业学会共识。
2. 系统综述、循证总结和高质量实践更新。
3. 对关键机制、诊断或疗效问题有直接贡献的原始研究。
4. 权威医疗机构面向患者的解释，用于校准公众语言。

新闻、搜索摘要、自媒体、药企宣传和 AI 生成内容只能提供线索，不能作为关键医学结论的唯一依据。每次检索都要记录查询日期，因为指南和网页会变化。

只有当新来源能解决当前证据缺口或影响故事结论时才继续检索。直接证据已经足够后停止扩张，避免研究过程挤占真正的内容判断。

### 3.4 建立事实库

事实库是内容模块的核心权威来源。建议每条事实至少包含：

```yaml
- fact_id: PIT-001
  claim: 垂体参与调节多种重要激素
  source_refs:
    - source_id: SRC-001
      locator: section 2
  population: 普通成人
  context: 一般医学科普
  certainty: established
  allowed_wording:
    - 垂体虽小，却参与调节多种重要激素
  forbidden_wording:
    - 垂体决定人体所有激素
  visual_boundary:
    - 可画垂体与多种激素的关系，不画成唯一控制中心
```

必须额外形成三张清单：

- 事实白名单：允许进入旁白、字幕或画面的内容。
- 禁止结论：缺乏证据、容易误导、过度绝对或构成个体建议的表达。
- 证据缺口：仍不确定或互相冲突的问题，后续不能悄悄补写。

### 3.5 同步建立视觉素材库

信息收集不应只摘文字结论。阅读指南、患者教育页、论文和机构资料时，同时登记对后续画面真正有帮助的视觉素材。其目的有三类：核对医学结构和机制、为患者情境提供真实细节、为视频设计提供可合法使用或可重新绘制的参考。

视觉素材至少分为以下角色，不能混用：

| `role` | 用途 | 典型例子 |
|---|---|---|
| `medical_evidence` | 支撑或核对医学事实 | 指南流程图、论文图表、影像学示例 |
| `anatomy_mechanism_reference` | 核对解剖位置、方向、机制关系 | 权威解剖图、机构机制示意图 |
| `patient_context_reference` | 还原患者经历和生活情境 | 就诊、检查、服药、等待结果的场景 |
| `scene_object_reference` | 提供环境、器械和物件细节 | MRI 机房、检查单、药盒、诊室 |
| `style_reference` | 只约束视觉语言 | 线条、色彩、构图、动画节奏案例 |
| `brand_reference` | 约束品牌人物和识别特征 | 经本人授权的照片、审定卡通设定图 |

建议每项素材至少记录：

```yaml
- visual_asset_id: VIS-PIT-001
  role: anatomy_mechanism_reference
  title: 垂体与视交叉位置参考
  source_ref: SRC-PIT-003
  source_url_or_path: https://example.org/...
  creator_or_institution: string
  license_status: public_domain | licensed | permission_required | reference_only
  attribution_required: optional string
  medical_meaning: 垂体位于蝶鞍区，邻近视交叉
  required_view: sagittal
  required_landmarks: [鼻腔后上方, 蝶鞍区, 垂体柄, 视交叉]
  critical_region: 颅底蝶鞍区
  must_not_imply:
    - 所有垂体瘤都会压迫视交叉
    - 把病灶画在大脑半球中央
  allowed_operations: [medical_review, crop, annotate, redraw_reference]
  patient_identifiable: false
  local_derivative_path: optional string
  quality_notes: optional string
```

必须遵守四个边界：

- “网上能看到”不等于“可以放进成片”。许可不清的素材标为 `reference_only` 或 `permission_required`，不能直接复用。
- 患者照片、影像和病历即使有医学价值，也必须确认授权并去标识化；不能把搜索结果中的真实患者素材直接送入生成模型。
- `style_reference` 只能帮助确定视觉语言，不能作为医学事实来源，也不能要求复制特定创作者的独特作品。
- 可重绘参考必须同时记录 `medical_meaning` 和 `must_not_imply`。否则画面可能看似漂亮，却改变结构、比例或因果关系。
- 对位置敏感的解剖和影像，还要记录所需视图、方向、必须同时可见的定位标志和关键区域。只写“画一个垂体瘤”不足以约束生成；第一篇实际出现过把轴位脑中央亮点误当作垂体病灶的问题。
- 参考图的职责是固定医学关系，不是保证模型输出自动正确。视频模块仍需逐帧核对；若模型不能稳定保持关键位置，可改用统一手绘风格的确定性信息动画，或把审定插图留在 animatic 中等待返修，但不能把整篇静态图当作正式动画交付。

素材库不要求为每句话找一张现成图片。只收集会改变医学准确性、场景可信度或制作效率的素材；同一优质参考可被多个故事节拍引用。

### 3.6 选择单条或系列

默认先尝试用一条视频解决一个核心问题。只有当存在多个无法在一条内容中保持连贯的受众任务或证据簇时才拆成系列。

系列组织分三层：医学知识结构梳理事实、条件及关系；患者问题地图把知识转成真实困惑和决策；篇目表再将问题分配给每一集。不得直接把教材的定义、病因、分类、诊断、治疗目录当成患者观看顺序。

`04_series_plan.md`至少给出系列目标、覆盖/排除范围、篇目顺序、各集依赖、重复边界与代表样片理由。每集声明：

- 受众情境、核心问题、核心判断、看完的主要行动。
- 本集引用哪些事实，哪些相邻问题明确留给其他集。
- 为什么排在这里、需要哪些最小前置信息，与前后篇如何自然衔接。
- 本集独有的解释路线、观看信息和记忆点，避免只换标题或照搬镜头排列。

用“患者关心的问题是否有归属”和“本集能否独立完成理解”分别检查覆盖与单集完整性。允许为安全和独立观看重复必要条件；不得为去重删掉急症边界，或要求观众看完下一集才能安全行动。没有明确前后依赖的篇目可按重要性、常见程度和可行动性排序，不强造连续剧情。

模板见[系列篇目表](../templates/series/04_series_plan.md)和[单集简报](../templates/series/episodes/NN_slug/00_episode_brief.md)。集数和时长由任务及认知负担决定，不为了固定集数填充知识点。

### 3.7 设计患者中心的故事

故事不是虚构戏剧，而是让信息沿着患者的认知变化推进。至少定义：

- `audience_judgement`：患者当前可能怎样理解这件事。
- `tension`：为什么这种理解不够，真正困难或担心在哪里。
- `why_now`：为什么这条信息现在值得听。
- `memory_hook`：听完后最希望记住的一句话或图像。
- `progression`：从熟悉情境进入解释，再到转折和行动。
- `resolution`：降低不必要恐惧，同时保留必要警觉。

常用但非强制的节拍是：

```text
患者熟悉的困惑 -> 一句关键判断 -> 用机制或路径解释 ->
纠正常见误区 -> 给出可执行行动/就医边界 -> 温和收束
```

不能用恐吓、奇迹、绝对疗效或未经核实的真实患者故事制造吸引力。需要人物场景时，优先使用不带身份细节的典型情境，并明确它不是对某个真实患者的诊断。

### 3.8 写可朗读的旁白

S05先形成可朗读的旁白草稿；S06与导演共同校验可见事件、解释关系及整篇承接后再冻结。导演在草稿阶段介入，不等正式配音后才找画面；也不把图文卡片正文原样念出来。

- 一句话只承担一个主要意思。
- 先用大众语言，再在必要时引入医学术语并立即解释。
- 数字和缩写只保留会改变理解或行动的部分。
- 每个代词有清楚指向，避免脱离画面后含义不明。
- 风险边界使用直接、平静的表达，不模糊也不恐吓。
- 结尾给一个现实可执行的下一步，不用空泛口号。

中文温柔旁白可以先按每秒约 3-4 个汉字估算时长，再以实际 TTS 或真人试读校准。该范围是制作启发式，不是内容硬合同。

每个节拍建议记录：

| 字段 | 作用 |
|---|---|
| `beat_id` | 稳定引用 |
| `purpose` | 这一段改变观众什么认知 |
| `narration` | 审定旁白 |
| `fact_ids` | 使用的事实 |
| `required_meaning` | 画面必须传达的含义 |
| `visual_asset_ids` | 可用于医学核对、场景设计或重绘参考的素材 |
| `must_not_imply` | 画面不能暗示的错误结论 |
| `action_boundary` | 就医、行动或不确定性边界 |

### 3.9 联合设计与内容交接

内容模块负责“这段必须表达什么”和“不能暗示什么”，与导演共同选择可靠表达；导演负责具体镜头、资产和实现。内容模块不指定模型节点、采样步数、字幕字体或编码参数。导演可提出简化、拆分或调整顺序，涉及医学判断和条件时回到事实库复核，不能为适配模型改变真相。

S06冻结前同时核对旁白、完整故事板、素材许可、具体基础方案及医学复核。故事包记录旁白和导演稿版本/哈希、引用的fact_id、内容审核及医生复核依据；未做的复核标为pending。医学事实、旁白、故事包和实现各有负责人，不在多份文件维护互相独立的医学结论。新音轨在S07产生后仅校准排时；含义变化回到此处重新交接。

例如：

```yaml
required_meaning: 肿瘤可能影响激素或邻近视路
visual_suggestion: 简化的垂体位置与视交叉关系
visual_asset_ids: [VIS-PIT-001]
must_not_imply:
  - 所有垂体瘤都会压迫视交叉
  - 仅凭症状即可确定肿瘤类型
```


只有内容审查通过、按第5.3节完成故事包冻结前医学复核的版本才进入正式配音与镜头生产。草稿可用于S06联合设计，不能复制`approved`提前过关。`visual_clearance`说明素材能否直接用于生产；`reference_only`允许据其核对或重新设计，但不能直接复制原素材。内容、医学和许可状态互不替代，也不证明生成画面自动正确。

冻结与证据记录使用[故事包模板](../templates/series/episodes/NN_slug/03_story_package.yaml)的`handoff`及`review`字段：引用旁白/导演稿、事实库和作者档案版本或哈希，记录冻结日期与实际审核依据。这是内容交接记录约定，尚无完整机器Schema执行医学审批；旧包按原始证据读取，不因新字段缺失自动退回整季重做，也不能补造历史审核。

## 5. 内容质量验收

### 5.1 必须通过

| 维度 | 验收问题 |
|---|---|
| 来源完备 | 每个会影响判断或行动的事实都有可回读来源和定位 |
| 适用性 | 人群、场景、地区和时间范围没有被偷换 |
| 不确定性 | 争议、条件和证据不足没有被改写为确定结论 |
| 医学边界 | 不做个体诊断，不代替处方，不承诺疗效，不延误急症 |
| 受众相关 | 核心问题来自患者真实任务，而不是作者想展示的知识目录 |
| 叙事完整 | 有清楚判断、推进和收束，每个节拍都服务同一核心问题 |
| 共鸣克制 | 能承接恐惧和困惑，但不靠恐吓、猎奇或虚构病例 |
| 行动可用 | 观众知道下一步该理解、记录、询问或就医什么 |
| 口语可读 | 旁白自然、医学名词可正确发音，时长与信息量匹配 |
| 可视化 | 关键含义可被画面表达，且写清不能误导的视觉边界 |
| 视觉素材 | 关键节拍有足够参考；来源、许可、医学含义和患者隐私状态清楚 |

### 5.2 必须停止并返修

- 关键结论只有二手转述，找不到可靠原始或权威依据。
- 来源之间存在会改变患者行动的冲突，尚未解释适用条件。
- 需要根据个人检查结果作判断，但输入没有完整临床信息。
- 为追求情绪张力而必须夸大风险或承诺结局。
- 旁白包含过多数字、分类和例外，无法在目标时长内准确讲清。
- 唯一可用的关键医学视觉来源不明，或包含无法获得授权、无法去标识化的患者信息。

### 5.3 人工医学复核

发布前至少两次医学复核：

1. 故事包冻结前，审查事实、旁白、风险和行动边界。
2. 视频成片后，审查画面是否新增错误暗示，以及字幕/配音是否改变原意。

第二次复核不能被第一次替代，因为生成画面可能在文字正确的情况下制造错误的解剖或因果关系。

## 6. 批量生产策略

### 6.1 先建立主题事实库

同一主题的系列共享来源清单和事实库，每条视频只引用需要的 `fact_id`。更新指南或发现错误时，先修改事实库，再定位受影响的故事包和成片，避免全文搜索碰运气。

同一主题也共享视觉素材库。更新或撤回素材许可时，先修改 `visual_library`，再通过 `visual_asset_id` 定位受影响的故事包和制作单；不能只从成片目录里人工寻找。

### 6.2 每条视频一个核心任务

批量不等于模板化复述。每条视频必须有独立的受众问题、核心判断和记忆点。系列全局负责覆盖面，单条视频负责清晰和完成感。

### 6.3 生成前冻结内容版本

故事包进入视频制作时记录版本或摘要。若医学内容改变，应明确作废受影响的制作单和候选片段；只改视觉呈现时，不需要重新打开事实研究。

### 6.4 记录失败原因

批量返修应归类到事实、故事、旁白、视觉边界、分镜、生成、配音、字幕或编码。只有定位到负责人，积累的经验才会变成方法，而不是越来越长的提示词。

第一版适配器可以直接读取以下历史产物：

| 历史文件 | 映射 |
|---|---|
| `00_任务说明.md` | brief、受众、品牌、风格和限制 |
| `01_素材清单.md` | source_list，以及可追溯的视觉素材候选 |

| `03_叙事风格与故事线.md` | audience、tension、progression、resolution、系列结构 |
| `04_系列笔记目录.md` | episode 责任和 no-repeat 边界 |

适配器只做结构转换和缺失字段提示，不把历史文档原样作为新运行时合同。缺少来源定位、不确定性或视觉禁区时，应进入内容补全，不能自动假定为通过。

### 7.1 小红书与微信视频号文案同步

发布文字只在主题 `06_release_catalog.yaml` 维护，两份平台 TXT 是派生产物。先对照本篇当前审定旁白与故事包，确定核心问题、判断条件和行动，再分别压缩标题、正文、话题和置顶评论；修订后回读生成 TXT，不能只检查 YAML 能解析。

前三篇优化形成的通用写法：

- 标题直接说患者问题，不把线索写成确诊，不制造恐惧或承诺疗效。正文先给本篇最重要的判断/行动，再解释理由。
- 小红书可用短段落展开核心判断，视频号文案更紧凑；压缩表达时仍保留适用条件、不能自诊断和下一步行动。平台差异不构成新增医学结论的理由。
- 急症篇把行动提前；“突发 + 合并异常”不能压成“头痛就是急症”，“方便时带资料”不能压成就医前必须备齐。不要等网上回复、不自行开车或加减药等内容，仅在本篇审定稿已有时保留，不套成所有主题通用医学建议。
- 机制篇保留“可能”“如果接触或压迫”“并非每个人”等条件。第一篇手绘影像、第三篇关系图都是简化示意，发布文字不能将其描述为真实病例影像或确定诊断。
- 正文、置顶评论和话题共同审核；评论不能重新引入正文已经删除的恐吓、个体方案或确定性承诺。免责声明保留，但不能补救正文错误。

只改文案时不生成 H3/TTS、不重做视频；只改画面时检查文案是否仍准确，不强制为了同步而改字。若文案需要新增医学判断，先回内容负责人修审定稿。打包与单集回读按 [系列 SOP 第 7 节](04_医学科普视频系列SOP.md#7-发布交付)；生成交付包不等于平台上传或发布。

## 8. 当前限制与下一步

十阶段方法、专业职责与内容模板已明确；现有脚本负责目录、生成、QA和打包，来源判断、事实冲突处理、叙事判断及医生终审仍需实际执行。系列进度在[工作台入口](../README.md)索引，由各系列当前产物/审核记录证明，本文不再维护逐季生产待办，旧历史进度不授权重做已交付视频。

后续按真实制作观察内容理解、计划外改稿、废弃生成和总耗时；只有稳定重复的机械需求再增加自动化。模板字段齐全、一次生成返回或技术检查通过，都不能证明患者理解或医学质量。通过内容与成片两次医学复核闭合表达风险，保留尚未完成的审核范围。

## 9. 维护规则

- 本文是本项目医学科普内容生产方法的权威来源。
- 医学事实属于每个主题自己的 `fact_library`，不能写进通用提示词或本文。
- 从 AI 小红书笔记、RedCube AI 或其他外部流程吸收的新经验，必须在本文或正式合同中明确落地后才对本项目生效。
- 内容模块只负责故事含义与医学边界；视频呈现细节由 `docs/02_视频呈现与制作.md` 维护。
- 发布文案的内容权威是主题 `06_release_catalog.yaml`，它只能压缩审定旁白和故事包；打包器只负责物化，不负责新增医学结论。
- 端到端执行顺序、交付定义和失败恢复见 `docs/04_医学科普视频系列SOP.md`。
- 方法与部分工具可跨主题复用；没有当前版本的审核证据，不声称端到端自动化或医学审核已完成。
