## 1. 文档定位

本文是本项目“视频呈现与制作”模块的权威文档，负责与内容共同设计可靠画面，并把已审故事包制作成音轨、镜头、字幕和成片。内容草稿可提前进入设计讨论，正式生产接收审定交接版本。

同一项目内的“医学科普内容生产”由 `docs/01_医学科普内容生产.md` 独立维护。两个模块通过“视频故事包”交接：内容模块拥有医学事实和叙事语义，视频模块拥有呈现和渲染实现。视频模型和制作方法可以快速迭代，但不得反向改变已审定的医学内容。

## 2. 当前结论

RTX 4090上的H3、独立IndexTTS旁白、字幕和确定性后期已有1—3分钟视频的实际输出。历史前三篇验证了时间轴、候选区间返修及内容优先的镜头安排，也暴露了精确解剖、复杂医学关系、报告内容和多条件信息图的不稳定性。当前可依赖能力按[H3策略](12_H3调研与制作策略.md)及对应素材实证判断，不能用“十轮后成功”证明首次生成稳定。沿用以下分工：

- H3 负责短视觉片段，不负责正式旁白；IndexTTS 2.5 的最终音轨是剪辑主时间轴。
- `production_plan.yaml` 的 `visual_timeline` 将观看区间绑定到明确素材和可用区间。画面要与正在讲的话题相关、不矛盾，但不要求逐句复现旁白。
- H3 输出按区间验收：可用前段可以进入成片，出现黑帧、人物漂移或伪文字的后段通过 `source_end` 排除；关键错误镜头也可整段退回。
- H3 主要负责人、情绪、生活情境和自然动作。关键解剖、报告、数值、流程图和品牌文字不交给模型；真正必须展示的结构使用短暂审定插图。
- 候选不得含自生文字、标签、Logo 和伪字符；提示用“干净无标记表面”等正向状态表达，不把长禁词表送进正向条件。污染区间淘汰，只有干净范围可以进入成片。
- 准确中文字幕和纯文字品牌 `Dr.咩` 在生成后确定性烧录。
- 旁白为授权参考声线生成的温柔成年中文女声，并用语音识别回读核对内容。
- 第一篇最终成片为 H.264/AAC、608×352、24 fps、121 秒。

历史前三篇以复用H3/WAV/SRT、重排、区间截取和少量审定图示完成优化，证据见[系列SOP第10.1节](04_医学科普视频系列SOP.md#101-三篇验证过什么2026-09-05-历史批次)。区间数量不等于新生成次数，旧animatic不能冒充当前合格视频；当前各篇状态须回读其最新产物及审核，不能从历史待办恢复旧批次。

补充制作规范：静态医学解说图不做持续缩放、平移、漂移或“假镜头运动”。单个镜头确需让观众辨认结构时可以短时稳定保持，但必须明确声明，且整篇静态镜头不得超过 25%。模型无法稳定生成精确医学画面时，保留观看任务，用同场景局部、分解动作或审定对象的确定性变化重新表达；只有解释职责确为情境承接时才使用医生、患者、家属或就医行动。不能自动用泛动作或文字卡替代核心解释，不能把整篇替换为静态关键帧后交付。

当前确定的是：节目采用“手绘医生陪伴式讲解 + 患者情境 B-roll + 少量审定医学插图”。`Dr.咩` 可以坐着或站着讲、翻阅资料、示意方向或陪伴患者；不要求逐字口型同步，也不因口型风险退回静态人物。H3 的目标是让视频自然、有人味、看得下去，不是把导演稿逐帧执行成医学教材。完整形式矩阵见 `docs/03_品牌人物呈现策略.md`。

## 3. 模块边界

### 3.1 内容生产模块必须决定的内容

正式制作接收已经通过内容及相应医学复核的故事包；S06联合设计接收标明状态的草稿，至少包含：

- 目标受众和患者正在面对的核心问题。
- 一句话核心判断，以及为什么现在值得听。
- 故事节拍：开场共鸣、解释、转折、行动或就医边界、收束。
- 可使用的医学事实白名单、不可使用的结论和证据缺口。
- 需要保留的不确定性，不能被简化掉的条件和风险。
- 每个节拍可用的视觉素材，以及素材的医学含义、来源、许可状态、患者隐私和不可暗示边界。
- 作者身份、品牌文案和目标平台。
- 来源引用，便于医学复核追溯。

这些信息在本项目的内容生产模块中有明确产物。现有小红书产物也可作为兼容输入：

|---|---|

| 材料和公开来源 | `01_素材清单.md` |
| 可用视觉素材、许可和重绘边界 | `01_素材清单.md`、`02A_视觉导演稿.md` |
| 事实白名单、禁区和风险边界 | `02_素材解析与事实基线.md` |
| 故事张力、推进和收束 | `03_叙事风格与故事线.md` |
| 单篇问题、内容范围和系列位置 | `04_系列笔记目录.md`、`01_单篇策划.md` |

### 3.2 本模块必须决定的呈现

- 视频长度、画幅、镜头数量、镜头节奏和转场。
- 根据故事类型选择医生讲解、患者时刻、家属动作、就医路径或审定插图；不再默认把机制动画当成主体。
- 每个生成镜头优先承担一个主要观看任务；精确关系使用审定图示及可靠实现，整篇共同完成医学解释，不重新决定医学观点。
- 明确区分“可看动作”和“假运动”：人物自然呼吸、转身、拿起物品、走近、坐下都能服务观看体验；静态图持续推镜、平移或漂移仍属于假运动。
- 决定上游视觉素材是直接使用、裁切标注、仅作重绘参考，还是因许可或隐私问题弃用。
- 角色参考图、画风、构图和跨镜头连续性策略。
- 与内容共同校准旁白可朗读性；内容维护旁白定稿，作者档案提供声线基线，制作负责语速实现、音乐及音效。
- H3 工作流、模型版本、分辨率、步数和随机种子。
- 字幕断句、时间轴、品牌位置和最终编码。
- 画面、医学、声音、字幕和技术规格的质检。
- 小红书和微信视频号的标题、精简文案、话题、免责声明和发布前检查；文案只能压缩已审定旁白和故事包，不能在发布阶段新增医学结论。
- 背景音乐只作为低存在感的听觉底色：无歌词、低音量、旁白侧链闪避、首尾淡入淡出；不得让音乐抢过旁白或给急症段增加警报感。

### 3.3 禁止跨界

- 视频模型不能补写上游没有证据支持的医学事实。
- 为了画面戏剧性，不能夸大风险、虚构病例或暗示个体诊断。
- 上游不能把 H3 节点、采样步数等实现参数写成内容合同。
- 字幕、标题和品牌不能交给生成模型绘制；否则伪中文字会直接破坏可信度。
- 来源或许可不清的图片不能因为“只是作为参考”就直接出现在成片；患者可识别素材不能未经授权进入模型或制作包。

成片和 QA 完成后，打包器在 `publish/<series_id>/<episode_id>/` 建立可转存的发布交付包。每篇包含从制作母版复制的真实 `video.mp4`、独立的 `小红书文案.txt`、`微信视频号文案.txt` 和发布说明；系列根目录保存索引和哈希清单。医学终审未完成时，交付包必须明确标注状态，不能把“技术成片完成”写成“可公开发布”。

视频模块消费视觉素材时遵循三条规则：

1. `licensed` 或 `public_domain` 仍需核对具体许可和署名要求，再决定能否直接进入成片。
2. `reference_only` 只能用于医学核对、构图思路或重新设计，不能复制原图，也不能要求模型模仿特定作品。
3. 素材不足时，视频模块应登记缺口并回到内容研究补齐；不能让视频模型凭空补写关键解剖、器械或患者情境。

## 5. 已验证环境

### 5.1 硬件与系统

- 工作站：`configured-workstation`
- GPU：NVIDIA GeForce RTX 4090，24 GB 显存
- 运行层：Windows + WSL2
- WSL 内存上限：52 GB；原型运行时 WSL 可见约 50 GiB
- 部署根目录：`/home/example/ai/minimax-h3`
- 本地可复现部署包：`backends/h3/`

`work/set-wslconfig-52gb.ps1` 会备份 Windows 用户目录下已有 `.wslconfig`，然后只更新 `[wsl2]` 的 `memory=52GB`。修改后需要在 Windows PowerShell 执行 `wsl --shutdown`，重新启动 WSL 才会生效。

### 5.2 固定软件和模型

| 组件 | 固定版本或修订 |
|---|---|
| ComfyUI | `v0.34.0` |
| Comfy-Org/MiniMax-H3 | `4cc1d817b6184899b41293954329f576cb5ae86b` |

模型约 44.4 GB。安装前至少准备 70 GiB 可用磁盘和 48 GiB 主机内存；当前 52 GB WSL 配额适合这条单卡验证路径。

### 5.3 网络和服务边界

ComfyUI 用户服务只监听工作站 WSL 的 `127.0.0.1:8188`，不直接暴露到局域网或公网。访问时使用 SSH 端口转发：

```bash
ssh -L 18188:127.0.0.1:8188 <workstation-ssh-target>
```

然后打开 `http://127.0.0.1:18188`。`<workstation-ssh-target>` 必须使用本机已经核验过主机密钥的 LAN 地址或 SSH 别名；换网卡或地址后不要用 `StrictHostKeyChecking=no` 绕过身份校验。

## 6. 从零复现

### 6.1 准备工作站

以下保留现有第一季的设备与样片经验，不是新用户必须采用的配置。通用安装、档案与路径边界以 `docs/09_工作台配置与档案.md`、`docs/10_安装与迁移.md` 为准。

在 Windows 侧将 WSL 内存设置为 52 GB：

```powershell
powershell -ExecutionPolicy Bypass -File .\set-wslconfig-52gb.ps1
wsl --shutdown
```

将 `backends/h3/` 放到 WSL 可访问位置后执行：

```bash
cd backends/h3
chmod +x setup_h3.sh run_h3.sh postprocess_video.sh
./setup_h3.sh
./run_h3.sh
```

国内网络下载 Hugging Face 模型较慢时，可以临时使用镜像。固定 revision 仍由脚本校验，镜像只改变下载入口：

```bash
HF_ENDPOINT=https://hf-mirror.com ./setup_h3.sh
```

不要把镜像地址固化为唯一来源；镜像同步滞后时应回退官方 Hugging Face，并继续使用固定 revision，不能改成浮动的 `main`。

`run_h3.sh` 在支持 systemd 的 WSL2 中安装并启用用户服务 `minimax-h3-comfyui.service`。核验命令：

```bash
systemctl --user is-enabled minimax-h3-comfyui.service
systemctl --user is-active minimax-h3-comfyui.service
curl -fsS http://127.0.0.1:8188/system_stats
```

预期前两项分别为 `enabled` 和 `active`，接口返回系统与 CUDA 设备信息。

### 6.2 准备内容和角色

1. S06读取单集简报、旁白草稿及实际视觉参考，与内容策划共同收敛；S07正式生产前读取已审定故事包和内容/医学复核证据。
2. 根据本集解释路线和作者档案选择呈现形式，决定人物情境、对象关系与审定医学图示分别承担什么观看任务。
3. 按解释对象、关系、行动与语义转折安排镜头，一个生成镜头优先完成一个主要可见变化。5—10秒只是作者档案下的制作启发，不用于平均切分；最终音轨产生后再校准实际区间。
4. 为每个素材决定 `direct_use`、`annotate`、`redraw_reference` 或 `reject`，并记录许可与署名处理。
5. 先审整篇故事板及低成本预排，检查解释对应、人物分布、重复场景和承接；基础素材及替代须实际可执行。画面不需要独立讲清全部医学，但不能退化成字幕背景。
6. 作者档案启用的品牌角色可承担信任建立、关键提示与收束；患者场景保持自己的身份。内容冻结后再配音和生成，不让单镜试验代替整篇设计。

当前角色参考从作者档案的 `visual_identity.character_reference` 读取。`backends/h3/doctor_brand_reference_v3.png` 只保留作旧制作记录的历史快照，不再作为新镜头的资产权威。原始人物照片不复制到部署包、制作包或成片目录。

### 6.3 编写 H3 提示词

最终形式必须是手绘患者科普动画，不能因可控性问题改成纯确定性二维动画。H3 提示词不是导演稿全文，只写模型能够稳定完成的可见任务：

- 一个主体或一组关系简单的人物。
- 一个日常场景和一个动作，如抬手、转身、拿手机、递资料、走近或坐下。
- 大致构图、机位和需要保持的角色特征。
- 平静、温暖、可信赖的手绘水彩质感。
- 画面表面无标记，文字、字幕和品牌留给后期。

不要把旁白全文、症状清单、精确解剖位置、数值、报告内容或完整检查流程塞进提示词。常用镜头为 5-10 秒；只有单一人物和单一动作才放宽到 10-14 秒。

当前 H3 节点没有独立负向条件输入。长串列举禁用对象会把“器官、报告、文字”等词本身送进正向语义条件，可能诱发与要求相反的拼贴。提示词应改为描述可见的正向状态，例如：

```text
plain unmarked paper surfaces, a single coherent room, the same two adults,
the existing black phone, locked camera, subtle continuous human action
```

禁用项仍保留在候选审核和交付门中，但不再把完整禁用词表复制进每条 H3 正向提示。生成后逐秒联系表发现伪文字、额外对象、拼贴、身份漂移或场景漂移，整段或污染区间直接淘汰。

### 6.3.1 三篇复盘：先分配任务，再写提示词

2026-09-05 依据前三篇实际候选、回执与返修补充。以下是当前 RTX 4090 H3-Base 工作流的项目经验，不是模型能力保证，也不外推到云端同名模型。先核对本篇及同系列已审素材，能够服务当前旁白的区间直接复用；只有缺口才进入新生成。

| 观看任务 | 当前证据与边界 | 默认做法 |
|---|---|---|
| 单人生活动作 | R01 转戒指、R08 拢开衫已有可用片段 | 完整场景首帧，固定镜头，一个小动作，动作结束即切 |
| 简单物件运动 | R05 信号流、R06 物件环绕、R12 证据汇聚可用 | 对象先在图中存在，文字只描述谁沿哪里移动、停在哪里 |
| 品牌人物与设备 | R02、R11 需要收窄动作；R15 最终依赖人物保持、纸带运动；第一篇旧视野设备有夸张光效 | 按讲解任务安排人物；不同时要求口型、手势和设备变化。R15 不能当成自然人物表演成功案例 |
| 精确解剖与单向生长 | R10 旧首帧已有分离球体，提示又要求球体上移，早先批准未发现错误 | 先检查首帧是否传达正确关系；该镜已改为短暂稳定示意，不能靠换 seed 修复错误首帧 |
| 图表连接与精确数量 | R13 在 v6/v7/v8 留有三次候选；多节点关系不宜同时改动 | 固定连接关系，只动已有一个指示物；必须精确的数量、比例由后期承担 |
| 汉字、标签、品牌文字 | H3 不提供可靠的排字保证 | 使用制作单 `visual_annotations` 和最终 SRT 后期合成，字幕仍由 SRT 独立负责 |

仅 v4-v9 六份回执已包含 23 个候选，对应 15 个镜头；更早版本未计入，不能用筛选后的合格镜头计算“一次成功率”。后续以每个观看任务的实际尝试和可用区间判断收益。

**首帧检查优先于视频抽样。** “approved” 文件夹或已有通过状态不能替代观看：结构是否连通、器具是否合理、人物是否正确、画面是否真的服务当前旁白，应在付出视频推理成本前看清。第三篇 R10 的分离球体和第一篇 `s01_report_corrected_keyframe_v1.png` 纸面上的解剖贴图，都是旧批准或文件名不可靠的实例；第一篇实际采用干净的 `references/s01_patient_report_reference_v1.png`。

**提示词写法：完整场景首帧 + 一个正向动作 + 落点 + 必须保持的关系。** 例如拢开衫镜头：

```text
The woman gently draws her existing blue cardigan closer with one hand,
then settles into the original pose. Her relaxed mouth stays closed.
The table, cup and room retain their appearance and position. Fixed camera.
```

`common` 只提供画风和共同连续性，`motion_prompt` 只提供动作。不要重复旁白、详细症状清单、所有禁用词和整段人物设定；有 `motion_prompt` 时排队脚本实际使用它，审核前应核对最终 `generation_prompt`。非人物镜头只说明首帧包含全部主体，不再追加头像、真人、小窗等对象清单。现有第三篇提示已收敛，但新措辞尚未重新跑 H3，不宣称已证明成功率提升。

**首尾帧按动作含义选择。** 相同首尾适合轻摆后归位，不能用于“持续缩小、变少、向前移动并停住”等单向变化，否则会把动作拉回起点。默认仅首帧；确实需要另一个终态时，先核对独立尾帧与首帧的对象身份和关系，再验证该工作流。脚本的独立尾帧输入尚不能仅凭代码存在就视为生产验证通过。

**先落实基础表达，按观看任务累计预算。** 执行连续性SOP第0.4节：已有可用区间先复用，新的生活动作默认一次，明确输入/调用缺陷最多一次定向修正；同类已反复失败时不重试。新关键帧、提示或模式不重置预算。当前新动作可从约4-6秒预期使用区间起步，不强行撑满长旁白。基础替代须有具体资产与实现，不能在失败后才写“改为后期”。

**检查顺序只走一遍必要链路。** 首帧语义检查 -> 同类代表样本 -> 候选起中末排错 -> 可用区间带同期旁白复核 -> 一次合成 -> 成片复核。局部错误只重做对应镜头及合成，不重做声音、字幕或其他已通过候选。源动画没有变化时继承其已有动作审核，新增文字与插图单独复核；技术检查不冒充完整音画观看或医学终审。

### 6.3.2 已有素材怎样复用

以制作单的 `source_start` / `source_end` 为真实剪辑边界，manifest 记录对应 `usable_source_range`、同期旁白及复核依据。跨篇复用还要核对人物、场景含义与原始来源；同一患者的连续剧情不能突然换年龄、性别或家庭关系。不同患者的例子应明确区分，不能靠相同配音伪装成同一人。

三篇的实际处理：

- 第一篇 semantic S03 只取 0-5.383 秒、S07 只取 0-7.267 秒；第二篇 S09 只取 0.2-7.3 秒，避开后段变色、换场与自生图文。好文件不等于全时长可用。
- 第二篇 B05 连续整理资料可跨两个旁白任务，切点只改变讲解意义，无须另外生成镜头。源区间很短时不大幅拉慢来填满旁白。
- 第一篇急症示例复用第二篇家中不适与到院画面，并明确“急症例外”；三篇仍分别以报告评估、急诊路径、症状机制为主线。复用功能素材不等于照抄整篇顺序。
- 鞍区关系图只说明位置与条件关系，不模拟真实出血、生长或个体影像；双幅手绘影像只提示比较任务，不能借其差异声称真实增长。此类边界同时由原旁白与必要后期说明承担。

稳定插图声明为 `reviewed_visual_insert`，不标为动画。普通 H.264 帧间有损编码曾让同一静帧产生微小解码差异，被帧哈希误报为运动；对这类源使用帧内编码，保持真实分类，不降低门槛：

```bash
ffmpeg -loop 1 -framerate 24 -i image.png \
  -vf 'scale=608:352:force_original_aspect_ratio=increase,crop=608:352' \
  -t <duration-seconds> -an -c:v libx264 -preset slow -crf 18 -g 1 \
  -pix_fmt yuv420p output.mp4
```

尺寸与帧率为当前合成器规格。哈希变化只证明像素变化，不证明动作或医学语义成立；不会因为给静态图加推拉、显隐或标签就自动把它算作生成动画。

`visual_annotations` 用于短路径名、条件或来源限制，最多两行、每行 20 字；默认位置为左上 `+16+16`，字号 17，深色字白描边。可用单条 `offset` 指定位置；例如当前 608x352 成片中 `+16+255` 可利用部分场景的下方留白。位置不是通用安全区，仍须看实际人物、物件和两行字幕；只对重叠区间拆分标签时码并调整，不能全片盲目下移。标签不能替代旁白中的医学条件，底部字幕仍由 SRT 持有。字段与品牌叠加规则见 [配置文档](09_工作台配置与档案.md#7-作者设置怎样生效)。

构建器检查时间轴连续性、结尾与最终音轨时长，以及每个内部视觉切点是否命中字幕/旁白边界。素材短于目标段时优先重拆镜头；小幅差异可匀速延展已审真实动作，需复看自然度。禁止循环或大段尾帧填充，不整体加速配音；当前约 0.45 秒片尾收束补垫不计为新动作。

字幕与品牌规则：

- 进入成片的 H3 候选区间不得包含模型生成的文字、伪字符、标签或水印；原始候选可以存在不合格区间，但必须在时间轴中排除或整段弃用。
- 字幕使用准确中文、白字深色描边，按语义断句，不遮挡主要医学对象。
- 每条字幕最多两行，每行最多 20 个字符，单条正文最多约 30 个字符；优先按语义和标点拆分，不能用固定字数从中间截断。
- 医学术语、固定短语、引号内短语和拉丁缩写保持完整，不能出现“应激反\n应”“IG\nF-1”“普\n通复诊”这类机械断词。
- 任何可见行只要在此结束，行末的逗号、句号、顿号、分号、冒号、问号、感叹号及对应英文标点全部删除。换行本身已经表达停顿，不在上一行保留标点，也不在整条字幕最后补句号。
- `narration.srt`（第一篇兼容文件为 `narration_index.srt`）是字幕文字、断句、换行和时码的唯一负责人。字幕生成后必须逐行自动检查；合成器只验证并照排，不能二次重排或重新引入标点。
- 品牌角标只能使用后期固定的 PNG/SVG 标识或固定纯文字 `Dr.咩`，不用 emoji、模型生成的小羊图形或模型生成的任何品牌字样。
- 品牌文字可持续小尺寸出现；独立审定头像只在片头和片尾短时出现，不从场景图或复合母图运行时裁切。
- 输出使用 H.264、`yuv420p`、AAC 和 `+faststart`，兼容常见移动端平台。

各篇共用 `scripts/build_episode_video.py`，第一篇旧入口只是转发，不维护独立合成实现。第一至三篇已完成本轮优化，第 4-12 篇静态合成仅保留在 `animatic/`。画布、品牌位置和字幕样式仍是当前横屏技术原型规格。

## 7. 质量验收

### 7.1 阻断项

任一项失败，都不能标记为可发布：

| 维度 | 验收要求 |
|---|---|
| 内容 | 每句旁白都能追溯到事实白名单；不越过诊疗边界 |
| 观看体验 | 最终形态是统一手绘患者科普动画；人物与物品持续有自然变化，不是纯确定性二维动画、静态人物、PPT 切换或无关素材拼接 |
| 音画关系 | 每个视觉段落与当前话题相关、不矛盾、不新增诊断暗示；不要求逐句或逐词图解 |
| 候选区间 | 时间轴只引用已经逐段检查的素材范围；已知错误尾帧、黑帧或身份漂移不得因同文件前段可用而被带入成片 |
| 素材 | 所有 `visual_asset_id` 可解析；直接使用、标注或重绘符合许可、署名和患者隐私边界 |
| 模型文字 | 候选逐段/抽帧检查；进入成片的区间不得出现文字、伪中文字、Logo、水印或胸牌 |
| 医学画面 | H3 不承担精确解剖；若出现关键医学结构，必须来自审定插图且没有可能误导患者的关系错误 |
| 角色 | 人脸、发型、眼镜、服装和年龄感基本一致；动作自然，允许承担主持、陪伴和情绪引导 |
| 旁白 | 温柔成年中文女声；发音清晰，语义、数字和医学名词与审定稿一致 |
| 字幕 | 逐字正确，断句自然，与旁白同步；无截断、遮挡、溢出和伪字符 |
| 品牌 | 只显示审定的 `Dr.咩`；无未经授权的人名、机构、Logo 或水印 |
| 技术 | 音视频流完整、无黑帧/静帧异常、时长正确、移动端可播放 |

静态图专项规则：连续静态画面只有在观众需要辨认结构或消化结论时才保留；此时画面应稳定。若需要节奏变化，使用语义切换、局部显隐、明确高亮或跨图转场，不使用无语义的持续缩放和平移。

医学内容和医学画面需要人工复核。OCR、语音识别和自动抽帧只能发现候选问题，不能代替医生判断。

### 7.2 当前质检方法

```bash
# 技术规格
ffprobe -v error -show_streams -show_format -of json OUTPUT.mp4

# 每秒抽帧，随后生成 contact sheet 做全片扫描
ffmpeg -i OUTPUT.mp4 -vf fps=1 qa/frame-%03d.png

# 指定单集 QA；完整系列检查才省略 --episode
python3 scripts/qa_series_videos.py \
  --series <series_id> --episode <episode_id>
```

高成本生成前先审镜头表或 animatic，确认人物分布、场景变化和节奏不单调。生成后分三层检查：候选素材联系表用于标出可用区间；切点前后抽帧用于核对话题相关性和有无误导；最终成片联系表用于检查字幕、品牌、遮挡和节奏。画面不需要离开旁白独立讲清医学知识。完整解码与内容黑帧必须分开检查：文件能解码不代表画面不是黑的。

本机 FFmpeg 未提供 `drawtext` 时，联系表可用 `fps/scale/tile`，不为加时码标签阻断画面核对。需要诊断新旧混音差异时，先确认采样率、声道和时间对齐，再对一轨 `volume=-1` 后用 `amix=inputs=2:normalize=0` 相加测残差；不要用负 `amix weights` 冒充相减。前三篇原 WAV/SRT 未改，重编码后的 AAC 仍不逐字节一致；电平、残差和 ASR 不能证明医学读音或完整听感通过。常规返修无音频疑点时不重复做差分诊断。

## 9. 已踩问题与处理原则

### 9.1 伪中文字

问题根因不是字体，而是让视频生成模型承担了排字。处理原则是提示词禁止排字，候选按区间检查，进入成片的范围彻底无生成文字；字幕、标题和品牌全部后期确定性叠加。只在提示词中纠正错字，无法获得稳定结果。

### 9.2 角色漂移

V2 证明首尾帧参考不能保证逐字口型和稳定表情；V3 用静态闭口人物规避口型，却因人物没有动作而未通过观看验收。新版允许医生成为稳定主持与陪伴角色，但只要求自然姿态、目光和手势，不要求嘴唇级同步。需要跨镜头连续时，每段显式传入批准的角色参考并做人物联系表。

### 9.3 `libass` 缺失

当前通过 ImageMagick 透明图层 + FFmpeg `overlay` 完成高质量中文烧录，无需等待 `libass`。后续若需要复杂逐字高亮、卡拉 OK 或通用 ASS 模板，再安装带 `libass` 的 FFmpeg，并把它作为后期实现替换，不改变上游内容契约。

### 9.4 固定 8 秒的误解

8 是 Turbo 采样步数，不是成片秒数。当前 `prepare_workflow.py` 已将时长设为 14 秒。最终时长应由故事需要决定；长内容优先多片段剪辑，而不是牺牲节奏硬塞进一个短片。

### 9.5 声音可控性不足

H3 内生音频可以快速验证“画面 + 女声旁白 + 环境声”的整体效果，但不能稳定锁定同一个品牌声线。正式流水线更适合把审定旁白交给独立、可复现的中文女声 TTS，再与 H3 画面、音乐和音效混音。

#### 本地品牌声线（IndexTTS 2.5 / CosyVoice 3）

在线声线克隆适合快速试听，但存在额度、音色槽和服务可用性约束；MiniMax 当前未公开可本地部署的同等 Speech 权重，因此本项目将本地 TTS 作为可复现生产路径。经过第一篇试听比较，IndexTTS 2.5 已固定为本项目默认生产配音引擎。

当前已在 `configured-workstation` 的 RTX 4090 完成两套零样本中文女声验证，参考录音为本人授权的约 26.6 秒单声道 WAV：

- IndexTTS 2.5（默认）：Python 3.11、PyTorch 2.8.0+cu128；完整旁白约 120.53 秒，Whisper 逐句回读与原稿对应。默认参数为 `use_bf16=True`、`use_qwen_emo=True`、`duration_factor=1.05`、`interval_silence=220ms`。产物位于 `productions/01_mri_found_pituitary_lesion/audio/local_voice/index-tts25-narration.wav`。
- CosyVoice 3：Python 3.10、PyTorch 2.3.1+cu121；短试听约 21 秒，Whisper 可识别完整句意，但“垂体占位/垂体瘤”等医学词存在同类 ASR 混淆，仍需人工试听和医学名词复核。产物位于 `productions/01_mri_found_pituitary_lesion/audio/local_voice/cosyvoice3-preview-corrected.wav`。

生产规则：IndexTTS 2.5 使用经本人授权的参考录音生成旁白；保留参考录音、提示文本、模型版本、采样率、推理参数和 ASR 回读。TTS 只负责声音，不负责字幕；字幕时间轴必须从最终确认音轨重新生成。未经本人授权，不得将真人录音用于其他角色或对外共享。CosyVoice 3 仅作为技术对照，不是本项目当前默认引擎。

字幕排版规范：字幕只呈现旁白，不承担信息图排字。按完整语义短句断行，优先在句号、问号、分号和自然逗号处拆分，顿号主要保留同行枚举；不拆医学术语、固定短语和拉丁缩写，不让下一行以标点开头。每个实际显示行末尾的中英文标点全部删除，因为换行或字幕切换已经表达停顿。单条最多两行，每行最多 20 个字符，单条正文最多约 30 个字符；宁可增加字幕条目，也不把多个逻辑句硬塞在同一条字幕里。最终 SRT 是唯一排版负责人，合成器不得重新断行。

H3 内生旁白与 IndexTTS 的职责边界：H3 一次生成画面和声音适合 5–15 秒概念样片，能快速验证“画面 + 旁白”的方向；1–3 分钟正式视频不把 H3 内生旁白作为最终音轨。原因是每次重做画面都会连带改变声音，声线、语速、停顿、情绪和医学名词读法难以稳定复现；多个镜头分别生成时还可能发生音色漂移，逐句时间轴和字幕也只能依赖生成后识别。正式生产中，H3 只负责适合它的短画面片段，IndexTTS 负责同一参考声线下的旁白，二者解耦。

### 9.6 正式视频的声音主时间轴

正式视频先锁定最终 IndexTTS 音轨，再决定画面时间线。推荐顺序：

```text
审定旁白
  ↓
按自然语义拆分旁白，并按 5–10 秒观看节奏设计画面
  ↓
IndexTTS 使用同一参考声线逐段生成
  ↓
拼接最终音轨，记录每段真实起止时间
  ↓
对最终音轨做强制对齐，生成字幕时间轴
  ↓
按旁白段落时长剪辑对应画面
```

对齐必须同时满足三层：字幕与声音同步；画面与当前话题相关且不矛盾；总画面长度与最终音频一致。画面不需要逐句翻译旁白，也不追求嘴唇级同步。

执行规则：

- 每个语义段单独生成，统一参考录音、模型版本和参数；段间加入 200–500 毫秒可控停顿。
- 每段音频真实长度决定全片时间轴，但画面可在一句话中切换，也可跨相邻句延续，只要话题相关且节奏自然。
- 制作计划必须保存机器可读的视觉时间轴；每段至少包含素材文件、素材内起止点、镜头类型和与当前话题的关系。合成器禁止按文件名顺序平均铺片后再裁到总音频长度。
- 镜头边界默认使用无重叠硬切；需要转场时以观看自然为准，不能用交叉淡化掩盖重复或素材不足。
- H3 镜头偏长就裁剪；偏短则补一个新的主持、患者、家属或就医动作镜头，不用静态图凑时长。
- 不用整体加速或减速旁白去迁就画面，以免破坏本人自然声线。
- 字幕基于最终拼接音轨强制对齐，并以审定旁白约束识别文本；不能直接采用 ASR 猜出的错字或医学名词。
- 只重做某个 H3 镜头时，只要旁白段没有变化，配音和字幕时间线不重做；只修改一句旁白时，重新生成该段并重算其后的时码。
- QA 必须在每个镜头边界前后抽帧，把当前字幕、话题和画面关系并排核对；重点查无关跳转和错误暗示，不查逐词图解。

### 9.7 总时长相同不等于音画同步

早期构建器把固定时长镜头按文件名顺序拼接，最后裁到音频总长。结果虽然音视频都约 121 秒，但检查、就诊资料和收束画面与旁白逐渐错位，末段甚至倒回了开场画面。

修复原则是先从最终音轨取得真实语义边界，再在 `visual_timeline` 中逐段绑定素材和本段目的。一个原始镜头可以被不同语义段引用，也可以交换顺序；合成器不得自行用“第几个文件”推断叙事顺序。QA 必须在每个切点前后核对字幕、旁白和画面。

### 9.8 医学解剖不稳定

负面提示词不能保证医学正确。精确解剖、报告和复杂流程默认不交给 H3；旁白能够讲清时，直接用医生讲解或患者情境承接。只有不看图就难以理解行动结论时，才短暂使用审定插图并保留人工医学审核。已审核插图不能替代整篇动画，也不应无边界地反复赌随机种子。

第一幕曾把垂体病灶画成轴位脑中央亮点，第二篇又把病灶变成脱离头颅的漂浮球体。根因不是提示词细节不足，而是任务超出 H3 的稳定职责。报告只承载患者看到结果后的情绪，纸面保持干净；解剖若非行动结论必需就不出现，确需出现时只用独立审定插图。

### 9.9 静态图的无意义运动

早期原型曾对稳定解说图使用持续轻微推镜。复盘发现，这种运动没有增加医学信息，反而造成画面漂移感，尤其在 608×352 的低分辨率下更明显。后续规则为：

- 稳定解剖图、检查对照图和收束信息图默认静止。
- 只有能改变观众理解的局部元素才运动，并在分镜中写明运动含义和起止时点。
- 若镜头需要更长时长，延长稳定停留或切换到下一张有新信息的图，不用 zoompan、随机平移或循环微抖动凑时长。
- 返修时先判断运动是否有语义；没有语义就删除，而不是继续调小幅度。

### 9.10 场景载体会诱发伪文字和身份污染

报告、药盒、屏幕、胸牌和墙面标识会强烈诱发模型生成伪文字；“留白”提示不能保证它们一直为空。第一幕 H3 返修还自行生成了患者头像小窗，说明预留头像位置也可能被模型误解为场景内容。

因此，第一幕报告不承载文字或医学图示；字幕、品牌和头像由后期确定性处理。品牌头像使用独立审定文件，禁止从患者场景或复合母图按固定坐标临时裁切，也禁止让 H3 在场景内生成角标头像。若候选仍自行生成角标或伪文字，必须整段清理/淘汰后才能进入成片；不能把模型生成的“咩”当作品牌资产。

### 9.11 候选不是只能整段接受或整段报废

H3 镜头可能前半段准确、后半段漂移。若核心对象和转场在一个清楚时间点之前均通过检查，可记录 `source_end` 只使用合格范围；如果错误已经污染核心医学对象、人物身份或无法找到稳定切点，则整段退回。这个区间决策必须写进制作单和构建清单，不能只存在剪辑者记忆里。

### 9.12 透明字幕层变黑与提前结束

系列批量合成曾出现两种“文件可解码但画面黑屏”的问题。第一，FFmpeg 8 对重复单帧 PNG 的 `ffconcat duration` 处理不稳定，字幕图层可能提前结束；第二，ImageMagick 的 `xc:none` 若保存成 1-bit `monob`，FFmpeg 会把透明背景解码成不透明黑底。

当前处理规则：字幕使用持续 PNG 输入，并用 `overlay enable=between(...)` 按时段启用；所有透明画布强制输出 `PNG32`。技术 QA 必须同时做完整解码和抽帧亮度检查，不能把 `ffmpeg -f null` 成功当作无黑屏证据。

### 9.13 Whisper 提示词会损害中文词级时间轴

逐节拍对齐时，给 Whisper 传入整段审定稿作为 `initial_prompt` 会让部分中文词时间残缺或被提示文本牵引。当前第 2-12 篇按独立语义节拍无提示词转写：ASR 只提供声学时间，最终字幕文字始终来自审定稿；每个节拍保存 ASR 匹配率和词时间覆盖率。匹配率用于发现读错或漏读，不能授权把 ASR 猜出的文本写回字幕。

## 10. 下一阶段迭代顺序

按对成片质量的直接影响排序：

1. 由垂体专科医生逐篇终审旁白、字幕和关键医学画面，形成可定位到篇章/镜头的修改单；当前技术 QA 不能替代这一步。
2. 根据医学终审结果只返修受影响的旁白节拍、SRT 和视觉段，保持未变化的最终音轨与素材不动。
3. 提升到发布级分辨率，验证 4090 上的显存、内存、耗时和稳定性；当前按用户决定继续使用横屏原型，不提前扩展多画幅。
4. 先用第二篇验证“医生陪伴式讲解 + 患者情境 + 就医行动”，再用 3-5 个不同医学主题验证同一镜头类型库，之后固定跨主题合同。
5. 质量稳定后，再评估是否需要图形前端；当前根级工作台、结构化目录和批量脚本已能完成选择系列、生成、QA、发布打包和失败恢复。

前四项没有跑稳前，不宜先做完整前端。否则界面会把仍在快速变化的制作参数过早固化，后续每次更换模型或剪辑策略都要同步改 UI。

## 11. 维护规则

- 本文是本项目视频呈现模块的设计、边界和验收权威来源。
- `backends/h3/README.md` 是当前 H3 部署和运行手册；脚本行为变化时先改脚本，再同步手册和本文中的事实。
- 医学科普内容生产方法由本项目 `docs/01_医学科普内容生产.md` 独立维护；AI 小红书笔记和 RedCube AI 是经验来源及兼容输入，不是本项目的运行时权威来源。
- 新模型接入应复用同一个故事包和质量门槛，不为每个模型复制一套内容事实。
- 每次原型升级保留最终成片、制作单、模型版本、随机种子、技术规格、ASR 回读和联系表，才能声称可复现。
- 发布标题和正文统一维护在主题 `06_release_catalog.yaml`，通过 `scripts/build_release_packages.py` 生成；不得直接修改生成后的单篇交付包形成第二套当前文案。
- 端到端操作、返修和失败恢复遵循 `docs/04_医学科普视频系列SOP.md`。
- 只有经过多主题、发布分辨率、医学审核和端到端批量验证后，状态才能从“技术原型”改为“生产就绪”。
