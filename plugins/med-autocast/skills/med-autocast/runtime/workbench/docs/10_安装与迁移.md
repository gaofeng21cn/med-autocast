# 安装与迁移

工作台核心不要求 NAS，也不要求本机安装视频模型。存储介质与推理机器由部署配置决定。

## 安装

核心需要 Python 3.11 或更新版本、PyYAML、FFmpeg/ffprobe、ImageMagick 和一份可用字体。核心依赖与可选 Whisper 依赖分别登记在 `requirements.txt` 和 `requirements-alignment.txt`；IndexTTS、H3 的模型环境保持独立，不能把 CUDA、MLX 或大模型依赖装进工作台核心环境。

macOS 可用 Homebrew 安装系统工具：

```bash
brew install python ffmpeg imagemagick
bash scripts/setup_workbench.sh
source .venv/bin/activate
bash scripts/setup_workbench.sh --check
```

安装脚本只创建本目录 `.venv` 并安装核心依赖，不下载模型、不启动服务、不修改后端默认。Linux 使用系统包管理器安装同等工具，字体通过部署档案 `tools.font` 或 `WORKBENCH_FONT` 指定。可选对齐环境显式安装 `requirements-alignment.txt`，模型权重另行准备；这份清单是兼容范围，不是跨平台锁定快照。

新用户先复制作者与部署档案模板、登记自己的授权资产，再修改 `workbench.yaml.active_profiles`。无人物、无头像、无 BGM 均可配置，不必复制本用户的个人资产。Key 只放环境变量或密钥库。

H3 安装不再自动带入某位作者的提示和图片。需要生成参考工作流时，给 `prepare_workflow.py` 显式传入 `--prompt`、`--reference-image` 和可选 `--workflow-name`。systemd 文件是模板，`run_h3.sh` 根据 `H3_ROOT` 渲染实际服务，不能直接复制模板到服务目录。

IndexTTS 的局域网权重复制需显式提供 `INDEXTTS_REMOTE_HOST` 和 `INDEXTTS_REMOTE_MODEL_ROOT`，取值来自用户的部署档案；使用 `--skip-models` 只安装运行时。已部署服务不因更新这些源码自动重启。

## 存储边界

| 层 | 内容 | 迁移与备份方式 |
| --- | --- | --- |
| 工作台核心 | scripts、通用 backends、Skill、docs、templates、依赖清单 | 可复用源码；不包含用户资产和凭据 |
| 工作台实例 | workbench.yaml、profiles、作者与音乐资产 | 随所选作者迁移；声线与人物资产需有使用授权 |
| 系列作品 | content、productions、publish | 按系列携带内容、使用的候选、制作单、审核证据与成片 |
| 机器环境 | 外部模型、venv、SSH 配置、挂载点 | 按目标机器重新配置；模型可由 LAN/NAS 复制 |
| 过程与历史 | work、tmp、archive、legacy_tools | 先核对引用再清理；目录名称不代表可无条件删除 |

当前 `backends/h3/` 尚保留早期测试图片和提示用于复核，它们不是可分发核心的一部分。分享通用工作台时排除这些历史个人资产、`docs/local/` 和个人档案，使用模板初始化。`.gitignore` 防止误收运行时、临时文件和本机部署档案，不代表可以不备份这些文件，也不自动建立 Git 仓库。

NAS 只是部署选项：把模型或某个系列的生产根放在 NAS 时，在部署档案或系列登记中写实际路径即可。通用 Skill 不应要求固定 NAS、主机名或挂载点。活动模型的性能依赖存储吞吐；工作台不静默把本地模型搬到 NAS。

## 迁移验收

1. 暂停目标系列写入，再复制核心、实例配置和所需作品；不要移动正在生成的目录。
2. 同步引用资产。相对路径以工作台根或单集目录为基准；绝对路径必须在新机器更新。旧生产目录保持原样也能使用。
3. 更新 `workbench.yaml.series` 的目录登记，部署档案的主机、模型路径、字体，以及 SSH 与密钥环境；新系列使用独立生产根和 QA 文件。
4. 运行安装检查、指定系列配置验证和 `media_backend.py resolve`；这些检查不代表推理服务已经可以出片。
5. 对准备交付的系列运行发布包 `--check`，对新后端另做真实短片验收。已有未通过视觉审核的篇目应继续显示不可发布。

`publish/` 的视频是真实副本，适合压缩转存。发布 manifest v2 的媒体路径相对于 manifest 所在目录，因此发布包可以独立移动；制作关联链接则在携带原作品目录时才能继续解析。

当前已制作内容不因目录整理自动重生成、自动获得医学批准或自动切换模型。本机仍使用部署档案原来的 RTX 4090 视频、音频默认值。
