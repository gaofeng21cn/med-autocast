# 素材准入与配音基线

新 JS 科普视频默认使用富有想象力的手绘拼贴：真实纸张质感、剪贴图层、手绘线条、人工排版和轻微不规则运动，共同服务叙事。医学主体先准备正确素材，再编排动画；不能用错误的代码自绘器官充当占位成片。

## 素材入口

先查看已审资产，静态参考不等于可直接使用。缺口通过 ImageGen Skill 的内置工具或有明确许可的网上素材补齐。ImageGen 是当前 Codex 会话提供的能力，Med Auto Cast 的 Python 工具不冒充已经调用它；没有可用工具时保留缺口。生成前记录医学参考、画面要解释的关系及不能暗示的含义，生成后保存原提示、工具回执和选图理由，查看图像后再记录审核。

项目根目录保存 `asset_manifest.json`，schema 为 `medical_animation_assets/v1`。所有文件引用相对该清单目录。`assets` 中每项包含：

- `asset_id`、`path`、`source_type`（`reviewed_library`、`imagegen`、`licensed_web`、`authored_graphic`）。
- `visual_meaning`、`must_not_imply`、布尔值 `medical`；医学主体还须 `medical_reference` 文件。
- ImageGen 必须有 `prompt_ref`、`generation_receipt`；网上素材必须有 `source_url`、`license`、`license_evidence`，搜索引擎结果不是许可证明。
- `status` 默认为 `pending_review`；已拒绝素材为 `rejected`；直接使用需 `approved_direct_use`。
- `visual_review`，医学主体还需 `medical_review`，各含 `status` 和 `evidence_ref`。通过时证据 JSON 必须绑定 `asset_id`、`asset_ref`，记录相应审核字段为 `passed`、`reviewer`、`notes`。证据中的路径也相对清单目录。

`shots` 列出每个 `shot_id` 和实际使用的 `asset_ids`。字体、纸张、装饰可共用；解剖主体和疾病关系须独立明确。机器只检查登记、引用和声明，画面正确性仍由实际看图和医学审核判断。

```bash
python3 scripts/check_animation_assets.py --manifest <项目>/asset_manifest.json
python3 scripts/render_javascript_animation.py --project-root <项目> --check-only
```

正式渲染入口默认先执行准入检查。手动调用项目自己的 Node 脚本不受该入口约束，不得据此宣称完成工作台审核。

需要用整片审看待审素材时，使用同一入口的 `--review-candidate`。它允许待审状态进入候选渲染，仍阻断已拒绝素材、来源缺失和无效引用。输出旁保存素材欠账和 `release_eligible: false` 回执；默认准入和正式交付预检不因此放行。

手绘拼贴的主体应优先生成带真实 alpha 的透明底 PNG，按需要独立运动的对象拆层。完整构图只承担背景或静态参考；分辨率大本身不是问题，无法分层才是问题。生成后检查透明通道、轮廓留白和实际画幅下的叠放，不把棋盘纹理当透明背景。

## 配音入口

用户授权声线优先。全篇共用一个旁白基线、同一参考音频和合成参数；不得给急诊、治疗、收尾等场景换不同情绪指令。IndexTTS 如因模型限制分段，也须记录固定情绪参数和模型参数，并逐段与全篇审听。语义重音可以自然变化，音色、距离感、情绪强度不应突然跳变。

Edge 保底入口接受纯旁白文本，整篇一次 `Communicate` 提交，默认 `zh-CN-XiaoyiNeural`、`rate=-8%`、`pitch=+0Hz`、`volume=+0%`。底层服务可能分块，不能保证绝对一致；Edge 没有本入口可用的自由情绪控制，不能把中文语气要求传入正文让它朗读。

```bash
python3 scripts/render_edge_tts.py --text narration.txt --output review-v2/narration.wav
python3 scripts/audio_baseline.py --audio narration.wav --beats narration_beats.json --report audio_qa.json
```

合成后两遍 EBU R128 归一化至旁白目标 -16 LUFS / -1 dBTP，并保留句子边界、文本和参数回执。句子边界须对齐校对后才能驱动画面或字幕，不复用旧语音时码。BGM 混入后还须检查最终成片。

场景响度偏离中位数超过 3 LU、静音或超出整轨目标会提示复核。这只是定位线索，不是情绪分类器；急诊段突然兴奋可能发生在响度完全一致时。`full_listening`、`tone_consistency` 默认 `pending`，必须完整听取旁白并重点比较场景接缝，才可作语义判断。

## 工作流测试边界

工作台入口、Med Auto Cast 源码分发入口、仓库内插件载体、已安装插件是不同生效位置。入口与负例验证通过不表示已安装插件升级，也不表示样片已通过听感或医学审核。用户拒绝的旧样片保留作故障证据，不作为默认风格或可用医学素材。


中文多音字和医学术语按[发音控制与听辨 SOP](27_中文配音发音控制与听辨SOP.md)执行：正文与 `tts_text` 分开，IndexTTS 2.5 支持原生注音，改注音即更新缓存。逐段原音和 `audio/pronunciation-review.json` 用于听辨定位，ASR、响度及注音输入均不能证明实际读音。已拒用 take 不得复用，局部重配后同步字幕、镜头及最终混音。
