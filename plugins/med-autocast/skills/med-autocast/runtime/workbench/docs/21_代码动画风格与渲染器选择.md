# 代码动画风格与渲染器选择

风格元数据以 `animation_style_registry.json` 为单一合同；工作台模板随包携带完整副本，智能体的 `contracts/animation_style_registry.json` 与它保持一致。这里的成熟度描述能力现状，不限制模型继续做导演策划、素材准备或兼容后端试作。

风格先于代码实现。导演在 `visual_treatment` 和镜头计划中确定观众任务、视觉锚点、素材类型、动作词汇和声音节奏；制作单再用 `style_id` 选择风格，用 `renderer` 选择实现后端。两者共享同一套 Score、Shot、Asset、Layout、Review 交接，不把某一个 renderer 当作所有动画的默认答案。

## Renderer 交接

不同 renderer 共享可寻址的时间轴和审片入口：`window.__seek(t_seconds)` 是逐帧捕获的共同入口；`__rendererId` 报告实际后端，`__requestedStyleId` 保存请求/计划风格，`__styleId` 只报告实现方明确声明已落地的风格。`__ready`、`__total`、`__cuts`、`__layout` 和 `__score` 为预览与布局复核提供信息。`__seek` 必须允许乱序调用并得到相同帧。Remotion 可在桥接层把秒数换成帧号，Three.js 可在 seek 后显式更新场景；后端内部时钟不另建主时间轴。

当前 Canvas 2D 模板已实现这套入口。其他 renderer 的成熟度在注册表中单独标注。若页面可 seek 但没有声明实际 renderer、实际 renderer 与请求不一致，或未声明风格如何落实，预览/候选仍可继续生成，回执应标出运行事实与 `quality_debt`；不得把计划项写成已激活能力，也不得只因元数据差异阻断前置 Stage。运行元数据不能判断画面是否真的符合某风格，最终仍由视觉 Review 语义审片。

## 可选风格

| style_id | 适用重点 | 常用 renderer | 主要风险 |
| --- | --- | --- | --- |
| `paper_collage` | 手绘纸片、撕边、胶带、图钉、遮挡、纸件接棒 | `canvas2d` | 透明素材和接触关系不准确会像 PPT |
| `line_art` | 线条生长、路径解释、手术或流程轮廓 | `svg` / `canvas2d` | 无语义连线和过度装饰 |
| `scientific_diagram` | 分层解剖、机制、流程和对比 | `svg` / `canvas2d` | 把图解做成静态教材，缺少因果动作 |
| `whiteboard` | 教学板书、逐步推导和标注 | `svg` / `canvas2d` | 文字占主导，手写节奏单一 |
| `flat_cutout` | 平面角色、道具和场景换位 | `canvas2d` / `remotion_dom` | 角色关节和遮挡穿帮 |
| `motion_comic` | 分格、推拉、拟声和叙事节奏 | `remotion_dom` / `canvas2d` | 过多文字框或镜头抖动 |
| `parallax_2_5d` | 景深、层叠空间、结构剖面 | `webgl_three` / `canvas2d` | 深度错误、性能和医学空间误读 |
| `watercolor_ink` | 水彩、墨线、情绪化医学隐喻 | `canvas2d` / `svg` | 颜色溢出影响可读性和医学边界 |
| `stop_motion_paper` | 逐格纸张、手工停顿和微小跳动 | `canvas2d` | cadence 失控、每格随机导致不可复现 |
| `kinetic_type` | 术语、节奏、数字和引导性文字 | `remotion_dom` / `svg` | 文字替代了视觉叙事 |
| `svg_morph` | 形状演化、结构转换和比较 | `svg` | 变形路径不代表医学关系 |
| `particle_field` | 微观、流体、细胞或概率场 | `canvas2d` / `webgl_three` | 粒子成为无意义背景 |
| `character_rig` | 可复用讲解角色和动作姿态 | `remotion_dom` / `canvas2d` | 角色基线、口型和医疗身份误用 |

## 选择规则

1. 先按患者任务和医学关系选风格，再按素材和动作需求选 renderer；不要从 renderer 反推故事。
2. `paper_collage` 的透明单件、前后遮挡、固定件和接触点必须进入素材准入；合成大图只能作参考。
3. 代码只实现导演稿中的起点、发展、接触、落点、转场和声音事件。渲染器不负责补救素材错误、字幕遮挡或没有视觉事件的长旁白。
4. 同一集保持一条主时间轴。Remotion、HyperFrames 或 Motion Canvas 可以用于独立镜头预览、DOM 排版或装配，但不能在幕后重新定义音画时码。
5. 未知或暂未实现的风格保留用户的 `style_id`，输出 `quality_debt` 和下一步建议；Progress First 允许继续做故事、资产和 Review，不把注册表缺项变成硬阻断。

当前真正端到端激活的是本地 `canvas2d`；`svg`、`remotion_dom` 仍是规划中的 renderer，`webgl_three` 为实验能力。`supported_next` 表示智能体可接受该风格、完成前置策划并保留明确 renderer 选择，不表示安装后已有完整通用模板。若目标 renderer 尚不可执行，先继续故事、素材与分镜，或由模型选择兼容的活动 renderer 并记录质量债务；不得静默把用户风格改成纸剧场。作者仍可在制作单中指定风格与 renderer。

## 共同 Review

每种风格都要先做去文字审片，再做完整审片；检查首帧、切入、准备/极值/落点、邻镜承接、字幕安全区、完整听感、医学关系和可复现 seek。风格专属 QA 只增加关注点，不能减少医学和声音 Review。通过的风格帧、透明纸件、镜头卡和返修原因进入系列资产库，具体品牌和医生形象仍来自工作区作者档案。
