# 全季交付回读与经验沉淀

本文件记录代码动画全季交付后，如何从当前工作区重建事实、修复交付说明并把经验反馈到下一轮制作。它服务于审看包和技术候选，不把机器回读升级为医学批准、完整听感通过或公开发布授权。

## 当前性先于批量检查

全季任务开始时先确定 `series_id` 和工作区根，再读取 `workbench.yaml`、系列登记、每集 `project.json`、`out/current.json` 与当前 `publish/<series>/<episode>/current/manifest.json`。当前制作版本由系列登记和 `project.json` 指向；`mtime`、目录排序、文件名前缀和旧 checkpoint 只能帮助发现线索，不能决定当前版本。

对代码纸剧场，每集的母版路径必须来自该项目的 `out/current.json`，而不是从 publish 目录反推。交付预检使用同一组明确输入，`--delivery` 传精确 manifest 文件，不传目录。预检通过只证明制作单、母版、publish 视频和 manifest 的引用与字节关系正确，同时返回仍待完成的质量债务。

## 全季技术审计

逐集预检通过后，再运行系列审计。审计应该报告字幕长度和主体遮挡、逐镜 `shot_recipe`、语义事件名、无 BGM 审听候选、当前 publish 唯一性、视频解码，以及制作母版、publish 视频和 manifest 的 SHA-256 一致性。

审计报告只记录它实际读取的范围。联系表、静帧、ASR、响度和浏览器布局可定位问题，但不能替代连续动态、完整听感或医生医学审查。`release_eligible`、`visual`、`full_motion`、`full_listening` 和 `medical` 必须分别保留，不用一个技术通过覆盖它们。

## 交付目录与归档

每集只保留一个活动 `current/`。被替换的当前候选移到该集自己的 `archive/<revision>/`，并保留 manifest、来源、回执和修订原因。全季文档不能把某一集的归档路径推广成所有集的归档路径，也不能仅因存在历史 `archive/*/current/` 就宣称它是本轮替换结果；本轮说明应依据本次日期和实际文件回读生成。

交付生成器应从 manifest 和真实目录生成版本、时长、哈希、预览帧、无音乐候选和归档路径。发布文案由标题自身的标点决定句号，不在问号或感叹号后追加重复句点。生成后回读 Markdown、JSON、SHA-256 清单和观看索引，避免视频已更新而文档仍指向旧版本。

## Progress First

发现版本、文档或审计问题时，先修正当前 owner 的实现或交付投影，再运行最窄验证。缺少字段、旧状态或单个工具失败时，保留可消费产物并写明 `quality_debt`、`route_back` 或可读诊断；只有当前性、权限、执行器、身份或明确人工决定等真实边界才停止工作。不会因为建议字段缺失而丢弃已完成媒体，也不会把“未通过”改写成“通过”。

返修后只重跑受影响的编码、预览、预检和系列审计；未改变的 IndexTTS 音轨、字幕或素材不重复生成。任何返修都要同步当前制作单、manifest、publish、README/checkpoint 和审查报告，防止恢复任务重新指向旧版本。

本方法是通用工作流经验；具体疾病、作者品牌、集数、日期和版本号留在目标工作区，不写入通用 Skill。
