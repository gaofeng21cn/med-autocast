# 中文配音发音控制与听辨 SOP

## 原则

中文 TTS 把文字读出来，不等于把语境读对。“看字还清楚”的“还”应读 hái；“归还”的“还”应读 huán。“重影”读 chóng yǐng，不能因单字常见读音选成 zhòng。读音由上下文决定，不建立“某字全局替换”的规则。

正文、配音专用输入、实际音频是三个对象。字幕和发布文案使用审定正文；配音输入可含后端原生注音；质量判断针对当前音频。机器核对正文身份、音频字节和缓存，AI/审听者判断语义及实际读音。注音输入成功、普通中文 ASR 同字转写、响度通过均不是发音通过。

## 配音稿交接就完成语境注音

多音字的正确读音属于配音稿，不是合成后补救项。内容策划写初稿时检查完整语境，导演联合收敛时将首句、多音字和医学术语的期望读音随稿交给制作。对于实际会合成的中文稿，优先准备可直接消费的 `tts_text`，不只在旁边写“注意读音”。可附 `pronunciation_notes` 说明词、所在声段/上下文、期望读音及理由；形式灵活，缺项记质量债，不让机械词表决定全文含义。品牌和疾病专用词表存作者/系列档案，通用 Skill 不写死品牌。

同一“还”可在不同句中读 hái 或 huán；整词、数字单位和缩写也要按语境处理。不得按单字全局自动注音。低歧义正文不必逐字加标签。未知医学词先查可靠读音，再做完整声段小样；先改变表达本身仅适用于内容与导演确认的同义改写。

## 拼接边界：逐段核对真实首词

段落切换听起来少字时，先区分源 take 漏读、拼接截字或错位、采样率处理错误、mix 遮盖及交付旧轨。前导静音只可能推迟起声，不能单凭静音长度宣称“吞字”。沿配音输入、源 take、拼接、归一化、mix 和当前 MP4 比较首词、尾词与真实采样位置；能量、频谱和 ASR 只用于定位，不按峰值阈值裁弱辅音。默认保留源信号，确需调整静音时先审真实边界。

修复后以实际新声音重新排时、构建、混音和编码；不强行维持旧总时长，不用删声、变速或间隙配平解决差异。只处理登记的当前目标集，历史副本留作比对，不通过工程目录通配扩大集数。工具和操作边界见[旁白拼接边界](33_旁白拼接边界SOP.md)与[逐集表意与段首完整性验收](39_逐集表意与段首完整性验收.md)。

## 制作顺序

1. 内容策划和导演通读全文，按语境标出多音字、医学术语、数字单位、缩写、引号与停顿边界。优先覆盖开头第一句及之前出现过的问题词。记录词所在声段、完整上下文、期望读音与理由；可用 Markdown 或 narration 中的补充说明，不用词表缺项阻断其他制作。
2. 后端核对当前模型的原生发音控制。有授权声线时保持同一参考音频和全篇表达方向。VoxCPM2 使用条理讲解风格指令，并支持上游示例中的原生大括号拼音（`{ni3}{hao3}`）。工作台把编辑稿里的 `<文字|大写拼音和声调>` 保存在 `tts_text` 与 `pronunciation_controls`，再生成实际 `model_text`（例如 `<还|HAI2>` → `{hai2}`）后合成；不要让模型朗读编辑标记。即使原生控制已生效，仍强制逐段人工听辨，不能因输入标签、ASR 或响度通过就跳过验收。
3. 先生成并审听首句与高风险术语所在声段，再扩展全文。听正常速度的无 BGM 原音；记录实际读音、漏字、错词、异常尾音、音色及语气。读错时重配该段并拒用精确旧 take，不能用后处理响度掩盖。首次术语测试可并行推进镜头/素材，未听的结果继续保留为候选。
4. 局部重配后使用真实新时长更新字幕、镜头切点及声音事件，保留语义断句。整段重配须听完整该段，并核对前后接缝，不只听一个字。
5. 混入 BGM/拟音并编码后，复核最终声音中的首句与修订窗口；完整听感须另行覆盖全片，不能继承源音或旧片的通过。审看材料保存源音、最终混音、上下文、期望读音和精确字节引用。

## 当前工具用法

全季可先生成非阻断的发音审计索引，定位高风险语境，再按段听辨：

```bash
python3 scripts/audit_pronunciation.py \
  --workspace <工作台> --series <系列ID> \
  --output work/<series>/pronunciation-audit.json
```

它只列出“还”“重影”“长期”“生长”“调整”“抽血”等语境和对应词在 `tts_text` 中的注音覆盖、实际模型输入与 Review 状态，不把规则命中当成错读，也不会阻断其他 Stage。

`narration.json` 可为单个声段增加 `tts_text`：

```json
{
  "beats": [{
    "id": "B01",
    "text": "看字还清楚，为什么医生仍可能安排视野检查？",
    "tts_text": "看字<还|HAI2>清楚，为什么医生仍可能安排视野检查？"
  }]
}
```

IndexTTS 历史回执按原输入与音频只读追溯，不再依赖已退役的词表和模型环境；新 VoxCPM2 回执分别保存 `tts_text`、原生拼音控制后的 `model_text` 和 `pronunciation_controls`，把带控制的声段标记为 `manual_review_required`。不合法的拼音输入会在该次合成前报错；其他镜头和素材工作继续。

去掉注音标签后必须还原同一正文；正文不能偷换成拼音，也不为绕开读音任意降低表达质量。`paper_project narrate --beat B01` 将配音输入纳入缓存，未变声段继续复用。`audio/pronunciation-review.json` 提供全段原音、当前轨道哈希、时间与请求读音，默认 pending；它是听辨索引，不是自动发音判定器。

确认旧声段读错时，在其 `audio/segments/<cache_key>.json` 的 `pronunciation_review` 记录 `status: rejected`、词/上下文、期望与实际听到的读音、审听者和该 WAV 的 sha256。冻结历史不改写，在新修订中保留旧音与用户反馈。render_narration 不复用明确拒用 take；paper_project 的混音/导出/交付不会把已拒用段当有效旁白。pending 可继续制作和候选审看。

声段生成成功后 `full_listening`、`tone_consistency` 和 `pronunciation_review` 保持待审。实际听辨通过必须有审听者、范围、当前音频字节和结论；没有音频听辨能力时如实保留 pending，并提供可直接听的无 BGM 原段与最终混音窗口，不能把 ASR 差异为零写成“发音正确”。

## Review 与 Meta Review

Review 查实际读音和全段听感；Meta Review 查读音问题是否被修复、源音到字幕/镜头/最终混音是否同版、覆盖范围是否真实。缺失记录或尚未审听作为质量债继续交接；已知读错且没有安全新 take 时继续其他 Stage，并明确受影响声音不能用于有效交付。声音审核与医学审核、动态审核和平台发布分开。

`build_no_music_mix --project P` 导出当前旁白＋拟音的独立无 BGM 版本，先核对已完成 mix 的旁白和 Score 字节；不改变正式混音。可通过 MAC workbench_tool 调用。配音前注音索引与配音后听辨是不同用途，不将“有标注”当成“读对”。

ASR 可能漏掉首句或尾句。对齐工具保留真实声段的整段提案，识别窗口与词级时间只作定位。内容/导演检查识别缺失后保留完整正文和语义断句，不能将全文压到识别出的段尾区间。首句小样同时核对字幕是否同步出现。

英文术语或缩写可以在配音稿中使用 CMU 音素，如 `<CT|S IY1 T IY1>` → `{S IY1 T IY1}`；中文拼音核对标准音节和 1—5 声调，旧 XVE4 转为 xue4。空读音、非法音素和未闭合标记会在模型加载前报错；保持 normalize=false，实际读音待听辨。时码以真正写入的采样数为准，ASR 原段时间戳按实际采样变换与落位映射到整轨；保留全部源样本时不得沿用历史裁头偏移。

数字和单位也可保留正文并标中文读音，如 `<5mg|WU3 HAO2 KE4>`；仍按语境确定读法和人工听辨。
