# 系列视觉语法与批量升级 SOP

## 为什么需要

同一套纸件工厂可以服务多集，但也会让不同疾病共享同一种构图、景别和镜头节奏。批量升级不能只把所有镜头换成同一段相机动画；那会把“重复”从画面构图变成运动公式。系列视觉语法只负责下限：确定基础构图、允许的景别、进入节奏、推移方向和残余漂移；导演仍可自由改写镜头动作、空间和事件。

## 四层结构

1. **系列语法**：每个主题一组 framing、travel、entry、move、tempo 和 counter framing。急性主题切入快，代谢主题退让慢，生活主题漂移，影像主题跟随后安静停住。
2. **镜头意图**：特写、局部、整体、跟随、揭示等意图决定目标景别。导演显式写 `close / follow / pullback` 时，显式意图优先。
3. **纸件动作**：拿取、翻面、夹住、推入、折叠、打开、收纳、接触后回弹。相机不能替代物件动作；只有相机运动而没有物件因果，仍然是技术演示。
4. **事件与声音**：揭示、接触、落点与旁白节拍共用 `score.json`，动作结束必须留下可读结果。

## 安全推广

- 只对共享工厂文件推广，系列专属镜头先人工审读；不得按文件名盲目全量替换。
- 替换前必须保存 `.pre-grammar` 备份，替换范围是完整 `camera` 属性，不能用前缀正则截断表达式。
- 推广后逐集 `build`，再抽一个代表镜头 `preview`；检查 NaN、空白帧、越界、字幕遮挡和主体偏移。
- 首批只选一个系列做样片，确认真实观看差异后再推广。相机语法不能被描述为“导演级重做”；导演级重做必须有新的空间、动作因果和事件节奏。
- 正式出片后必须重新渲染当前源码对应的 MP4，再执行 `paper_project package`；不能沿用旧成片结论。

## 当前实现

`src/series_grammar.ts` 提供 `grammarFor / baseCamera / cameraFor / sizeFor`。`install_series_grammar.py` 是带备份的批量工具，`optimize_current_episodes.py` 负责按 `workbench.yaml` 渲染并发布当前修订。工具只提供稳定下限，镜头自由度不被库存锁死。
