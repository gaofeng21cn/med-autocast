# 逐集评估与独立改写 SOP

## 评估当前成片，再独立返修

每集先确认当前工程、候选成片、实际旁白和字幕，按[逐集表意与段首完整性验收](39_逐集表意与段首完整性验收.md)检查本集患者任务、核心事实与实际对象/关系/结果。去文字反向描述画面，再恢复旁白和必要标签核对含义。静帧和源码只能定位，连续动态及完整声音须按实际覆盖范围记录。

`scripts/evaluate_episodes.py` 从 TypeScript 与 `score.json` 提供源码检索线索：

- 动作库与编排模式的调用密度（`actions.ts` 的纸件动作 + `patterns.ts` 的编排骨架）
- 纸件容器与固定件使用量
- 匹配到的机位表达式（不能据此认定实际画面在运动）
- 画内文字量
- 舞台数量
- 动作时点是否由 `beat.events` 驱动

它不评定动画质量，不按函数词频给分，也不按分数决定保持、升级或重写。调用可能是未使用代码、错误物件或没有绘制的空动作；固定机位、自定义动作和同一空间也可能非常适合当前故事。

是否需要重写由当前画面、同期事实与观众所得判断。表意错误、核心动作缺失或整集故事不成立时，回到最早责任点；局部构图、节奏或文字问题可局部返修。代码复杂度、动作数量和独立性哈希均不替代这一判断。

## 两条历史教训（写在这里就是为了不再犯）

1. **批量重渲染不等于优化。** 89 集曾做过一次「相机语法」批量升级：给每个疾病系列不同的构图、景别和推移速度，然后重渲染全部 89 集。核对源码后确认这轮没有改善动画本体——垂体瘤 12 集一行未改，其余 77 集只换了 `camera`，场景仍是物件并排摆好然后停住。
2. **共用工厂不是效率。** 76 集共用 3 个渲染工厂后，「一次改写全部受益」的批处理思路看似高效，实际把 89 集压成 11 集的导演稿。系列级工厂从一开始就不该存在（见 `docs/34_逐集独立导演与系列资产分层SOP.md`）。

## 批次只用于排期与验收，不用于共享实现

批次划分的作用是安排渲染与目视验收的人力，以及记录进度，**不是**让一组集数共用一份镜头代码。每一集都要：

1. 确认当前候选，记录本集真实问题、实际审查范围和未覆盖项
2. 读本集 `episode_stories.yaml` 的 beats 与 directing
3. 独立修订故事、导演稿与 `episodeshots.ts`；镜头数、空间和动作方式按本集患者任务决定
4. 重写本集 `scene_directions.json`（只含本集镜头 + 本集 intent）
5. `build` → `preview` → `render`；核对真实帧、受影响连续窗口与整集衔接，声音变化后同步真实时码与最终视频音轨
6. 按实际通过范围 `package`，回读用户会拿到的文件；审看交付与公开发布资格分开
7. 更新逐集报告：具体问题、改了什么、依据哪条事实、修后候选、实际复核范围与剩余项

一集未完成不阻断其他可消费工作，但不能把该集计入已完成。批处理成功只能报告批处理事实，不能批量填入视觉、听感或医学通过。

## 目视确认要抓什么

- **空白占位方块**：新增的纸片如果没有内容，会读成素材缺失。这是反复出现的真实缺陷，宁可不加这张纸。
- **文字打架**：新加的标签压住原有标题或记录线，叠第二张纸通常比写在原地更糟。
- **对象身份**：样本、器械、药物与食品是否正确，不能仅靠标签把尿杯改成血样。
- **动作真实**：注释说翻面、收纳或揭示时，实际是否绘制了部件和结果；空 group 不等于动作。
- **同期承接**：后续事实是否仍有画面解释，动作提前结束后是否长时间没有内容承接。
- **动作方向**：进入、揭示或原位变化按本集含义决定，不把画外飞入当作所有镜头标准。
- **接触阴影**：检查落桌、落盘、夹合的接触与结果是否可见，阴影、形变或遮挡按本镜材质和风格选择，不仅凭效果调用批准接触。
- **实景照片背景**：环境板与纸件是否有明确的媒介层级与职责；照片可以成为有意的拼贴材料，不能用统一罩染自动批准，也不能以混合媒介本身判错（见 `docs/35`）。
- **无意义大色块**：画面里的大面积色块如果只是文字底板又没有和物件对齐，删掉比留着好。

## 已验证的导演手法（可复用为原语，不是可复用为镜头）

- **一次读数**：设备飞入 → 读数随事件点亮 → 记录本飞入落位 → 笔迹写在页上 → 接触阴影。全程由 `beat.events` 驱动时点。
- **三张读数叠放**：每张依次滑入并轻微错位，最后夹子合拢——重复变成可数的东西。
- **两份记录对照**：两张纸被推到一起、对齐、夹合成一个判断，而不是并排放。
- **进入-操作-反应-落定**：见 `kit/patterns.ts` 的 `arc()`。本集从哪到哪、为什么、什么时候反应，由导演决定。

这些是手法库。每一集用哪几个、怎么排、填什么物件，仍由本集导演决定。静态科学关系、连续生活情境和局部医学变化也可采用更合适的镜头语言，不强制所有镜头走同一动作弧。具体表意与声音链复核见[39](39_逐集表意与段首完整性验收.md)。
