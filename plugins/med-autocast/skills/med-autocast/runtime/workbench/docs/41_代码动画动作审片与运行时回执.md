# 代码动画动作审片与运行时回执

更新：2026-10-18。本文把 nexu-io/open-design 的可复现运动方法落到 MAC 的 Canvas 纸剧场主线。OpenDesign 的 `build / breathe / resolve`、layout-first、固定种子、单一主时间轴和 animation-map 只提供导演与审片方法；医学事实、素材准入、完整听感和医学终审仍由 MAC 原职责负责。

## 1. 适用边界

MAC 默认仍是 TypeScript → Canvas 2D → Chrome → FFmpeg。HyperFrames/GSAP 可以做独立镜头预览或替换 renderer，但不建立第二条主时间轴。所有实现共享 `Score / Shot / Asset / Layout / Review` 和 `window.__seek(t_seconds)`。本工具只定位问题，不把机器发现改写成通过结论，也不阻断后续可消费工作。

## 2. 初稿先验收代表镜头

每集导演稿在完整扩展前先登记一个 `signature_shot` 或 `representative_shot`，并给出真实代码风格帧和短动作。代表镜头至少证明：

- 观众能在去文字画面中认出主物件、关系和变化；
- 动作具有准备、发展/接触、反应、落定和停留中的可读部分；
- 纸件的内容 bounds、接触点、前后层和认知比例成立；
- 首句或关键旁白、字幕安全区与镜头节奏能同时工作。

代表镜头通过后才扩展同集镜头。它提高初稿下限，但不替导演决定整集的故事、景别和动作语法。

## 3. 动作审片工具

对当前精确工程运行：

```bash
python3 scripts/audit_motion.py \
  --project /absolute/productions/<series>/<episode>/<revision> \
  --output work/<episode>/motion-audit.json --pretty
```

`render_javascript_animation.py --preview` 和正式渲染会自动执行同一审计，并在 `preview.json` 或成片旁边写入 `motion_audit`。报告检查：镜头重叠/空档、命名事件、动作弧覆盖、最长事件间隔、导演交接字段、重复镜头配方、事件签名重复、空间方向多样性、跨镜承接和代表镜头登记。

报告的 `quality_debt` 全部是 `blocks_stage_progress=false`。例如“缺少 reaction 事件”可能是有意静态观察，也可能是动作空洞；导演要回看精确帧、连续 strip、邻镜和正常速度后决定保留或重写。不能用债务数量、重复率或方向数量机械判定艺术质量。

## 4. 运行时回执

预览和正式渲染会记录 `medical_animation_runtime_receipt/v1`，包含：

- Node、操作系统、架构、Chrome 可执行路径；
- FFmpeg/FFprobe 版本；
- `index.html`、`project.json`、`score.json`、`dist/film.js` 和旁白输入的 SHA-256；
- 画幅、帧率、`window.__seek`、Score 主时钟和随机访问要求。

这份回执只证明本次运行读取了什么环境和输入，不能证明画面符合风格、医学语义或完整听感。源码、Score、素材、声音或浏览器发生变化时，应重新 build、preview、audit、render 并回读新回执。

## 5. 审片顺序

先看精确首帧和代表镜头，再看每镜准备/接触/反应/落定事件帧，随后看 12 姿态 strip、邻镜承接、去文字版本、正式字幕版本和正常速度整片。声音按旁白、无 BGM、完整混音分别审。联系表和 motion-audit 只用于定位重复、死区和可疑切点，不能替代连续动态、听感或医学复核。
