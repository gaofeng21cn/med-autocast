# 媒体文件生命周期与存储治理规范

更新：2026-11-16。本规范适用于医学科普纸剧场的工作台和 MAC。它解决一个先后顺序：先判断文件是否承担当前制作、恢复、审看或发布职责，再决定删除、原样保留或无损压缩；压缩不是保留理由。

## 一、四类生命周期

每个文件在治理计划中必须落入以下一类：

| 类别 | 含义 | 默认处理 |
| --- | --- | --- |
| `keep_operational` | 当前指针、当前返修、当前可运行工程或正式交付的直接输入 | 原样保留；运行链路要求时保留 WAV/PNG |
| `keep_canonical` | 医学来源、素材母版、作者档案、源码、Score、故事/导演/分镜、许可和审核结论 | 原样保留；不得按扩展名批量改写 |
| `keep_compressed` | 仍需恢复或审看，但不需要原始容器的证据与历史派生物 | 先完成无损校验，再换成 WebP/FLAC，保留哈希、恢复命令和来源指针 |
| `delete_rebuildable` / `delete_redundant` | 可由已保留输入重建的中间物，或已由充分证据替代的冗余副本 | 记录哈希、理由、替代证据或重建入口后删除 |

无法证明用途、引用或恢复路径的文件进入 `defer_review`，不凭目录名、年龄、文件名最高版本或“看起来像缓存”删除。

## 二、目录职责与保护边界

- `content/`、`profiles/`、`assets/`、`publish/`、`deliveries/` 和 `archive/` 是内容、身份、稳定素材、用户交付、内部交接和只读历史的权威层。先按 `keep_canonical` 保护其中的权威对象，再沿发布/替换/复用记录判断历史载荷的必要性，目录名本身不产生永久保留义务；交付视频和封面不因治理而重编码。
- `productions/<series>/<episode>/<revision>/` 中的源码、`project.json`、`score.json`、导演稿、分镜、故事源、素材清单、来源/许可、当前指针、当前母版和当前音频输入受保护。版本是否当前以 `workbench.yaml`、队列和 `out/current.json` 回读为准。
- `work/`、`output/` 和 `tmp/` 是运行态、批量输出和可重建临时层。只有已绑定审看问题、恢复路径或独立经验的材料进入 `keep_compressed`；其余按证据替代关系判断。
- `.render-*` 是渲染暂存目录。确认没有渲染、预览、TTS、打包进程写入后，列入 `delete_rebuildable`；不能因为进程退出码而跳过句柄和计划哈希核对。

## 三、图像规则

1. 先识别用途，再识别格式。`assets/` 中的原始透明素材、医学来源图和可复用库载荷保留原格式，除非所有消费者已验证支持替代格式。
2. `qa/` 或 `work/` 中的审看帧分成三种：联系表/动作条是摘要证据；`event-*`、`clean-*` 和被问题单引用的关键帧是定位证据；逐时刻编号帧是可重建源帧。
3. 有 `preview.json`、联系表和动作条时，未被独立问题记录引用的编号帧和动作条源帧可删除，在制修订也不保留这两种冗余缓存。冻结的 Score/构建输入仍匹配时，其余无独立引用的派生帧也可重新取样；历史源码已经变化时保留每个事件的中心帧、每镜去文字中间态和原联系表/动作条。回执明确是否能够重放当前源码，不承诺重建历史 PNG 的原始字节。
4. 当前返修的必要动作证据不得删除；无独立引用的保留帧转为无损 WebP，并逐像素核对 RGBA、更新生成的预览索引。被问题单按精确字节或路径引用的 PNG 已经是无损压缩图像，保留原容器，避免破坏证据绑定。素材母版同样不为统一扩展名而换格式。
5. 有损 JPEG 动作条、联系表只能承担定位和观看顺序，不得冒充逐帧原件或连续动态、听感、医学审核。

## 四、音频规则

- 当前项目的 `audio.wav`、源旁白和正在使用的片段保留 WAV，确保现有混音、渲染和返修链路可直接运行。
- 已冻结的旧版本或历史混音，如果仍需恢复，使用 FLAC 保存；FLAC 解码后的 WAV 字节必须与原 SHA-256 一致，且项目/回执中的引用同步更新。
- `foley`、`music-*`、`premix` 等中间轨先判断是否还需诊断：最终混音和真实输入已核验、没有独立审核引用时直接清理，不必先转成 FLAC。确需保留的中间轨才在还原字节校验后以 FLAC 取代 WAV。最终混音按来源与当前性保管，不能仅按文件名删除。
- 未被当前 Score、混音回执、审核记录或来源清单引用的失败 take、`unused-*` 和重复导出列入 `delete_rebuildable`；无法判定的源声保留或延后人工确认。

## 五、执行顺序和回执

每次治理必须按以下顺序执行，回执存入 `work/disk-lifecycle-YYYYMMDD/`：

1. 建立同口径基线：卷可用空间、目录逻辑大小和分配量、活动写入进程、当前项目与队列。
2. 生成逐文件计划，记录类别、理由、项目/版本、SHA-256、分配量、替代物和恢复命令。没有具体清单或清单尚未完整核验时不得删除。
3. 先按已判断的必要性处理删除项：逐文件复核计划 SHA、无活动写入、替代证据和恢复路径；删除后回读路径确实消失。冗余材料不先压缩一遍。
4. 对 `keep_compressed` 写入临时目标，完成像素或音频字节校验，登记精确映射和同目录回执，再删除原容器。压缩后的历史 WAV 需要使用时由恢复入口核对哈希并还原，当前播放/混音输入保持可直接运行。
5. 重新统计工作台和卷空间，核对当前工程、发布包、审核入口和恢复命令；区分目录分配量减少与 APFS 可用空间净变化。

## 六、持续约束

- 新预览默认使用无损 WebP；动作条源帧进入临时目录，紧凑模式不在工作台长期保存逐帧缓存。
- 新混音把可重建中间轨写成 FLAC；只有需要现有工具直接读取的当前输入才写 WAV。
- 新项目在 `project.json.storage_profile` 登记默认策略；每次实际处置在 `qa/lifecycle-receipt.json` 或治理回执中保存源/目标哈希、替代证据和恢复入口。不使用固定天数替代必要性判断。
- 制作、审看或修订收尾时，由当前负责人判断本集文件的去向；需要清理时先出精确计划。批量治理读取工作台及显式在制保护清单，不要求每集反复全盘扫描。`defer_review` 不影响其他制作，但不得静默扩大删除集合。

## 七、现有工具入口

工作台使用同根 `.venv/bin/python scripts/plan_workspace_retention.py plan --workspace <绝对路径> --policy <本次策略.json> --output <计划.json>`。策略只登记当前在制保护对象与本次人工判断，不按年龄自动删除。回读计划后，用 `apply --plan <计划.json> --parts review_frame audio render_temporary --output <回执.json>` 处理选定类别；工具先校验整个集合的身份和替代证据。

保留音轨需要重新编辑时，用 `restore --path <原WAV或FLAC绝对路径> --output <恢复回执.json>` 从同目录 `storage-compaction.json` 找到精确映射；恢复不会覆盖不同字节的原件。PNG 恢复核对 RGBA，WAV 恢复核对完整原始字节。已按必要性淘汰的缓存不提供虚假无损恢复承诺。

`compact_workspace_media.py plan` 仅为格式库存，其全量 apply 已关闭。旧工具产生的清单不能替代必要性判定。MAC 随包工具可通过 `workbench_tool --name plan_workspace_retention` 访问；工作台显式本地工具路径和已安装包分别回读，不把源码或载体通过当作安装完成。
