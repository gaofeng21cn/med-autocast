# 医学科普内容策划

以显式 `workspace_root` 定位制作数据，按目标系列解析作者覆盖和后端档案。OPL 持有阶段运行；本 Skill 保留原工作台专业职责。下文 `scripts/`、`backends/`、`content/`、`productions/`、`work/`、`publish/` 均相对制作工作区，方法链接相对本 Skill。工具通过 [工作台工具接入](../../../docs/workspace-adapter.md) 定位：优先使用现有工作区入口，缺少通用工具时使用随包工具；不得默默替换工作区的专用修订入口。案例中的疾病、尺寸和作者选择只适用于对应案例。


负责把材料转成患者能理解并安全行动的内容。覆盖[十阶段SOP](../../../runtime/workbench/docs/04_医学科普视频系列SOP.md#0-十阶段流程与交接)的S02—S05、S06内容交接，以及S09医学问题溯源和S10文案/证据更新。阶段合同以SOP为准；内容方法以[医学科普内容生产](../../../runtime/workbench/docs/01_医学科普内容生产.md)为准。本Skill不替代具备相关诊疗经验的医生复核。

## 找到本次内容范围

从`workbench.yaml.series`读取目标系列路径与作者档案；新选题尚未建系列时先读已有总规划及作者基线，交出选题结果，不为了规划启动视频生成。复用主题事实库与已审故事包，历史自媒体文案和模型输出只作线索。用户只要系列规划就完成S02—S04；只改画面时不重写已审旁白。

## 内容决策

- 先确定患者情境、误解、需要改善的判断和行动，再检索。选题综合常见程度、受众规模、误解后果和可行动性；不以作者想展示的知识或流量替代需求。
- 按内容文档第3.2—3.5节登记来源、时效、适用人群/地区、事实条件、不确定性和可视化边界。给定材料不自动成为事实；会影响结论的来源冲突未解决时保留缺口，不能自行补成确定答案。视觉参考同步记录用途、许可及隐私边界。
- 先组织医学关系与患者问题地图，再拆篇目。S04给出覆盖、排除、顺序、每集独有问题及前后依赖；集数服从内容。普通单集独立可理解，必要风险条件允许重复，不能留到下一集才交代。
- S05围绕一个核心问题组织“受众当前理解→必要解释→判断→主要行动”，按实际故事选择结构，不套固定开头或强造戏剧。每段能说明它改变什么理解，并引用支持的事实；不能把稿子写成知识清单。
- 在旁白草稿阶段交给`medical-video-director`共同设计可见事件。内容拥有含义与医学条件，导演拥有镜头与实现；模型做不到时调整表达、拆分或使用审定视觉，不能删掉影响患者判断的条件。不要先冻音轨再要求导演逐句配画面。

## 交接与审核

系列与单集骨架见[系列模板](../../../runtime/workbench/templates/series/README.md)。按范围维护`00_brief.md`、来源/事实/问题地图、`04_series_plan.md`及单集简报、旁白、故事包；医学事实只在事实库维护，其他产物引用fact_id和版本。

S06共同核对整篇故事板、实际基础表达与替代可执行性，记录内容审查、医生复核和视觉许可的真实状态，再冻结对应旁白/导演稿版本。没有实际复核人或证据就留pending，不能将AI自审填写为人工医学通过。故事包是语义交接，制作参数放制作单。

S09发现医学错误时回到相应事实、故事或画面定位，不靠免责声明补救。医学文字正确也要核对画面有无新增因果、解剖或诊断暗示。S10发布文案从已审故事包压缩，只在登记的`release_catalog`维护，再交打包器生成两份TXT；新增医学判断必须回上游复核。

指南更新或反馈命中某事实时，先找引用该fact_id的集和段，再更新受影响旁白、字幕、画面、审核与文案；只有措辞/排版变化且含义未变时限定修订范围。记录真实收益与遗留缺口，不用标题数量、关键词或字段齐全代替内容质量判断。
