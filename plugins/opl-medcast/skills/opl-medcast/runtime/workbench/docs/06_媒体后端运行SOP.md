# 媒体后端运行 SOP

本 SOP 负责把已经审定的旁白和镜头卡交给正确后端，并留下可追踪的生成回执。后端能力以 `backends/config/media_backends.yaml` 为准，当前实例和默认选择以 `workbench.yaml.active_profiles.media_backends` 为准；机器实测、NAS 和临时缓存记录属于 `docs/local/`。

## 1. 默认选择

视频和音频默认值只从当前部署档案的 `policy.default_video` 与 `policy.default_audio` 读取。Skill、SOP 和能力目录都不另设默认。后端不可达不授权静默切换。

## 2. 开工检查

先按 [系列 SOP](04_医学科普视频系列SOP.md#5-制作阶段) 盘点可复用 WAV/SRT、候选与源区间。只改剪辑或文案时不需要启动推理服务；确有生成缺口时在工作台根目录运行：

```bash
python3 scripts/media_backend.py resolve --media video --pretty
python3 scripts/media_backend.py resolve --media audio --pretty
python3 scripts/media_backend.py doctor --pretty
python3 scripts/workbench_config.py validate --pretty
```

继续生产前确认默认实例存在，且相应 endpoint、本地运行时或 SSH 路径达到它的健康条件。隧道、主机别名、端口和模型目录从部署档案与 `docs/local/` 读取。SSH 身份校验失败时停止，不关闭主机密钥检查。

## 3. 旁白生成

审定旁白、声线和音频无变化时复用原 WAV 与 SRT，制作单记录真实路径和实测时长。缺音轨、需改声线或修正读音时，才按作者档案生成并重建对齐；最终音轨是唯一时间轴。实际后端、设备和参考声音从制作单、作者档案和部署档案解析，参考声音必须获得授权。

每篇完成后检查：WAV 可解码、采样参数一致、总时长合理；Whisper 只用于回读和对齐，审定稿仍是字幕文字唯一来源。医学词、漏读、重读和异常停顿必须人工复核。

## 4. 生成视频与回执

先确认导演已经落实基础素材、新生成的收益及失败时的具体替代，按[连续性SOP第0.4节](11_解释对应与叙事连续性SOP.md#04-先保证下限再增加效果)执行累计预算。不先攻克最难样本；生活动作通过不代表复杂设备通过。已有可用候选不重复smoke。H3调用按[调研策略](12_H3调研与制作策略.md)选择已验证路线，未知模式试验不成为整季依赖。实际请求从能力目录指向的实现入口读取，参数从部署档案解析。

新任务先看完整首帧并核对实际发送提示，不从approved文件名推断正确，也不从正确首帧推断全片正确。生成失败取已核对可用区间或交回导演采用预定替代；仅明确输入/调用缺陷允许一次修正。回执包含后端ID、模型、任务ID、seed、去密请求和精确输出；队列接受不等于交付。独立尾帧输入已有代码，尚无本项目稳定生产证据。

当前 `queue_h3_shots.py` 对 `h3_capability_first_shots/v1`、`h3_semantic_shots/v2` 检查 `ready_to_generate`；第二篇历史 `h3_capability_first_shots/v2` 不在此集合中。不要假设脚本能统一保护所有旧输入，也不要把历史 ready 状态当作当前排队指令；先从制作单确认真实缺口。本轮不改写历史回执来冒充新提示词已执行。

当前脚本已有 `official_prompt` 完整直通及模式核对；旧 `motion_prompt` 仍有历史锁定包装，不能混用。原生节点不自动补官方首帧说明。I2VA、FL2VA、Ref2VA按真实资产职责及对应权重选择，代码支持不证明新能力稳定。[本机核查](production-lessons.md)保留实现和输出验证依据。

当前高血压继续608×352、24fps、配套Turbo8，不恢复已中止高清试验。采样及画布比较仅在具体需求下独立进行，分别留回执。保存实际帧数与时长，按17k+5网格和24fps处理，不以请求秒数代替媒体回读。断流与视觉失败分开处理，先查询原任务。

### 4.1 场景关键帧与图片 API 故障

需要人物连续性或明确物件关系时，先生成完整场景关键帧并实际查看，再交给视频后端。图片工具返回 404 时先核对真正请求的入口与路由支持范围；文本 Responses 可用不能证明同一入口支持 Images。当前请求已经授权的图片 API 可以继续使用，不把图片故障作为跳过参考图、改用无参考文生视频的理由。

1. 从当前供应商配置解析 base URL 和凭据来源，分别判断客户端、中继和上游的断点。只将凭据放在受控环境或请求头，不写日志、回执或项目文件。
2. 中继不支持 Images 而登记的原始上游支持时，单次图片请求使用该上游；保留正在服务对话的通路，不为出图重启共享中继。
3. 先真实生成一张 PNG、解码并实际查看，再批量生成独立场景。编辑人物身份时同时参考目标场景与本篇已审患者，不只改衣服颜色。
4. 响应必须检查实际 `data` 项：非空 `b64_json` 才解码；只有 URL 时取回该精确生成结果。空结果、`b64_json: null` 或客户端解码失败不是供应商尚未生成的证据，先确认响应，避免重复计费。
5. 当前上游支持显式 `response_format=b64_json` 的编辑请求；其他供应商按其实际协议使用。批量结果逐项验收，只补失败项。

2026-09-06 的本机 404 定位、已实测入口和请求方式见 恢复记录（来源工作区案例：`work/series-diversity/image-api-recovery.md`）。该记录证明替代 API 生产路径恢复，不表示内置工具已经修复；机器端口、凭据字段和供应商支持不能外推为通用合同。

### 4.2 提交快照与串行批次

提交前核对同一次请求的已审关键帧、后端实际引用、完整发送提示、模式与参数。队列可能已经读取旧设计；修改design或本地图像后，必须回读即将发送的请求及实际上传引用，不能用编辑完成代替输入已生效。已提交任务保留原请求；确有输入缺陷时，按累计预算作一次定向修正，用独立任务标识和回执关联原任务及原因，不篡改历史来冒充新版已执行。接口已有的graph_hash等幂等校验按原合同保留，不将其扩展为日常剪辑新增哈希门槛。

批次每轮可能只处理启动时的ready快照。停止前用当前应处理清单对照精确回执和产物，核对本轮后批准的条目；每项须有已验证输出或明确失败/弃用原因，未决项不能被“全部关键帧审完”或旧快照完成标记吞掉。生成结束与全季制作完成分别记录。沿用唯一写入者补齐缺口；原进程仍运行时不另起runner争写回执或成片。

图片、视频和完整响应保存到受控文件；对话工具文本只返回必要状态、任务引用与精确本地路径，不打印base64、data URL、image_url内容或整个生成响应。查看图片使用图片工具或清晰度合适的联系表。图片结果已生成但显示/解码异常时按4.1节取回原结果，不把重新生成作为显示修复。

## 5. 精确取回与技术验收

只按回执的任务 ID 和输出引用取回文件，不按目录时间或文件名前缀猜测。云端签名 URL 成功后立即下载，不把 URL 本身当作交付物。

```bash
ffprobe -v error -show_streams -show_format \
  productions/<episode_id>/candidates/<output>.mp4
```

技术验收至少确认视频可解码、分辨率、时长和音视频流符合请求。随后立即交给 `$medical-video-visual-qa`；动作、人物连续性、手绘质感、伪文字和医学误导风险不能由 `ffprobe` 代替。

## 6. 后端切换

切换时先记录原因，再显式解析目标：

```bash
python3 scripts/media_backend.py resolve --media video \
  --backend <backend-id> --pretty
```

本地资源模式、云 API 状态、部署脚本和特定模型限制均从该实例引用的实现文档读取。切换单次任务不修改部署档案的默认值；新后端只有真实生成 MP4/WAV、完成媒体回读并记录性能或费用后，才能从 candidate 升级。

## 7. 收尾

保留生成回执、取回文件、`ffprobe` 结果和后端耗时；候选移交视觉 QA，已通过素材再进入制作单。临时权重、转换中间文件和缓存不进入项目目录；确认受控存储已有完整副本后才可清理测试副本，不删除当前部署档案保护的生产通道或唯一模型副本。

## 8. 中断后续接

先核对原进程、后端 queue/history、回执任务 ID 与输出，再决定继续查询、取回或重新提交。聊天的 `stream disconnected ... /v1/responses` 不是后端失败证据；不能一断线就开启第二个写入者。已有完整文件通过媒体回读后从最深未完成层继续，具体恢复顺序见系列 SOP 第 9 节。接口可达、推理阶段日志或输出路径出现都不等于任务已完成。
