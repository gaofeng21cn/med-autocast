# 多后端能力与运行合同

本文件定义工作台可选择的媒体后端类型、公共请求字段、选择规则和验收标准。`backends/config/media_backends.yaml` 是能力目录，`workbench.yaml` 选中的 `profiles/backends/<id>.yaml` 是当前部署配置；机器实测、临时进程和性能记录只放在 `docs/local/`。

## 结论

- 视频后端分为局域网算力、本地高性能、本地低内存兼容和用户配置云 API 四类；每类可以登记多个实现、供应商或模型。
- 默认后端由当前部署档案决定。新增或配置云 API 不会删除现有后端，也不会静默改写生产默认值。
- 云 API 不要求工作台机器安装模型。用户提供供应商 endpoint 和专用凭据，工作台负责协议适配、异步轮询、下载、回执和媒体验收。
- 当前已确认 MiniMax 官方 H3 与 APIYI Seedance 2.5 的原生异步协议；调用器仍待实现，详细合同见 `docs/08_云视频API接入.md`。
- Skill、通用合同和机器落地记录分工明确：Skill 保存选择方法与经验，合同保存稳定接口，`docs/local/` 保存特定设备的部署和实测。

## 已登记能力

| 能力定义 | 类型 | 可实例化为 |
| --- | --- | --- |
| `minimax_h3_comfyui` | ComfyUI 生成协议 | 本地或局域网运行时 |
| `minimax_h3_api` | MiniMax 官方 Video V2 API | 用户配置的云视频实例 |
| `seedance_2_5_api` | APIYI Seedance 2.5 异步 API | 用户配置的云视频实例 |
| `indextts_2_5` | IndexTTS 旁白能力 | 本地或局域网音频运行时 |

供应商协议和凭据环境变量名从能力目录读取；具体实例 ID、endpoint、模型选择、运行 profile 和默认值从部署档案读取。

## 公共请求合同

视频编排层使用与后端无关的字段表达意图：

```yaml
backend: configured_video_backend_id
prompt: "..."
duration_seconds: 5
resolution: 768P
aspect_ratio: "16:9"
reference_inputs: []
generate_audio: false
output: /path/to/result.mp4
backend_options: {}
```

- `reference_inputs` 可以包含首帧、尾帧、参考图、参考视频或参考音频；适配器必须按目标模型能力校验组合。
- `backend_options` 只承载无法通用化的模型或运行时参数，例如本地采样步数、内存 profile 或供应商扩展字段；不能改变公共字段含义。
- 后端不支持某个公共字段时必须明确报错或记录用户批准的降级，不能静默忽略。
- 音频请求额外包含 `text`、`voice/reference_audio` 和输出 WAV 路径。参考音频必须获得授权，生成后仍需回读和医学术语复核。

## 选择规则

1. 用户显式指定后端时先验证它满足任务所需的输入模态、时长、分辨率、音轨、隐私、成本和时延；没有指定时使用登记表当前默认值。
2. 后端暂时不可达不授权自动切换。需要切换时记录原因并显式选择，任务结束后不改写默认策略。
3. 本地与局域网路径适合已有算力、离线或敏感素材；云 API 适合降低工作台硬件要求和弹性生成。它们是并列能力，不是互相替代的产品路线。
4. 一般先完成统一旁白和时间轴，再生成短视频镜头；只有任务确实需要模型原生音画时才启用生成音频。
5. 长内容拆为可独立验收的短镜头。先跑最小真实任务，再提高分辨率、时长或并发。

## 本地与局域网后端

- 启动、隧道、模型位置和运行参数使用部署档案及对应实现文档，不写死在 Skill 中。
- 高性能与低内存 profile 必须显式选择；不能仅根据当前设备内存自动改变资源策略。
- 性能报告分别记录加载、推理、峰值内存和端到端耗时。设备型号、实测数据、NAS 和磁盘清理属于 `docs/local/`，不构成其他机器的前置条件。
- 权重可以从受控局域网来源复制；模型传输位置与实际推理位置是两件事。

## 云 API 后端

- endpoint 和 API Key 由用户或部署环境提供，凭据只从登记的环境变量或受控密钥存储读取。
- 每个供应商按真实创建、查询和下载接口适配；Bearer 鉴权或模型出现在 `/models` 中不能证明 OpenAI 视频协议兼容。
- 当前 OPL Gateway 未原生支持这些视频协议时使用供应商直连。将来接入 Gateway 只改变 endpoint 和凭据来源，不改变公共请求、回执和验收合同。
- `contract_documented` 只表示供应商契约已核实；在调用器实现并真实出片前不能标记 ready。

## 回执与验收

每次生成保留后端、供应商、模型、去密后的请求参数、任务 ID 或本地运行 ID、状态、耗时、输出路径和文件哈希。不得记录 API Key、认证头或完整签名 URL，也不得按目录时间猜测输出。

后端只有同时满足以下条件，才能报告为可运行或生产就绪：

1. 实际配置和凭据齐全，目标服务或运行时可用；
2. 所选模型与参数真实产出目标 MP4/WAV，而非仅接受队列；
3. `ffprobe`、音频回读或等价检查确认文件可解码且媒体参数符合请求；
4. 异步任务收敛到明确终态，输出已在临时 URL 失效前下载；
5. 视觉、声音和医学语义通过相应人工 QA；
6. 新后端没有静默改变登记表的默认策略或删除其他能力。
