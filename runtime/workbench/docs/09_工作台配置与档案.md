> 本文保留来源工作台的专业方法与制作案例。案例中的作者、疾病、路径、参数和实测状态不代表新工作区的默认或验收；当前任务以所选档案、制作单及真实证据为准。

# 工作台配置与档案

本文档定义工作台的可迁移配置边界。核心原则是：专业文档持有方法，Skill 提供岗位决策与入口，档案保存用户与部署选择，生产文件记录某次实际使用了什么。

## 1. 四层责任

| 层 | 回答的问题 | 权威位置 |
| --- | --- | --- |
| 通用能力 | 如何导演、选后端、审核和交付 | `.agents/skills/`、`docs/` |
| 作者档案 | 谁在讲、什么声线、品牌资产和动画形式 | `profiles/authors/<id>.yaml` |
| 后端配置 | 能力合同是什么，当前机器怎样调用 | `backends/config/media_backends.yaml` + `profiles/backends/<id>.yaml` |
| 生产实例 | 这一集实际用了哪个档案、后端和候选 | `production_plan.yaml`、`visual_delivery_manifest.json`、生成回执 |

不这样拆分的直接后果是：更换医生需要改 Skill，更换机器需要改通用协议，更换模型还可能被发布门拒绝。

## 2. 作者档案

作者档案至少包含：

- `profile_id`、展示名、语言、受众和表达气质；
- 声音参考资产、声线指导和偏好音频后端；
- 可选的品牌人物参考图、稳定特征和身份审核要求；
- 视觉风格、动画形式、人物职责和精确医学图的处理方式；
- 品牌叠加和混音偏好。

作者档案不保存模型 endpoint、主机名、GPU 类型、部署实例 ID 或 API Key。`voice.preferred_backend_definition` 只表达可移植的能力偏好；实际音频后端必须从部署档案选择，并在单集制作单中留痕。

当前实例使用 `profiles/authors/dr_mie.yaml`。它是本用户配置，不是 Skill 的默认世界观。新作者从 `templates/profiles/author_profile.example.yaml` 复制，不复制 `Dr.咩` 的人物特征、声音或品牌文字。

### 2.1 S01作者基线与认可依据

[十阶段SOP](04_医学科普视频系列SOP.md#0-十阶段流程与交接)的S01输出可复用基线。真实作者的专业身份/内容边界与品牌讲解角色分别说明；卡通医生的外观不证明现实执业资质，剧中患者不自动继承作者身份。记录形象与声音素材的授权用途，不猜测资质、授权人或审核人。

基线需有实际形象参考、声音样本和适用风格参考，并说明认可了什么、未验证什么。可在作者档案使用可选`baseline`元数据：版本、真实身份说明、专业边界、样本用途/授权依据、风格样本引用及分项审核证据；新作者模板提供该结构。用户认可的历史样本可直接引用具体版本及会话/文件证据，不重复要求认可。文件存在或声音可解码不能证明听感获认可。

S01风格参考可以是已有认可片段/作品，不要求先生产完整一集。新系列常用解释方式的整体验证属于S04选样、S05—S09制作和验收；参考风格不能冒充新片通过。作者基线变化时确认影响的是形象、声线还是表达，按影响范围更新后续产物，不因换后端重设人设。

`baseline`是人工与AI读取的记录约定，当前配置校验器只核验原有必填字段、路径及资产存在；不会自动验证授权、身份或认可。既有档案不因缺少新元数据失效，也不在本次流程升级中虚构历史审核。

## 3. 后端能力与部署实例

`backends/config/media_backends.yaml` 只定义可移植能力，例如 MiniMax Video V2 的协议、Seedance 的任务路由、IndexTTS 的语音能力。它不决定当前应该连哪台机器。

`profiles/backends/<id>.yaml` 将能力定义实例化，记录：

- 实例 ID 与所引用的 `definition`；
- 本地或局域网主机、端点、运行时路径和资源模式；
- 云 API 的 endpoint 环境变量和模型选择；
- 当前默认与显式 fallback。

当前 `profiles/backends/example_deployment.yaml` 仍以 `h3_remote_4090` 和 `indextts_remote_4090` 为默认生产实例。这是本机部署选择，不是通用 Skill 的必要条件。

## 4. 生效、覆盖和留痕

1. `workbench.yaml.active_profiles` 选择工作台默认作者与部署档案。
2. 系列可在其登记中显式改写作者档案；不改写时继承工作台默认。
3. `production_plan.yaml` 必须记录 `delivery.author_profile`、`delivery.primary_video_backend` 和 `audio.backend`。
4. `visual_delivery_manifest.json` 记录同样的作者与主后端，生成镜头记录实际 `backend_id`。
5. 发布门验证制作单与 manifest 一致、生成动画为主、真实运动与人工审核；不按 MiniMax、Seedance 或其他供应商名称决定资格。

旧制作单和 manifest 中的 `primary_generator: MiniMax H3-Base` 与 `minimax_h3_hand_drawn_animation` 仍可读，用于保持已交付成片可复核；新文件一律写档案 ID、后端 ID 和供应商无关的 `generative_animation`。

## 5. 配置验证

```bash
python3 scripts/workbench_config.py validate --pretty
python3 scripts/workbench_config.py validate --series <series_id> --pretty
python3 scripts/media_backend.py list --pretty
python3 scripts/media_backend.py resolve --media video --pretty
```

前两条分别验证工作台默认与指定系列的档案和引用资产；后两条展示能力目录与当前部署档案合并后的实际配置。它们不显示 API Key，也不会因某个服务不可达而改写默认值。

## 6. 系列路径与执行入口

`workbench.yaml.series` 是系列目录的唯一运行时来源。新系列示例：

```yaml
series:
  example_s01:
    title: 示例第一季
    author_profile: profiles/authors/example_author.yaml
    topic_id: example
    content_root: content/example/example_s01
    production_root: productions/example_s01
    release_catalog: content/example/example_s01/06_release_catalog.yaml
    publish_root: publish/example_s01
    technical_qa: productions/example_s01/series-final-qa.json
```

路径相对于工作台根目录，也可以是绝对路径。新系列不要共享生产根目录或 QA 文件；当前垂体瘤系列保留原 `productions/`，不为整理目录搬动已有成片。旧 catalog 中 `publish_root`、`technical_qa` 字段只保留历史兼容，当前执行值以系列登记为准，不再维护第二份配置。

```bash
python3 scripts/build_episode_timelines.py --series example_s01
python3 scripts/build_series_videos.py --series example_s01 --episode 01_example
python3 scripts/qa_series_videos.py --series example_s01
python3 scripts/build_release_packages.py --series example_s01
python3 scripts/build_release_packages.py --series example_s01 --check
```

这些是不同生产阶段，不是一条可以盲目串行执行的初始化命令。时间轴生成器产出草案，其 `unassigned_*.mp4` 必须由导演按真实回执替换，不能猜测计数文件名。QA 单篇复查保留其他集 JSON 报告，但系列联系表只包含本次选择，不能据此声称全季已看；完整复查使用不带 `--episode` 的入口。打包器没有 `--episode`，单集更新示例见 [系列 SOP 第 7.1 节](04_医学科普视频系列SOP.md#71-单集更新与回读)，整季检查会报告其余未完成篇目。

音频生成与 Whisper 对齐入口也支持 `--series`；IndexTTS 仍在安装了模型的专属运行时执行，`--model-root` 指包含 `checkpoints/` 的运行时根目录，不是 checkpoints 本身。迁移到执行主机时应携带脚本、工作台登记、所用档案和引用资产，而不是只复制一份脚本。

H3 批量入口必须传 `--series`、`--base-queue`、`--output-root` 和 `--receipt-root`；默认 endpoint 从部署档案解析。`--output-root` 指实际取回或挂载的输出目录。续做依据回执与输出文件，而不是模糊文件名前缀；现有单镜命令仍可使用 `scripts/queue_h3_shots.py`。云 API 适配器尚未实现，登记了协议不等于可以交给 H3 入口执行。

已存在的回执只用于恢复同一组请求；修改旁白、声线、镜头提示、种子或后端时应另建本次输出目录/回执，或显式重生成并重新验收，不能把旧缓存当作新配置已经生效的证据。

## 7. 作者设置怎样生效

- `scripts/build_episode_video.py` 是唯一通用合成器；批量入口将选定作者档案显式传给它，作者 ID 与制作单不一致时停止。
- `brand.overlay_text` 控制品牌文字；`brand.enabled: false` 关闭文字，`brand.avatar_usage: disabled` 或 `--no-avatar` 关闭头像。
- `director_contract.brand_character_segments` 按实际片内品牌人物填写；当前只要非空，就关闭全部额外头像叠加，并非只避开这些区间。无人物镜头而需关头像时使用 `--no-avatar`，不填虚构镜号。
- `audio_mix.background_music: null` 表示不配 BGM；`--no-bgm` 可关闭本次合成的音乐。
- `target_relative_level_db: [low, high]` 取区间中点作为目标：先测量旁白和 BGM 在目标时长内的平均电平，再计算音乐增益。之后应用旁白侧链闪避和档案的淡入淡出；这不是 LUFS 响度认证，最终仍须试听。
- 实际品牌文字、作者 ID、混音参数写入构建目录的 `build-manifest.json`。本次整理不重建既有成片，新混音算法只在下一次显式构建时生效。
- 字体由命令行 `--font`、环境变量 `WORKBENCH_FONT`、部署档案 `tools.font` 依次选择，不属于作者身份配置。
- 合成器读取制作单画布，坐标按608x352基准缩放，帧率24fps；已验证608x352和1344x768合成，当前高血压仍按用户要求使用608x352。这不意味着所有字幕语言或云模型已适配。

### 7.1 制作单的真实输入

返修时保留未变的声音与字幕，显式填 `audio.source`、`subtitles.source` 和实测音轨时长。第一篇实际字幕是 `audio/local_voice/narration_index.srt`，不能因为其他篇叫 `narration.srt` 就照填；历史 v0 的 140 秒也不能替代当前音轨约 120.53 秒。

时间轴显式绑定实际 `source`、`source_start`、`source_end`，manifest 记录相同可用源区间。后期 `visual_annotations` 采用 `start`、`end`、`text`，可选 `offset`；默认左上 `+16+16`、17 号深字白描边，最多两行每行 20 字。按实际场景拆分时段并移动单条标签；下方留白并非通用安全区，还须避开主体、物件与字幕。无合适位置且字幕已表达完整时，可取消该段多余标签。标签不替代底部 SRT，实际遮挡由成片复核。

字幕默认底部居中、偏移 `+0+16`。必要时制作单 `subtitles.cue_offsets` 以从1开始的SRT条目编号指定偏移，例如 `{6: '+0+72', 7: '+0+72'}`，用于让姿势字幕避开双脚。只改变排版，不改变SRT正文或时码；编号超出实际条目或偏移格式无效时停止。回执 `subtitle_cue_offsets` 保存实际选择；SRT条目变更后重新核对编号，先预排再合成。

`audio.background_music` 等旧制作单字段可能只是历史记录，实际 BGM 与品牌参数按档案及 CLI 生效，并回读 `build-manifest.json`。已有合成候选通过审核后可继续 QA 和打包，不为了经过批量包装器重复编码。模板的 pending 状态必须由实际审核结论更新；`release_eligible` 的机器含义与完整听感/医学终审边界见系列 SOP 第 6 节。

## 8. 通用、系列专用与历史文件

作者资产的当前来源只从 `profiles/authors/` 读取。`backends/h3/` 中旧人物图片及现有制作单对它们的引用是历史快照，不再更新；新镜头上传作者资产后，把该后端实际返回的引用位置写入镜头文件，不假设另一台服务器已有同名图片。

垂体瘤专用提示、元数据和旧生成器位于 `content/pituitary_tumor/legacy_tools/`，不用于创建新系列。原脚本路径只保留明确标注的兼容入口；第一集旧合成入口转发到共享合成器，没有第二份合成实现。字幕专用词表位于各系列内容根的 `subtitle_terms.yaml`，通过 `--series` 读取；显式根目录模式可以传 `--subtitle-terms`。

安装、数据分层、NAS 使用和迁移验收见 `docs/10_安装与迁移.md`。
