# MiniMax H3 调研与医学视频制作策略

本机新增证据（2026-09-08）：[人物构图修复复盘](production-lessons.md)。H3会执行躯干近景，也可能在推近中丢掉头顶；此次通过已审区间和已有素材修复，没有新生成成功率数据。相关提示修订属于后续设计建议，不能冒充模型已验证能力或官方保证。

版本：1.1，2026-09-07。研究对象是 MiniMax H3，包括开源 H3-Base、官方上下文处理及 ComfyUI 实现；不混用 Hailuo 其他型号的参数。本文维护外部证据、采用理由和实际能力边界；可靠制作规则由[解释连续性 SOP 第0.4节](11_解释对应与叙事连续性SOP.md#04-先保证下限再增加效果)维护。

## 1. 结论

当前主要问题是制作方案依赖未经验证的生成能力：正确首帧被当作全段正确的保证，长旁白被机械交给一个长镜头，差异化被理解为大量全新场景，再靠不断修改提示和首帧补救。之前的文字课件又证明，仅降低动作难度不足以保证视频形式。分辨率、步数和提示格式都不能替代职责分配。

采用“已有可用动作 + 审定的具体对象与关系 + 按语义剪辑”的基础版本。H3承担已有同类证据的生活动作，新生成失败时回到事先准备好的素材。精准操作、设备结构、读数和医学关系不依赖H3在后续帧持续画对。先把整篇基础表达做实，再选择有收益的增强；不先攻克最难镜头，也不把未知能力推广到整季。

外部经验继续采用官方模式与参考职责、选择性运行、图词邻近和语义承接。官方支持与社区示例说明可探索的范围，本地全部尝试及实际源片决定当前生产范围；两者不混为“模型已经稳定”。

| SAWBO 官方实践介绍 [S9] | 将疾病等知识转为 2D/2.5D/3D 动画，再叠加多语言配音 | 借鉴视觉资产与配音分离、动作表达可复用；页面介绍不能证明某个 H3 提示或本项目制作效果 |

## 3. H3 能力应该怎样分配

| 需要观众看懂的内容 | 优先方式 | 下一层能力何时值得测试 |
| --- | --- | --- |
| 人物、场景与生活行动 | 已有可用动作区间优先；新任务限定简单可见变化，先准备基础素材 | 基础版成立后才增加可选运镜或动作，不为增加动感重新生成已合格片段 |
| 两个明确状态之间的变化 | 审定的起始、结果对象通过剪辑或已实现的局部动画连接 | 独立首尾帧FL2VA属于试验，失败不阻断解释，不要求模型精确接棒 |
| 同一角色换景别或场景 | 复用已有同场素材及明确的对象承接；不同例子可分别建立情境 | Ref2VA尚未验证，不用整季换装换景测试身份能力 |
| 同一动作超出单段 | 在动作说清时结束，接相关近景、结果或下一件事；先调整观看节奏 | AddGuide或latent context仅供必要且独立的连续运动试验 |
| 精确解剖、设备姿势、数值和曲线 | 精确区域使用已审素材及固定近景；必要的动画先做出、审核，再列入基础版 | 不让H3重画精确区域，不把动态屏幕追踪或新图解引擎当现成兜底 |
| 跨地点、多个治疗条件 | 分镜建立新情境，旁白保留条件 | 不让一段模型输出自行导演整个医学论证 |

“一个观看任务”也可能包含多个高风险动作。拿起包装、旋转到指定角度、稳定露出可读标签，语义上是一件事，实现上却有手物交互、几何保持和精准落点三个依赖。当前基础表达采用已有拿放片段接固定包装近景。动作能力的上限可继续探索，本季不依赖这些探索成功。

## 4. 稳定调用与画风

### 4.1 先固定视觉依据

从作者档案选定已审人物与画风，形成一套人物、环境全景及必要近景。记录笔触、材质、轮廓、颜色关系和空间布局，从实际图片提取描述，避免同时要求写实摄影、纸艺和水彩。每张派生图都实际检查；“同参考生成”不能代替身份复核。

首帧就是视频的真实开场。要展示拿放，物体先摆在可操作位置；要展示设备，姿势和部件先正确；不把人物头像当完整场景输入。关键数值在后期添加，空白区域的范围必须具体，不要求模型把整个环境变成无物体的白底。

### 4.2 使用模式匹配的结构化提示

基础模式使用官方三段格式，Ref2VA 使用六段格式；图片标签、角色与时间对应真实输入。具体格式、中文导演卡和英文示例见[导演提示指南](../../../agent/professional_skills/medical-video-director/references/h3-prompt-design.md)。

提示写成“真实开场 -> 动作发展 -> 结果/反应”，只保留有关的身份与关系约束。摄影运动描述类型、幅度和速度；已有运镜时不能再自动追加 locked-camera。避免冗长禁词与含糊的 cinematic / beautiful。文字长度不是优化目标，信息无冲突、具体可见才是。

本项目继续独立 IndexTTS 旁白，不要求 H3 同时负责医学朗读、人物口型和背景配乐。H3 环境声可按实际场景描述，最终默认不混入其原生音轨；如采用需另审。不要把删除音频字段理解为已关闭模型内部音频生成或已节省算力。

### 4.3 区分质量档位

2026-09-07用户明确纠正：高血压重做继续608×352旧尺寸，内容与形式优先，暂缓高清。下表的正式质量是后续可选试验，不是本轮完成样片或整季的前置条件。已启动的1344×768试验按要求主动中止，未留下正式质量出片证据，不视为模型失败。

| 档位 | 起始参数 | 用途与边界 |
| --- | --- | --- |
| 当前快速迭代规格 | 608×352，24fps，FL2VA Turbo 8 步、匹配的 LoRA | 当前用户明确选定的高血压审看交付规格；优先验证内容、动作和叙事 |
| 正式质量候选 | 1344×768，24fps，非 Turbo 20 步；动作仍不足时单独比较 25 步 | 官方建议基础，尚待本机端到端验证；保持采样器等其他变量不变 |
| 资源受限候选 | 例如社区 864×480、常规采样 | 是待测折中，不是已定默认；记录实际画布和最终输出，不标原生768p |
| 2K再生成 | 官方 H3-Regenerate-2K | 是另一阶段/服务，不等同于 FFmpeg 放大；当前不引入整季默认 |

1344×768 接近但并非精确 16:9，先选生成画布，再明确交付裁切或留边。Resolution Selector 的 1.0MP 会得到 1376×768，超出官方所述面积上限，应选 0.98MP 或明确宽高。只改生成尺寸不够：合成器、标签、字幕和品牌坐标必须随成片画布验证；不能先升清晰度再被旧合成器缩回 608×352。

Turbo开关、LoRA及步数要配套。FL2VA 8步 LoRA不能用于Ref2VA；Ref2VA官方模板的加速 LoRA是4步。采样器、sigma、量化、Sage Attention等仅在有明确问题时单独比较，不同时更换全部组件，也不为调研升级或重启共享生产服务。

### 4.4 稳定性包含任务恢复

先检查原队列和任务回执，保存真实发送提示、图、seed、参考资产哈希、Comfy/权重标识、尺寸、帧数、采样设置、任务ID、耗时及精确输出。请求超时只说明客户端没有取到结果，先查询同一任务，再决定是否重试。效果失败与传输失败分别记录；不重复排队，不靠目录时间猜输出。[后端 SOP](06_媒体后端运行SOP.md)

## 5. 新的最短制作流程

1. **先选可做的解释。** 同期旁白与观看对象共同设计，保留医学条件；先查已有动作、准确对象及可用源区间，不先列整季新生成清单。
2. **把基础表达备齐。** 每段明确主素材、解释职责及缺口。必要图示、操作示范或固定近景先做出并审核；写了“后期控制”不等于有实现。
3. **先排整篇。** 以当前608×352画布检查人物、对象、字幕、节奏与相邻连接；长旁白可跨相关镜头，不能逼模型撑满整段。核心解释不足先改设计，不扩大关键帧生成。
4. **仅尝试有基础替代的新镜头。** 确有收益才按官方模式提交一次；失败按连续性SOP第0.4节处理，不把提示、模式、seed分别开新预算。没有新素材也能讲清时直接使用基础版。
5. **合成并检查同一候选。** 先看整篇形式和解释，再做后台技术QA；分别记录实际动作检查、语义、听感和医学终审范围。采样或高清升级另作可选试验。
6. **沿相同分工扩展。** 复用准确的功能素材、风格及工具，每篇保留不同的解释问题；新的能力缺口先解决基础素材，不因某个生活动作成功而整季批量。
7. **按事实变化维护文案。** 纯视觉替换核对现有双平台文案；医学内容确需变化才更新事实、旁白、时码及catalog，再形成一致的交付包。

## 6. 有界比较与失败处理

第5集同一已审厨房动作已取得Turbo8与常规20步的608×352输出，两者都能完成瓶子移动和松手。20步耗时约130.4秒，8步约65.3秒，未观察到足以推广20步的明确动作收益。当前没有“新版提示普遍优于旧版”的证据。下表是可选研究方法，已从整季生产必经步骤中移出；仅有具体待回答问题时使用，不为补齐实验表重复生成。

| 阶段 | 固定项 | 仅改变的内容 | 何时停止 |
| --- | --- | --- | --- |
| 提示比较 | 首帧、seed、时长、画布、权重与采样 | 旧提示策略 vs 官方结构化策略；后者去除冲突锁定但保持观看任务 | 两者都无可用动作则定位首帧/动作，停止文字微调；若差别不明确，再用第二个任务作小范围复核 |
| 采样比较 | 已选提示、首帧、seed、时长与画布 | Turbo8 vs 配套非Turbo20；25步仅在仍有动作问题时增加 | 清晰说明收益与耗时后选用，不为多一个候选无限重抽 |
| 画布比较 | 提示与已选采样方案 | 预览画布 vs 正式画布 | 读回实际规格、完整解码与后期结果；显存/耗时不合适时测一个有依据的折中 |
| 连续性比较 | 同一相邻镜头意图和音轨 | 常规匹配剪辑 vs 必要的首尾/引导方案 | 常规剪辑已成立就不增加上下文链；新模式先证明实际可用 |

这是策略组合比较，不能从中单独归因于 header、某个词或某个禁令。相同 seed 方便对照，但不同分辨率/采样下不保证相同轨迹；小样本不报告普遍成功率。

每次留下全部候选、可用源区间、失败位置及原因。优先记录基础素材缺口、实际采用预定替代的情况、计划外改设计次数及总耗时；新生成再统计首轮可用任务/全部首轮任务、可用源时长和失败类别，素材复用单列，不能算本轮生成成功。耗时包含图片、准备、生成、QA和返修，不只比GPU速度。一次成功是有限样本证据，语义质量不由像素差或固定分数替代。

传输失败先查原任务，不能和视觉失败合并计因。视觉失败按[连续性SOP第0.4节](11_解释对应与叙事连续性SOP.md#04-先保证下限再增加效果)累计预算、接回具体基础素材；不在一次失败后重新走提示、图片、采样和模式比较的完整循环。保留事件与关系，不自动退回文字课件。
