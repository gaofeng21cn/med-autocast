# 纸剧场单集工具与局部返修

预览会在均匀动作 strip 之外，按当前 score 的命名事件保存前 0.10 秒、事件时刻与后 0.12 秒的原尺寸画面，登记在 `preview.json.eventFrames`。闪点、按压、夹持等短动作可能被均匀抽样漏掉；先看这些事件帧，再看动作前后连续窗口。事件帧不是完整动态批准，缺失或不完整事件仍可继续预览其他内容。

逐镜返修时可使用 `shot_recipe` 记录观众读取顺序、主运动、carrier、hold/rest、字幕安全区和声音职责。该记录是导演交接和审片索引，不是阻断渲染的结构化脚本；缺项先保留候选并记录质量债。具体字段见[Video Shotcraft 方法适配](../../../docs/video-shotcraft方法适配.md)。

导演先决定患者任务、物件因果、镜头和声音节奏；工具负责把这些决定稳定地执行出来。`paper_project` 是单集操作入口，不是自动导演或新的调度系统。三个公开动作仍为 `plan-series`、`produce-episodes`、`review-delivery`。

## 入口与环境

安装后的 Skill 根提供 `runtime/native_helpers/workbench_tool.py`。统一分发器对 `paper_project`、`render_narration`、`render_javascript_animation` 始终采用随包实现，并使用目标工作区 `.venv/bin/python`。`tools` 的路径和解释器就是实际执行路径。旧制作单工具保留工作区覆盖，避免破坏已存在的系列。VoxCPM2 使用后端档案中的独立模型环境；不将 Python 虚拟环境符号链接展开成系统解释器。

下面 `W` 为工作区绝对路径，`P` 为单集绝对路径，`K` 为安装后 Skill 根。它们是命令示例变量，不是另一个配置来源。

```sh
"$W/.venv/bin/python" "$K/runtime/native_helpers/workbench_tool.py" \
  --workspace "$W" --name paper_project -- --project "$P" inspect
```

后文列的是 `--project "$P"` 之后的子命令。工作区、项目参数放在子命令之前。

### 本地工具修订的显式验证入口

已安装 Skill 的 `workbench_tool` 会从该 Skill 随包目录选择 `paper_project`，后续 renderer 和素材检查器也跟随同一根目录。工作台源码已修复，不代表旧安装缓存已经更新；单独运行新检查器成功，也不能证明旧分发器的预览消费了它。

当前任务正在修工作台工具、尚未安装新版时，可以显式调用已核对的工作台源码入口：

```sh
"$W/.venv/bin/python" "$W/scripts/paper_project.py" \
  --workspace "$W" --project "$P" preview --start 0 --end 1 \
  --output "$W/work/review/local-entrypoint-probe"
```

先确认该工作台入口及其同根 renderer、检查器是本任务修订版本，再用独立审查目录回读实际预览状态、错误与帧。后续构建、预览、编码和打包沿同一明确入口完成；源码、随包投影和已安装包的生效范围分别记录。保留安装缓存，通过标准安装流程更新它；不要手工补丁旧缓存，也不要用反复重试旧入口代替路径核对。

## 从导演稿到审看交付

| 工作 | 子命令 | 产物与判断 |
| --- | --- | --- |
| 建立单集 | `init --series SERIES --episode EPISODE --narration /path/narration.json [--style-id ID --renderer ID]` | 复制独立模板、锁定依赖、作者品牌快照；单集显式风格覆盖作者档案默认值，不修改全局档案 |
| 独立返修 | `revise --from-project /path/current-project` | 独立复制可编辑文件、保留未变素材证据；不继承旧整片审核，不自动切换当前版本 |
| 接入旧作品 | `adopt --series SERIES --episode EPISODE [--style-id ID --renderer ID]` | 增加 project.json 和系列登记；保留既有 Score，可选覆盖本集风格选择 |
| 准备纸件 | `assets` | 三底色 alpha 联系表、尺寸和连接点记录；逐个查看纸边、残片、绘画和解剖 |
| 配音 | `narrate` | 固定全篇参考声线与方向；逐段音频缓存、真实起止时间、整轨响度归一化 |
| 建立剪辑时间 | `retime` | 按完整批准正文与 `beat_id` 归属字幕，完整断句可映射真实声段时间，缺句则从全文重建；不按旧 cue 中点归镜头后裁切。可用 `--reference-score` 与 `--reference-narration` 恢复明确来源；相同声音重复执行保持幂等，不拉伸动作 |
| 字幕对齐辅助 | `align --python /path/model-env/bin/python --model /path/whisper.pt` | ASR 输出源音频局部秒数与 voice/source SHA，字幕提案按批准正文完整拆句/双行；本地模型可以离线使用 |
| 采用字幕 | `captions --cues /path/cues.json` | 导演核对识别差异并拆句后采用；ASR 不改写医学正文、不批准发音 |
| 混音 | `mix`、`mix --music /path/music.wav` 或 `mix --music-plan /path/music-plan.json` | 单曲或分轨、实际旁白侧链、整篇响度；未配置音乐时混旁白与拟音；播放器接入混音文件 |
| 构建 | `build` | npm 锁定依赖、TypeScript 检查与本地 bundle；需要在第一次混音增加播放器音轨后重建 |
| 审看 | `preview --shot SHOT --neighbors` | 全局时码不变的邻镜联系表和动作 strip；HTML 可逐帧、循环、半速、去文字观看 |
| 精确窗口 | `preview --start 8 --end 12 --clean` | 定位接触、遮挡和切点；不能以抽帧替代完整运动观看 |
| 导出 | `render` | 当前输入对应的 MP4；审看候选保留所有未审项目 |
| 交付 | `package` | 用户目录直接保留唯一 video.mp4、封面、字幕和文案；score、旁白和审看状态留内部，旧包移出 publish |

旁白输入为 `{"beats":[{"id":"B01","text":"审定旁白"}]}`。`project.json` 只登记文件位置和 `beat_shots` 对应关系；`score.json` 持有镜头、事件、字幕、请求风格与 renderer 的单集选择，并作为执行时唯一风格来源。`--style-id` 和 `--renderer` 可保留尚未注册或未激活的请求；渲染回执记录实际 renderer 与质量债务，不阻断导演和候选审查。初始模板的一段一镜映射仅为起点，复杂分镜由导演直接编辑，不能假装任意多对多映射已自动对齐。

`init --from-project` 接收自包含的项目素材和来源证据。跨集复用图像不应复制已经批准的全片结论。模板动作样本仅演示铰接、收纳和接触；品牌从当前作者档案读取，叙事、画风和构图必须逐集设计。

## 只改一句或一镜

修改 `narration.json` 中目标段后运行 `narrate --beat B02`。未改变的文本、参考声音及模型配置复用原段；未选择的段没有匹配缓存时会停止，避免混入旧稿。需要另一个 take 时用 `--force`，先生成到暂存目录、解码成功后才采用；旧 take 保留。异常发音应按语义重写或重配该句，不以响度归一化掩盖。

声音改变后依次 retime、align/captions、mix、build、局部和完整审看、render、package。旧视频不能冒充新音轨交付。镜头代码改变时只需 build、相应窗口审看和 render/package；动作事件改变还需重新 mix。未变声音不重配。品牌、医疗核对、完整听感与动态审查分别记录。

只改视觉或导演说明、声音依赖确实未变时，使用 `mix --reuse-from-project /path/original-project` 保留原混音字节，再 build、preview、render。工具核对同一系列/单集、源 Score/旁白/混音回执及真实文件、当前旁白与 timing、总时长、sounds、实际挂音效的镜头起点与事件时点，以及引用音效载荷。没有挂音效的纯视觉事件、静默镜头不触发重混；完整原输入快照仍保留并严格核验，源回执和实际音效变更不能绕过。工具生成含原来源的新绑定，不手工改回执 SHA。注册音效缺少历史载荷哈希时，保留旧证据并重新建立可验证声音输入。

若历史返修只冻结了原音频输入，可在独立 `work/` 目录按原 `project.json` 的相对路径保存原 Score、混音 WAV、`audio/mix-receipt.json`、与原回执 SHA 一致的旁白、素材清单及被引用音效，再将该目录传给同一入口。明确标为“仅音频输入快照”，不声称恢复旧动画工程；图片载荷无需为音轨复用复制。新返修优先先用 `revise` 保留独立原工程。复用不重新批准听感。

字幕缺句与声音缺字必须分别检查。`retime` 先核对批准正文，不能因为旧字幕已有时码就保留截断正文；小数点、数值范围和英文词间空格均属于内容。批准正文存在无音频的整段时，保留现有可用声段并列出 `source_beats_without_audio`，回到配音补齐，不给无声段编造时码或回报全量完整。动作放不下时留下 `score.proposed.json` 供导演调整。

批量或单集只读检查使用随包工具，结果写在独立目录，不改实际 Score：

```sh
"$W/.venv/bin/python" "$K/runtime/native_helpers/workbench_tool.py" \
  --workspace "$W" --name audit_paper_captions -- \
  --workspace "$W" --output "$W/work/caption-audit" \
  --series SERIES --episode EPISODE
```

去掉 `--series`、`--episode` 可检查全部已登记当前工程。`caption-audit.json` 保留当前正文差异、声段归属与需审窗口，`cues.proposed.json` 绑定当前旁白 SHA；旧音轨的编辑时码不能直接沿用。提案按真实声段窗口和字符比例保全全文，不是词级对齐或实际同期批准；采用前结合原音校准，采用后重建混音、预览、MP4 与交付，正常速度回看字幕阅读节奏。

`align` 的 `alignment.json` 明确声明 `timing_coordinates=source_local_seconds`：segment/word 时码相对各自 source take，不预先加 `beat.start`。`build_cues` 只在生成最终字幕时加一次声段起点，并仅按 receipt 中的真实裁头量减一次局部时间；识别字句不替换批准正文。提案复用正常拆句和双行排版，绑定当前 voice、每段 source SHA 及 narration receipt SHA，不能用一个整段长 cue 挤满画面。

旧全局 alignment 需先根据已查实来源明确登记 `timing_coordinates=timeline_global_seconds`，并在每个 beat 写 `source_to_timeline_offset_seconds`（该旧文件当初加到源局部时码上的确切偏移）；读取时先减该偏移还原 source-local，再走同一字幕链。无坐标声明、无确切偏移或无可用词级锚点时，不猜时码：保留完整批准正文的字符比例提案并写 `timing_note`，结合原音校准后采用。局部 ASR 文件不能再减一次 `beat.start`；全局字幕提案也不能再加一次起点。坐标一致、SHA 绑定和全文保全都不批准实际同期、发音或完整听感。

构建记录绑定代码、素材、时间轴和入口；混音绑定声音及事件；交付回读当前视频字节。它们只解决“有没有用错版本”，不解决“是否有好故事”。

## 素材与真实拟音

归档或登记单件素材后，命令只返回本次涉及的条目和动作回执，完整发现索引仍保存在素材台；纯查询保持只读。预览的终端回执按诊断类别保留数量与完整preview.json引用，不把每帧重复定位全部回灌对话。完整定位与原尺寸帧继续用于逐项审看，摘要不清除质量债。

metadata 内的来源证据相对路径以该 metadata 文件所在目录为基准。例如 metadata 已在 preproduction/，同目录回执写 receipt.json，不能再写 preproduction/receipt.json。导入先检查所有证据文件，再复制原图与证据；引用错误时给出实际解析路径，不覆盖已保留候选或写入半成品登记。

`assets --asset FILE --asset-id ID --kind imagegen|licensed_web|authored_graphic|reviewed_library --source 来源 --usage 解释用途 --limits 不应暗示的内容` 导入独立文件；`--metadata JSON` 带入提示词、生成回执、网页许可或医学参考，并复制来源证据。`--registration JSON --asset-id ID` 登记 `pivot`、`anchors`、可选 `front`。图册残片、错误解剖、人物不像必须换素材，不靠卡片遮挡。

`library --query 关键词` 只读检索持久库和已登记单集，区分已独立保管与仅工程发现。`--ingest-project --notes JSON` 独立复制图像及已有来源证据，`--register JSON` 保存代码、动作样例和声音包；`--refresh` 生成完整看图库，不受查询过滤影响。`--use ID --revision REVISION` 将精确版本复制到本集，保留来源并重置新镜头审核，不覆盖不同字节。通用组件、选题材料与作者资产分范围；使用记录帮助追踪复用影响，旧片不随库更新改变。具体策展、版本和文件包方法见[可复用素材保管](23_可复用素材保管与策展.md)。

`use` 完成复制与资产登记后，还要由本集实现接入源码，并按真实镜头更新 `asset_manifest.shots[].asset_ids`，移除已退出画面的旧依赖。用实际加载/绘制引用回读这两层；候选导入不等于已在镜头中使用，旧镜头覆盖表也不能决定画面事实。库不知道新资产会服务哪一镜，不能自动把它绑定到全片。

拟音可以在素材清单登记 WAV，再在 `score.sounds` 使用 `{shot,event,asset_id,gain,offset}` 绑定真实纸响、落印等声音。没有声效素材时保留克制的程序拟音。声音必须服务于物理事件，不给每个物件机械配音。背景音乐与拟音均须保留来源。

## 交付回读与能力范围

`med_autocast.py preflight-workbench --workspace W --series S --episode E --plan P/project.json --master P/out/精确版本.mp4` 读取原项目与当前交付指针；兼容旧 YAML 制作单。`inspect` 可发现新项目登记。`package --review JSON` 只接受绑定当前 video_sha256 的审看记录，未审项保持 pending；本工具不批准公开发布。

交付预检必须使用当前项目 `out/current.json` 指向的母版和内部 `deliveries/<series>/<episode>/manifest.json`；`--delivery` 传文件，不传目录。不要按修改时间、目录名或旧 checkpoint 猜版本。全季完成后再按[全季交付回读与经验沉淀](25_全季交付回读与经验沉淀.md)逐集汇总审计、哈希、归档路径和质量债务。

JavaScript 构建、配音、ASR、预览和导出可在本机完成。首次 npm/Python 安装需要依赖下载；已有本地权重可离线配音。Edge 与在线素材搜索、ImageGen 仍有联网或托管服务依赖，不能将它们描述为离线图像生成能力。

完整环境、透明对象、音乐弧线与分轨计划见[纸面舞台与声音导演](22_纸面舞台与声音导演.md)。采样器只用于可选的本地原创音乐，已有音乐音轨可直接混音；听审独立记录。


中文多音字和医学术语按[发音控制与听辨 SOP](27_中文配音发音控制与听辨SOP.md)执行：正文与 `tts_text` 分开，VoxCPM2 保存发音标记并把带标记声段置为人工听辨待审，改注音即更新缓存。逐段原音和 `audio/pronunciation-review.json` 用于听辨定位，ASR、响度及注音输入均不能证明实际读音。已拒用 take 不得复用，局部重配后同步字幕、镜头及最终混音。

提高初版质量优先在配音稿中完成语境注音，并先做首句/术语小样和代表镜头。局部返修建立独立修订，不用硬链接复制可编辑工程。详见[初版质量与高效返修](28_初版质量与高效返修流程.md)。
