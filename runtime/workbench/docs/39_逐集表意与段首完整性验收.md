# 逐集表意与段首完整性验收

医学科普动画的基本质量，是让观众正确理解本集的问题、关键关系和行动，同时听到完整、准确的旁白。工程可复现、代码模块化和资产丰富只能帮助制作，不能证明这个下限已经成立。创意、材质、镜头和情绪在这一基础上继续打磨。

本规范用于新集初稿和已有作品返修。自然语言记录可以直接交给下一阶段，不新增必填 Schema、关键词评分或固定章节门。缺项继续补做，已知缺陷继续返修；可消费候选可以交接，欠项不能记为通过。

## 1. 从患者所得反推画面

导演先写本集观众看完能理解什么、能做什么，再逐句核对核心事实。一个连续镜头可以承接几句话，不能为了逐句登记把完整事件切碎。

每个核心事实应交接可见对象、对象之间的关系、需要发生的变化或需要保持的状态，以及观众应得到的判断。例如“查结构与查功能”应让影像与激素资料承担不同职责并汇入同一判断；不能只放两个同形纸框，再靠标签解释区别。

| 交接内容 | 导演需要回答的问题 |
| --- | --- |
| 当前事实与患者任务 | 本句最重要的含义是什么？条件、否定或先后是否容易误读？ |
| 可见对象 | 观众能认出什么？样本、器械、药物和解剖结构是否选对？ |
| 关系或结果 | 什么在影响什么、什么先做、什么只是线索、什么尚未确定？ |
| 动作与时机 | 如果有操作，起点、操作、反应和结果是否实际可见？静态关系为何值得停留？ |
| 误读与修复 | 只看画面可能理解成什么？如何改对象、关系或旁白避免？ |

去文字审片帮助判断核心对象和关系是否成立，不要求画面独立传递所有数值、术语和限制条件。必要名称可由简短标签和旁白补足；不能用标签掩盖错误物件或不存在的动作。

“进入→接触→反应→落定”适合检查有物理操作的动作，不是每镜必套的模板。稳定的解剖关系、同时存在的影响和时间比较可以清楚表意；合理比喻也可以解释关系，但映射要可读，不能暗示错误的器械身份、解剖或诊疗顺序。选择动作、停留和机位由本集解释任务决定，不按固定动作链、数量或静止时长打分。

## 2. 反向读图，找出真实误读

文字先区分纸上排版与独立题注，再检查它自己的区域和实际遮挡。`Stage.text` 不能推断所属纸件；新实现用 `textBox` 或同局部坐标的 `cardTitle` 登记明确宽高与真实字形。`text_region_overflow` 定位该区域放不下的内容；旧文字的 `unbound_text_subject_partial_overlap` 只表示屏幕包围盒部分相交，不能猜 owner，也不能靠任意大背景包含就判通过。日历叠页、笔杆、固定件和人物须看原尺寸帧、运动极值与正常速度；修具体镜头，不批量居中。诊断作为质量债保留，不阻断其他可消费工作。方法见[纸片文字与遮挡SOP](37_纸片文字对齐SOP.md)。

先暂时隐藏字幕、解释标签和导演描述，只根据实际画面写一句“我看到了什么、它们有什么关系、刚才发生了什么”。再与本句的医学含义比对。若只能描述为“几张纸滑进来”“一个杯子和一本本子”，就回到对象和事件设计；不能把导演注释中的“化验”“药物”“翻面”“收纳”当作观众已经看见。

反向读图之后恢复旁白和必要文字，检查画面是否与同期内容同向。尤其检查否定、比较、先后与可能性：血样不能画成尿杯；检查线索不能被画成已确诊；多种治疗不能被画成人人必经的阶梯；空纸翻过来不能被记为包装成分已经揭示。

先确认基本意思，再评审创造力、纸片层次、物件比例、导演节奏和声音情绪。增加素材、胶带、撕边和镜头运动不能修复表意错误。

## 3. 逐集覆盖整条时间线

先从工作区登记、单集制作单、当前母版指针和交付 manifest 找到准确的候选。记录工程版本、实际视频/声音路径、构建与混音来源，以及本次实际查看范围。复制到 publish 后再核对用户会拿到的那份文件。

开始构建或审查前，冻结本次导演稿、源码、素材、正文/配音输入、声音和 Score 的精确引用；每个工程保留单一 writer。构建、渲染、混音和打包期间不让另一任务改写同一输入；后续编辑形成新修订，重新生成受影响证据。冻结服务于可复核，不新增第二套状态或强制表单。

每集独立检查首帧、每镜切入和切出、核心事实对应区间、动作极值与结果状态、相邻切点和完整结尾。静帧、1 fps 帧序列、联系表和动作 strip 用于定位；它们不能证明快速动作、连续节奏或完整听感。关键动作有疑点时加密查看实际连续窗口，正常速度的完整动态和完整声音分别记录覆盖情况。没有完成的范围保持待审。

特别检查动作完成后的长时间区间。镜头提前落定、旁白继续解释十几秒时，后续内容可能已经没有画面承接。按语义安排第二个局部事件、推入真正有内容的细节、切到结果或缩短镜头；不能用持续晃动、相机慢推或随机粒子假装内容仍在变化。清楚的静态关系可以有理解停留，不按固定秒数否决静止。

改代码或素材后重建、预览和渲染受影响版本；再看实际编码首帧、返修窗口与邻镜。旁白变化后先以实际采样和声音定位重排时间线、字幕与动作，再混音和编码。源码变化、命令成功或报告文字改变都不是成片修复证据。

预览联系表必须由本轮实际帧清单组成。复用输出目录时，不用文件名通配符收集旧时码帧；保留旧证据，但当前 contact sheet 与 preview.json 必须指向同一批帧。否则重排后的首帧和镜头内容可能被历史抽帧冒充。

Canvas 透明度要沿嵌套绘制继承。子函数写绝对 `globalAlpha` 会覆盖父组淡入/淡出，导致父组透明时纸纹、色块或线段仍可见；局部值应与继承值相乘，并在绘制后恢复状态。实际复核精确第 0 帧、转场、淡出完成和相邻镜头，不把随机微动或遮片当作残影修复。

字幕以审定正文为唯一文字来源，按语义断句后逐段核对完整覆盖，不漏首尾、不重句、不让 ASR 替换医学正文。retime 从冻结的原 cue/声段参考映射到新声音；声音与切点未变时保留已校准时码，不重复变换已经 retime 的旧 cue。新时码是提案，仍按实际声音核对断句、同步、可读性和遮挡；机械正文覆盖与包围盒不能代替这项判断。

ASR 时间坐标必须显式交接为源段局部秒或整集全局秒。局部识别只叠加一次实际 beat.start；旧全局结果先按声明的偏移还原，不能在下一步再次叠加。为识别加的前导静音也只减去一次，并绑定源 take 与当前旁白 SHA。句级时码可以复用已登记逐词证据，正文仍来自审定稿，识别缺词不能裁掉批准内容。

字幕缺句与声音缺字是独立问题。旧 retime 按 cue 时间中点归入镜头，再缩放或裁切，既会继承旧字幕缺句，也可能把后半句裁掉；声音完整不能证明字幕完整。`scripts/paper_captions.py` 按审定正文和声段 `beat_id` 归属字幕，优先保留完整的语义断句，缺句从完整正文重建；同一声音与切点重复 retime 应得到相同结果。批准正文已改而配音 receipt 仍是旧文本时，记录声音待重配，不能把补齐字幕记为声音修复。

只读检查可运行 `scripts/audit_paper_captions.py --workspace <工作台> --output <过程目录>`，按 `workbench.yaml` 登记枚举当前工程，逐集输出 `caption-audit.json` 和 `cues.proposed.json`，不改生产 Score。采用提案后重新核对完整正文覆盖、当前 MP4 的实际同期和用户交付字幕；时间窗口和字数分配只是待审提案，不是 ASR、发音或听感批准。批量问题数绑定冻结快照，不能沿用并行修改中的旧统计作为最终验收。

## 4. 段首完整性检查整条声音链

听起来像“段首少字”时，先区分源 take 已经漏读、拼接截字或位移、混音遮盖、时间线错配，以及实际交付仍引用旧音轨。前导静音可能造成起声迟到，但静音本身不会删除词，不能仅凭静音长度宣称找到了根因。

对每个语段沿“正文/配音输入 → 源 take → 拼接旁白 → 归一化旁白 → timing/Score → 最终 mix → 当前 render → 用户实际 MP4 解复用音轨”比较实际内容。检查源采样率、声道、采样数和时长；采样率转换必须真实重采样，落位来自真正写入的采样数。默认保留完整源 take，不凭能量阈值裁掉弱首辅音；调整停顿时计入源 take 自带前导静音，保留实际结果和听辨范围。

逐段比较首词、尾词和下一段开头；抽取接缝前后完整短句，分别核对无 BGM 轨和最终视频音轨。波形、能量检测与 ASR 帮助找到可疑段，不能自动批准首字、清辅音、多音字或术语读音。裁静音时保留低能量辅音及必要前后余量；局部 TTS 漏读才重配该段，未变且正确的 take 继续复用。

`splice`、`repaired`、`already_repaired` 等字段只是处理记录。实际使用的归一化旁白、混音和视频没有对应变化，修复就未交付。修复后核对时间线和字幕，不以“保持旧总时长”为由截断语音，也不强行把新段压回旧时码。明确需要保留的时长由真实内容和编辑目标决定。

已有工具各守一层事实：`scripts/audit_narration_samples.py` 逐样本比较 source take 与原始 `narration.wav`；`scripts/audit_audio_freshness.py` 定位 source/timing/mix/render/publish 的字节失配；`scripts/audit_narration_lineage.py` 用局部波形锚点追踪最终音轨的位置。`source_timeline_bound` 不证明模型读全或读对，`publish_current` 不证明首词可闻或听感合格。若 `mix-receipt.json` 的 `voice_sha256`、`score_sha256` 或 `audio_sha256` 不对应当前输入/输出，重建 mix；其余失配回到最早断点，只刷新受影响下游。回读用户实际 MP4 后再更新 Review，不能只改 receipt 或沿用旧片结论。

另运行 `scripts/audit_narration_prefixes.py` 读取冻结的当前源段 ASR，分别记录首词文字差异、疑似段首省略和术语/发音听辨定位；这份报告只排听辨顺序，不批准发音或语气。需要刷新实际候选时按 `scripts/rebuild_current_episodes.py` 的 `retime → build → preview → mix → render → package` 顺序逐集记录，单集失败不阻断其他可消费进度。

首句、高风险术语与多音字、每次段间切换和结尾都需要实际声音证据；全片语气、响度和音乐遮蔽另作完整听感检查。没有实际听辨时写清检测方法、已定位问题和未覆盖听感，不把分析结果称为听过或发音合格。操作细节见[中文配音发音控制与听辨](27_中文配音发音控制与听辨SOP.md)与[旁白拼接边界](33_旁白拼接边界SOP.md)。

## 5. 把本轮缺陷回到最早责任点

| 已发现的缺陷类型 | 最早应改的环节 | 修复后的证据 |
| --- | --- | --- |
| 样本、器械或药物身份错用；靠标签改身份 | 导演选材与素材准入；重新准备正确物件 | 去文字可辨原件；当前镜头对象与同期事实一致 |
| 空纸、无内容色块承担检查、药物或操作 | 导演事件与素材；补真实内容或改解释方式 | 观众能描述具体对象、关系和结果 |
| 注释说“翻面/收纳”，实际空 group 或没有可见部件 | 镜头实现；真实绘制部件并保持结果状态 | 动作前、中、后及邻镜中结果真实可见 |
| 动作很早结束，后续事实没有画面承接 | 联合时间轴与导演；按含义重排动作与镜头 | 同期旁白全部有成立的画面承接，完整节奏复核 |
| 父组已淡出，纸纹、色带或线段仍残留 | 绘制原语；修绝对 globalAlpha 覆盖及状态泄漏 | 精确首帧、转场、消失状态和邻镜实际帧 |
| 字幕漏正文、重句或反复 retime 后漂移 | 正文与时间线交接；从冻结参考重建完整 cue | 正文覆盖事实与当前 MP4 的实际同期复核 |
| 新标签叠旧文字；条带对齐却压住其他内容 | 构图与排版；减少重复文字并检查实际全画面 | 原尺寸帧及运动极值无遮挡；对齐报告仅作辅助 |
| 元数据说已修复，归一化旁白或 MP4 仍是旧轨 | 音频与构建交接；确认真实读取者并更新下游 | 源 take、拼接轨、混音、当前 MP4 的实际首词与时间一致 |

通病可以修工具，但每集仍要判定问题是否存在、具体错在哪里、改什么。没有发现问题的集也要留下实际覆盖依据；不能给全部集数复制相同的“已优化/通过”结论。

## 6. 逐集记录和 Stage 交接

每集保留可读的问题记录：原候选、问题时码与同期旁白、实际画面/声音、可能误读或缺失、修复 owner、已做的改变、修后候选、复核范围和剩余项。字段和排版可以按已有工程调整；下游能定位和继续返修即可。问题合并时保留每集实际差异，不把通病修复次数当作已完成集数。

内容策划提供患者任务和准确事实；导演提供可见对象、关系与结果及误读判断；制作落实真实部件和声音链；Visual Review 反向读图并检查当前动态与音轨；Meta Review 核对这些结论是否覆盖同一候选、是否把技术检查扩大成语义批准；交付回读用户目录实际文件。发现表意错误回最早责任环节，其他独立工作继续。

`evaluate_episodes.py` 的函数调用、文字调用或环境统计只用于导航源码。未调用登记动作不等于没有动作，调用了也不等于实际绘制；不按词频分数决定合格、重写或升级。独立性哈希只能定位逐字复制，文件不同不证明故事独立，也不证明导演质量。

公开发布资格仍按真实医学与发布授权处理。工程检查、逐集视觉表意、连续动态、发音与段首完整性、完整听感、医学复核和上传状态分别记录；已知表意或声音缺陷不能带着 `passed` 进入用户最新版。候选、诊断和不依赖该缺陷的进度可以继续保留。

## 7. 提高下一轮初稿质量

初稿按“本集独立故事/导演 → 事实对应可见对象、关系与真实变化/稳定状态 → 真实完整代表镜头 → 整集 animatic → 实现 → 逐集 Review → Meta Review → 唯一最新版交付”推进。代表镜头从开始演到结果，使用真实素材和完整声段；先去文字反向读图，再恢复同期旁白。animatic 检查整集解释、承接与节奏，代表集仅验证制作方法，不豁免其他各集。

复用清楚的纸件、材质、固定件、接触动作、绘制与声音工具；每集的事实关系、故事、物件组合、镜头顺序和时间线保持独立。通用 Skill 不内置工作区品牌、私人形象或声线参数；风格与 Renderer 可按患者任务选择，现有样本不封顶。资产不足时重新生成或寻找更合适的合法素材，不为库存降低解释质量。

新增经验回到本规范、对应 Stage 提示与专业 Skill；缺陷样例和真实证据留制作工作区。机器减少搬运与确定性错误，逐集语义审片守住“把意思讲清楚”的下限，导演继续探索创造力与表现力。

## 8. 批量排队，逐集落地与交付

整季复核可通过工作台或 MAC 随包的 `scripts/build_episode_review_queue.py --workspace <工作台> --output work/episode-review-queue.json` 建立现有逐集队列。它按 `workbench.yaml`、`project.json` 和 `out/current.json` 定位工程、导演稿与当前媒体，只给出下一步任务。输入或工具缺失时保留可读诊断，不因队列、Schema 或某集缺项阻断其他可消费工作。

逐集消费第 2—4 节的表意、动态、字幕与声音证据，再由 Meta Review 核对同一候选、目标与实际覆盖；修复回到最早责任点。工程、基本表意、连续动态、段首/发音、完整听感、医学与上传状态分别记录，不将批量重渲染或检查次数计作已完成集数。

最后回读 `publish/<系列展示名>/<集号_标题>/` 用户实际 MP4、字幕和文案；只留唯一最新版，过程、待修候选与旧版本放在目录外。已知表意或声音缺陷不能伪装为已修复最新版；未覆盖的审核范围明确待审，打包不签发医学批准或上传授权。
