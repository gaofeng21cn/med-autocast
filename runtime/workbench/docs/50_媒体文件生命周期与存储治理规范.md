# 媒体文件生命周期与存储治理规范

更新：2026-11-21。本规范适用于医学科普纸剧场的工作台和 MAC。它解决一个先后顺序：先判断文件是否承担当前制作、恢复、审看或发布职责，再决定删除、原样保留或无损压缩；压缩不是保留理由。同时从构建、预览、混音和修订源头防止重复依赖与逐帧缓存膨胀。

## 一、四类生命周期

每个文件或可重建依赖目录在治理计划中必须落入以下一类：

| 类别 | 含义 | 默认处理 |
| --- | --- | --- |
| `keep_operational` | 当前指针、当前返修、当前可运行工程或正式交付的直接输入 | 原样保留；运行链路要求时保留 WAV/PNG |
| `keep_canonical` | 医学来源、素材母版、作者档案、源码、Score、故事/导演/分镜、许可和审核结论 | 原样保留；不得按扩展名批量改写 |
| `keep_compressed` | 仍需恢复或审看，但不需要原始容器的证据与历史派生物 | 先完成无损校验，再换成 WebP/FLAC，保留哈希、恢复命令和来源指针 |
| `delete_rebuildable` / `delete_redundant` | 可由已保留输入重建的中间物（含带锁文件的项目级 `node_modules`），或已由充分证据替代的冗余副本 | 记录哈希、理由、替代证据或重建入口后删除 |

无法证明用途、引用或恢复路径的文件进入 `defer_review`，不凭目录名、年龄、文件名最高版本或“看起来像缓存”删除。

## 二、目录职责与保护边界

- `content/`、`profiles/`、`assets/`、`publish/`、`deliveries/` 和 `archive/` 是内容、身份、稳定素材、用户交付、内部交接和只读历史的权威层。先按 `keep_canonical` 保护其中的权威对象，再沿发布/替换/复用记录判断历史载荷的必要性，目录名本身不产生永久保留义务；交付视频和封面不因治理而重编码。
- `productions/<series>/<episode>/<revision>/` 中的源码、`project.json`、`score.json`、导演稿、分镜、故事源、素材清单、来源/许可、当前指针、当前母版和当前音频输入受保护。版本是否当前以 `workbench.yaml`、队列和 `out/current.json` 回读为准。
- `work/`、`output/` 和 `tmp/` 是运行态、批量输出和可重建临时层。只有已绑定审看问题、恢复路径或独立经验的材料进入 `keep_compressed`；其余按证据替代关系判断。
- `.cache/node-deps/<fingerprint>/` 是工作区共享 Node 构建依赖池，按 `package-lock.json` 的规范依赖指纹与平台去重缓存（例如全部同构纸剧场工程仅共享一套 `typescript + esbuild`）；根目录 `node_modules/` 仅保留工作区级共享运行时（如 Playwright）。两者均不属于待删项目级依赖。
- `out/.render-*` 是渲染暂存目录（覆盖根目录 `out/`、`productions/**/out/` 和 `work/**/out/`，排除 `assets/`、`entries/`、`src/library/`、`payloads/` 等素材库样例载荷）。确认没有渲染、预览、TTS、打包或构建进程写入后，列入 `delete_rebuildable`；不能因为进程退出码而跳过句柄和计划哈希核对。

## 三、项目构建依赖（`node_modules`）与跨修订复制规则

1. **禁止在单集或修订目录长期安装独立 `node_modules`**。所有纸剧场单集和 `animation_lab` 样例统一通过 `paper_project build` / `animation_lab build` / `shared_node_deps.py` 复用工作区共享依赖池（`.cache/node-deps/<fingerprint>/node_modules`，通过 `PATH`、`NODE_PATH` 与 `shared_node_resolve.mjs` 解析），项目目录内不创建 `node_modules` 副本，也不创建符号链接。
2. 已有或意外产生的项目级 `node_modules`（排除工作区根 `node_modules/` 与 `.cache/`）：核对同目录存在 `package.json` 和 `package-lock.json`、确认无活动构建进程后，列入 `node_modules:delete_rebuildable`，记录锁文件 SHA-256 与目录统计后清理；缺失 `package-lock.json` 的目录进入 `defer_review`。
3. 跨修订复制（`paper_project revise` / `init`）与交付复制（`reuse_mix` / `package`）在 macOS APFS 卷上优先使用 `clonefile` Copy-on-Write 独立克隆，其他系统回退 `shutil.copy2`：保证独立 inode（`os.path.samefile == False`，不使用硬链接）、写时自动分离不污染源版本，同时避免重复素材与音频占用成倍物理磁盘空间。`paper_project revise` 默认跳过 `out/`、`qa/`、`dist/`、`history/`、`work/`、`entries/`、`node_modules/` 等非项目源码目录，防止误放的素材库镜像跨修订传播。

## 四、图像规则

1. 先识别用途，再识别格式。`assets/` 中的原始透明素材、医学来源图和可复用库载荷保留原格式，除非所有消费者已验证支持替代格式。
2. `qa/`、`work/` 或任何含 `preview.json` 的预览目录（包括误落盘到 `out/` 的旧预览目录）中的审看帧分成三种：联系表/动作条是摘要证据；`event-*`、`clean-*` 和被问题单引用的关键帧是定位证据；逐时刻编号帧是可重建源帧。
3. 有 `preview.json`、联系表和动作条时，未被独立问题记录引用的编号帧和动作条源帧可删除，在制修订也不保留这两种冗余缓存。冻结的 Score/构建输入仍匹配时，其余无独立引用的派生帧也可重新取样；历史源码已经变化时保留每个事件的中心帧、每镜去文字中间态和原联系表/动作条。回执明确是否能够重放当前源码，不承诺重建历史 PNG 的原始字节。
4. 当前返修的必要动作证据不得删除；无独立引用的保留帧转为无损 WebP，并逐像素核对 RGBA、更新生成的预览索引。被问题单按精确字节或路径引用的 PNG 已经是无损压缩图像，保留原容器，避免破坏证据绑定。素材母版同样不为统一扩展名而换格式。
5. 有损 JPEG 动作条、联系表只能承担定位和观看顺序，不得冒充逐帧原件或连续动态、听感、医学审核。

## 五、音频与渲染中间物规则

- 当前项目的 `audio.wav`、源旁白和正在使用的片段保留 WAV，确保现有混音、渲染、音频审计与返修链路可直接运行。
- 已冻结的旧版本（`productions/` 非当前修订）、历史混音快照（`audio/mix-history/`）、历史交付备份（`archive/deliveries/**/record/*.wav`）及历史工作缓存（`work/**/*.wav`）保留 100% 无损恢复能力，统一归档为 exact-restore FLAC：FLAC 解码后的 WAV 字节必须与原 SHA-256 一致，同目录生成 `storage-compaction.json`（混音快照同步更新 `snapshot.json`），新交付覆盖旧交付时由 `delivery_layout.install()` 在原子切换后自动完成旧备份 WAV 的无损 FLAC 归档。
- `foley`、`music-*`、`premix` 等中间轨先判断是否还需诊断：最终混音和真实输入已核验、没有独立审核引用时直接清理，不必先转成 FLAC。确需保留的中间轨才在还原字节校验后以 FLAC 取代 WAV。最终混音按来源与当前性保管，不能仅按文件名删除。
- 未被 `audio/narration_beats.json` 选中且无审核文档引用的淘汰/孤儿配音分段（`orphan_take`，非 `wip` 保护工程）和同目录已有经 SHA-256 校验的 `out/current.json` + 当前 MP4 替代且无外部引用的过时草稿渲染（`superseded_render`，非 `wip` 保护工程）分别列入显式可选分类 `orphan_take` / `superseded_render`（默认 `--parts audio` 不删除源段，需显式传入分类并校验替代物哈希后清理）。

## 六、执行顺序和回执

每次治理必须按以下顺序执行，回执存入 `work/disk-lifecycle-YYYYMMDD/`（单集收尾可存入该集 `qa/lifecycle-receipt.json`）；超大的明细计划与执行回执优先以 `.json.gz` 保存，`.jsonl` 过程日志超过 `256 KiB` 时自动无损 gzip 归档，摘要文档与小回执保留明文可读：

1. 建立同口径基线：卷可用空间、目录逻辑大小和分配量、活动写入与构建进程、当前项目与队列。
2. 生成逐项精确计划，记录类别、理由、项目/版本、SHA-256（目录类记录文件数、分配量及锁文件 SHA-256）、替代物和恢复命令。没有具体清单或清单尚未完整核验时不得删除。
3. 先按已判断的必要性处理删除项：逐项复核计划哈希、无活动写入/构建、替代证据和恢复路径；删除后回读路径确实消失。冗余材料不先压缩一遍。
4. 对 `keep_compressed` 写入临时目标，完成像素或音频字节校验，登记精确映射和同目录回执，再删除原容器。压缩后的历史 WAV 需要使用时由恢复入口核对哈希并还原，当前播放/混音输入保持可直接运行。
5. 重新统计工作台和卷空间，核对当前工程、构建共享池、发布包、审核入口和恢复命令；区分目录分配量减少、APFS CoW 物理去重与卷可用空间净变化（存在活跃 Time Machine 本地快照时如实说明）。

## 七、持续约束与防膨胀闭环

- **构建**：严禁在单集目录手动执行 `npm ci` / `npm install`；统一经 `paper_project build` 或 `shared_node_deps.py` 使用共享依赖池。健康基线为项目级 `node_modules = 0`。
- **预览**：新预览默认使用无损 WebP，动作条源帧与 `contact-frames.ffconcat` 仅存在于临时目录；默认紧凑模式下无布局/字幕疑点的普通编号帧合成 `contact.jpg` 后即清理，不长期落盘到 `qa/`（需逐帧排查时显式传 `--retain-numbered-frames` 或 `--retain-motion-strip-frames`）。
- **混音**：新混音默认仅保留最终混音与配方来源，可重建中间轨写临时 FLAC 并校验后清理；`preserve_mix()` 覆写前历史混音自动无损归档为 FLAC 并逐字节校验还原哈希。
- **单集收尾**：制作、审看、打包或切换修订收尾时，直接运行单集快速收尾 `paper_project.py --workspace <W> --project <P> prune --apply`（默认先不带 `--apply` 预览计划，无需全盘扫描），在 `qa/lifecycle-receipt.json` 留存回执。
- **周期巡检**：定期或批次结束后运行 `plan_workspace_retention.py check --workspace <W>`，核对项目级 `node_modules`、残留 `out/.render-*`、冗余编号帧、未归档历史/交付/工作缓存 WAV 与未压缩大体积治理日志是否归零。
- 新项目在 `project.json.storage_profile` 登记默认策略；不使用固定天数替代必要性判断。`defer_review` 不影响其他制作，但不得静默扩大删除集合。

## 八、现有工具入口

- 全工作区或单集计划：`.venv/bin/python scripts/plan_workspace_retention.py plan --workspace <绝对路径> --policy <本次策略.json> [--project <单集目录>] --output <计划.json|.json.gz>`。
- 执行选定类别：`.venv/bin/python scripts/plan_workspace_retention.py apply --plan <计划.json|.json.gz> --parts node_modules review_frame audio render_temporary [orphan_take superseded_render] --output <回执.json|.json.gz>`；工具在首次变更前先校验全部候选与替代证据（含锁文件与活动进程）。
- 单集快捷收尾：`.venv/bin/python scripts/paper_project.py --workspace <绝对路径> --project <单集目录> prune [--apply]`。
- 只读健康巡检：`.venv/bin/python scripts/plan_workspace_retention.py check --workspace <绝对路径>`。
- 无损音轨/图像还原：`.venv/bin/python scripts/plan_workspace_retention.py restore --path <原WAV或FLAC绝对路径> --output <恢复回执.json>` 从同目录 `storage-compaction.json` 精确还原并校验 SHA-256 / RGBA。

`compact_workspace_media.py plan` 仅为格式库存，其全量 apply 已关闭。MAC 随包工具已将 `plan_workspace_retention` 和 `shared_node_deps` 纳入 `CANONICAL_TOOLS`，可通过 `workbench_tool --name plan_workspace_retention` 访问；工作台显式本地工具路径、MAC 源码、本地载体和已安装全局插件分别回读，不把源码通过当作全局安装完成。
